# MES 新服务器首装部署执行单（逐步照做）

**版本：V1.2　最后更新：2026-09-05**
> V1.1：服务器实际**已预装 SQL Server 2022 Express（命名实例 `SQLEXPRESS`）**，无需安装 SQL；第 3/4/7 步已适配实例名与 Express 限制；每日备份改由 **Windows 计划任务**（`07-setup-backup.ps1`）完成，取代 SQL Agent 作业（第 14 步）。
> V1.2（2026-09-05 首装实测补充）：a) 建库走**「从真库恢复」**路径（见第 7 步下方说明）——EF 迁移链**无法自建空库**（`InitialCompressed` 是空壳聚合迁移，生产表早已存在），全新部署必须 `08-restore-db.ps1` 恢复一份真库 `.bak`；b) 05 已内置三个 nginx 关键修复（证书绝对路径 / `.br`·`.gz` 带 Content-Encoding / SPA 兜底），并在「如果不对」补充 nginx 热重载 Access denied 的处理；c) 前端已根治「空 BaseUrl → `net_uri_EmptyUri` 启动即崩」与「手机版无登录按钮」两处（V1.2 之后的新发布自带，旧版本需临时手改 `web\appsettings.json` 或用 `/login` 直达）。
> 本文是**第一次在空服务器上从零把 MES 跑起来**的逐条操作单，照做即可，每步含「成功标志 / 如果不对」。可与 `scripts/deploy-windows/README.md`（简版）对照；上线后的**长期运维**（增量更新、回滚、备份策略、Hangfire、监控）请看 [`05_部署与运维.md`](05_部署与运维.md)。

## 第 7 步　02 建空数据库（必须先建！）　🖥️

□ 同一个管理员 PowerShell：
```powershell
powershell -ExecutionPolicy Bypass -File .\02-init-db.ps1
```
□ 观察输出：会先连通 `localhost\SQLEXPRESS` → 给 SQL 服务账户授权 `C:\MSSQL` → 锁内存（Express 自动封顶 ~1.4GB，命令仅保险）→ 建空库 `MES`

【成功标志】依次出现 `[OK] connected to SQL instance localhost\SQLEXPRESS` 与 `[OK] database 'MES' ready at C:\MSSQL\DATA`。
【如果不对】
- `sqlcmd not found`：回第 4 步确认装好 sqlcmd，**新开** PowerShell 重跑；
- `Cannot connect to SQL instance 'localhost\SQLEXPRESS'`：a) 确认 00-params 里实例名没被改（应为 `SQLEXPRESS`）；b) SQL 服务在运行；c) 试着 `Start-Service SQLBrowser` 后再重跑；
- 报无权限/拒绝访问：确认你是管理员身份运行；SQL 服务账户授权那步是否成功；
- `failed to set max memory`：说明当前账号不是 sysadmin（建库必须 sysadmin）——回第 4 步用当初装 SQL 的那个管理员 Windows 账号跑本步。

> **⚠️ 建库路径选择（2026-09-05 实测）**：EF 迁移链**无法在空库上自建全部表**——`InitialCompressed` 是空壳聚合迁移（Up/Down 均为空，生产表早已存在），后续 ~300 个增量迁移无人接得住，一跑就 4902「对象不存在」。因此**首次装库别指望第 10 步首启建表**，改用**从真库恢复**：
> 1. 在真库机器（`zhou`，库 `MESMN`）上把库备一份：`BACKUP DATABASE MESMN TO DISK='<SQL默认Backup目录>\MESMN_日期.bak' WITH COMPRESSION`（SQL 服务账户写不了 `C:\` 根，须用 SQL 的默认备份目录）；
> 2. 用**管理员/授权账号**把 `.bak` 拷出（SQL Backup 目录普通用户读不了，需提权 PowerShell），再上传到服务器；
> 3. 服务器上跑 `08-restore-db.ps1 -BackupFile C:\mes\MESMN_日期.bak`（会自动：连通 → 授权 SYSTEM → 卸掉已有 MES → 解析逻辑文件名 → 恢复到 `C:\MSSQL\DATA\MES.mdf/.ldf`），成功标志 `[OK] database restored as 'MES'`；
> 4. `DbInitializer` 全幂等（每个种子都 `Any()`/`RoleExists` 守卫），恢复已满库**不会二次播种**；
> 5. **密码语义变化**：恢复后用户/`Admin` 密码继承自真库，`00-params.ps1` 的 `$AdminPassword` 不再用于云端 `Admin`；`$JwtSecret`（令牌签名）与 `$HangfirePassword`（面板）仍为应用配置生效。

## 第 10 步　04 注册 API 服务　🖥️

□ 管理员 PowerShell 里（仍在 `C:\mes\deploy`）：
```powershell
powershell -ExecutionPolicy Bypass -File .\04-setup-api.ps1
```
□ 脚本会把 API 注册成 Windows 服务并打印一段**「前台验证」命令**——**先别按 y**
□ 按脚本提示**另开一个管理员 PowerShell**，把打印的那几行命令**逐行复制粘贴**运行（会设数据库连接、端口、密码等环境变量，然后 `dotnet MES.Api.dll`）
□ 盯着日志：首次启动会自动**建全部表 + 写入 46 个角色 + 管理员 Admin**，可能要等 30 秒～2 分钟；看到服务稳定在监听、**无红色异常**后按 `Ctrl+C` 停止

【如果不对】

- 忘了另开会话：服务没起来时可再跑一次本脚本（已存在服务会跳过注册）。

## 第 11 步　放证书 + 05 起 Nginx　🖥️

□ 把第 2 步下载的两个文件（`.crt` / `.key`）拖进服务器，放到 **`C:\mes\nginx\conf\ssl\`**
□ 回到管理员 PowerShell：
```powershell
powershell -ExecutionPolicy Bypass -File .\05-setup-nginx.ps1
```
□ 脚本自动用这两个文件生成 nginx 配置 → `nginx -t` 校验 → 注册 nginx 服务并启动

【成功标志】末尾出现 nginx 已运行/`nginx -t ... ok`。
【如果不对】
- 校验报 `cannot load certificate ... No such file`：证书文件名/目录没对上，确认两个文件就在 `C:\mes\nginx\conf\ssl\` 下且扩展名是 `.crt`/`.key`，重跑；
- **05 末尾 `nginx reload ... Access is denied`（V1.2 已知）**：nginx 服务在 LocalSystem 会话，用户会话发 reload 信号被拒——**不是错误**，服务其实还跑着旧配置。**改配置后必须 `Restart-Service nginx`** 才会加载新配置；
- 05 已内置三个关键修复，勿回退：证书用**绝对路径**注入（nginx 相对路径按 `nginx.conf` 所在目录解析，写 `conf/ssl/...` 会变成 `.../conf/conf/ssl/...` 报错）；`.br`/`.gz` 压缩件带 `Content-Encoding` 头（否则 Blazor 提示「应用加载失败或网络连接断开」）；`location / try_files ... /index.html` SPA 兜底（否则直接输 `/login`、`/orders` 或刷新会 404）。

## 第 12 步　开端口（最容易漏）　🖥️+🌐

□ **腾讯云控制台** → 该服务器 → 防火墙/安全组 → 添加入站规则：**TCP 80** 与 **TCP 443** 放行（来源先 `0.0.0.0/0`）
□ **服务器内 Windows 防火墙** → 高级设置 → 入站规则 → 新建两条：**TCP 80**、**TCP 443** 均允许
□ ⚠️ 反向检查：**不要**放行 1433 和 7000（只允许服务器本机内部使用）

【成功标志】本机访问 `https://111.231.10.18` 能看到浏览器锁图标或证书提示（先忽略证书域名告警，说明 443 通了）。
【如果不对】打不开：八成是腾讯云安全组或 Windows 防火墙只放了一个，两边都要放。

## 第 13 步　冒烟验证 + 手机实测　🌐

□ 在能上网的电脑跑 06（也可放服务器上跑）：
```powershell
powershell -ExecutionPolicy Bypass -File .\06-verify.ps1
```
期望：首页 200 / manifest 200 / login 400（=后端活着且有校验）/ hangfire 401（=有密码保护）。
□ 浏览器打开 `https://zhz.js.cn` → 用 `Admin` + 第 5 步设的 `AdminPassword` 登录 → 进系统主页
□ **强烈建议**：登录后进「用户管理」，把 Admin 密码改成你日常用的（可仍用同一强密码）
□ **手机**：同一局域网/4G 打开 `https://zhz.js.cn` 登录 → 浏览器菜单「添加到主屏幕」→ 从主屏幕图标进入 → 到「扫码管理」试摄像头扫码报工一条

【成功标志】电脑、手机都能 https 访问并登录，手机能装 PWA、扫码有画面。
【如果不对】
- 网页能开但登录报错：API 没起来/库没连上，回第 10 步看日志；
- **浏览器直接输 `/login` 等深链 404**：SPA 兜底没生效，确认 05 已带 `location / try_files`（见第 11 步），改完 `Restart-Service nginx`；
- **手机打开根地址看不到任何登录按钮/进不去**：V1.2 前的版本手机版布局没做匿名登录入口，桌面版才有「登录」按钮——直接访问 `https://域名/login`（SPA 兜底已使其可达）或装带登录按钮的新版本；
- **打开即「应用加载失败或网络连接断开」**（PC F12 见 `net_uri_EmptyUri`）：发布把 `ApiSettings:BaseUrl` 写成空串而旧代码 `new Uri("")` 崩——V1.2 后代码已回退到站点基址；旧版本临时改服务器 `C:\mes\web\appsettings.json` 的 `BaseUrl` 为 `https://域名/` 后强刷；
- **更新部署后仍是旧界面 / 新 UI 永不出现**：Blazor loader 的非指纹文件（index.html、service-worker.js、appsettings.json、`_framework/` 下的 boot.json·webassembly.js）被长缓存 → 一直拉旧版 wasm。05 已内置 no-cache（`location /` 与 `location /_framework/` 均 `Cache-Control: no-cache`，见 05 §3.5），改过 nginx 记得 `Restart-Service nginx`；手机仍旧则清浏览器缓存并重装 PWA（真正 .wasm/.dll 自带 ?id=hash 指纹，无需清）；
- 手机摄像头黑屏/不能装 PWA：确认是 `https://`（不是 http）且证书域名是 `zhz.js.cn`（不要用 IP 访问）。

## 第 14 步　07 每日备份 + 收尾　🖥️

> 服务器是 **Express（无 SQL Agent）**，每日备份改由 **Windows 计划任务**（`MES_Backup_Daily`）完成。

□ 管理员 PowerShell（`C:\mes\deploy` 下）：
```powershell
powershell -ExecutionPolicy Bypass -File .\07-setup-backup.ps1
```
□ 脚本会自动：给系统账户授权连 SQL → 注册计划任务 `MES_Backup_Daily`（每天 02:30 跑 `backup-mes.ps1`）→ **当场试跑一次**备份
□ 顺手手动备一份留底：
> ⚠️ **Express 不支持 `WITH COMPRESSION`**（会报 1844 中止）——备份一律**不带压缩**。手动备份示例：
```powershell
sqlcmd -S localhost\SQLEXPRESS -E -Q "BACKUP DATABASE MES TO DISK='C:\MSSQL\Backup\manual.bak' WITH INIT, CHECKSUM"
```
□ 打开 `https://zhz.js.cn/hangfire`，用 `hf_admin` + `HangfirePassword` 登录确认能进（后台任务面板）

【成功标志】末尾出现绿色 `[OK] Scheduled Task 'MES_Backup_Daily' registered` 与 `[OK] trial backup verified: C:\MSSQL\Backup\MES_FULL_....bak`；Hangfire 能登录。
【如果不对】
- 授权/注册报错：确认以管理员身份运行，且当前账号是装 SQL 时的 sysadmin（用当初那个管理员 Windows 账号跑本步）；
- 试跑失败：打开 `C:\mes\logs\backup.log` 看最后几行定位（多半是连接串/权限）；任务已注册，修好后开始菜单搜「任务计划程序」→ `MES_Backup_Daily` → 右键「运行」再验证一次；
- 备份目录不存在：手动建 `C:\MSSQL\Backup`（正常 02 步已建好）。
