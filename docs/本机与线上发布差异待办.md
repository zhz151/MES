- **复现**：`ProcessGroup`（工序组）/ `OrderItem`（订单项次）/ `ProductRequirement`（技术要求）/ `SubcontractReturnItem`（委外子项）/ `MaterialReceiveCheck`（成检到料）5 类实体走「**先删旧记录、再插新记录**」的覆盖式导入。用户在数据工具点「下载」得到 xlsx（**含 ID 列**，`EntityDef` 统一注入）→ 不改动直接「上传」回导：清理块**先把旧记录删掉并 `SaveChanges`**，随后逐行按 ID 落到「已存在」分支 → 但缓存仍是**整表 `existingCache.Clear()`** → 第 2 行起 ID 校验失败报「**ID 不存在**」→ 全行失败 → **旧记录已删、新记录全建不出**，且提交后库中数据**凭空消失**（无报错弹窗之外的痕迹）。

### ④ NCR「待处理批次」两组重构 + 让步放行三字段 + 超阈值遗漏「忽略」（**前后端 + 迁移**）

- **待处理拆两组**：「待处理批次」卡片与「不合格品实时待处理」表**各分两节两表**——「**正常提交**」（来源=不合格反馈，**无条件列出**，`Bucket=NormalSubmitted`）/「**超阈值遗漏**」（来源=过程检验 / 成品检验，`Bucket=OverageMissing`），各自条数 chip。
- **超阈值遗漏判据（组级一条）**：组内不合格**合计 = 让步放行支 + 各流向支**，**合计 > `NcrThreshold.Count`（绝对支数）且 合计÷组内总数 > `NcrThreshold.Percent`（占比）**（**均严格大于**，旧 `>=` 已改）→ 产出**一条**被动记录；**让步放行计入分子但永不单独成行**。组聚合键 = 过程检验「批次 + 工序」/ 成品检验「批次 + **成检类型** + 检验项目」。
- **组定位键（~~三处~~ 两处一致；09-13 起）** `GroupKey = "{SourceType}|{ProductionBatchId}|{ProcessName}|{InspectionType}|{InspectionItem}"`（列表行 `GroupKey` / `Ncr.SourceGroupKey`；第三处「忽略台账唯一索引」随表删除）。
- **流向（方案 B/A）**：被动行**可展开明细**（返整 / 入在制库 / 可入备库 / 入次品库 / 退货 各 N 支）；「**次品流向**」列**只读**取组内支数最多流向（并列按 **返整 > 入在制库 > 可入备库 > 入次品库 > 退货** 定序），主动行（不合格反馈）为 NULL。
- **G1 问题反馈组新增 3 列**（被动比主动恰多 4 字段）：`… 次品支数 / 次品重量 / 问题描述 / **次品流向** / 让步支数 / 让步重量 / 让步说明`；`ConcessionRemark` 组内**去重拼接**（`string.Join("；", Distinct)`）。

### ⑦ 控制台告警与 DotNetObjectReference 僵尸引用修复（**纯 WASM + 静态 js**）

> 来源：线上 F12 控制台三条信息复核。① ② 为告警（其中 ② 暴露一处死代码），**③ 为真 bug**（与 Edge 打印崩溃无关，是独立问题，Release 构建下同样发生）。

| 文件 | 改动 |
|---|---|
| `MES.Blazor/wwwroot/index.html` | ① `<head>` 补 `<meta name="mobile-web-app-capable" content="yes" />`（Chrome/Edge 已弃用 `apple-` 前缀名，两条并存才对）；② 删 `<script src="js/pwa-install.js"></script>`，把其中**唯一有实际作用的一行** `beforeinstallprompt → e.preventDefault()` 内联进内联 `<script>`（**刻意保留**，见下）；③ 改写横屏提示条监听总线 |
| `MES.Blazor/wwwroot/js/pwa-install.js` | **删除文件**：全仓 0 调用方的死代码（`triggerPwaInstall` / `getPwaInstallPrompt` / `window.pwaInstallPrompt` 三个全局无人调用）。原实现只 `preventDefault()` 压制浏览器原生安装横幅、却从不调 `prompt()`，属**半截功能** |
| `MES.Blazor/Shared/LandscapeHintBanner.razor` | `stopLandscapeHintRefresh` 调用去掉 `_dotNetRef` 参数（原因同下） |

> **② 的取舍（用户拍板：不要安装横幅）**：MES 不做 PWA 安装引导 → **保留** `preventDefault()` 压制浏览器原生「安装 MES 应用」横幅。
> 代价：DevTools 会保留一条 **info 级**提示 `Banner not shown: beforeinstallpromptevent.preventDefault() called` —— 那是「你压制了横幅却没调 prompt()」的提醒，**属预期、非错误**；只要压制横幅就无法避免（除非删 `manifest.json` 的 `<link>`，副作用更大）。**故本条不再计为待修项**。

**③ 根因（真 bug，已在发布产物 `blazor.webassembly.js` 源码坐实）**：JSInterop 反序列化 reviver 对 **.NET 引用**是 `new DotNetObject(id)` —— **每次跨边界传递都新建 JS 包装对象**；只有 **JS 引用**才走 `getWrappedObject()` 缓存复用。故 `index.html` 原 `_landscapeHintRefs.indexOf(dotnetRef)` **恒为 `-1`**：

- `stop` 永远删不掉 → 组件销毁 `_dotNetRef.Dispose()` 后数组残留僵尸引用 → 之后每次 `resize`/`orientationchange` 回调已释放 id → `System.ArgumentException: There is no tracked object with id 'N'`（Uncaught in promise）；`N` = 该会话第 N 个创建的 DotNetObjectReference。
- `listen` 的 `indexOf` 去重同样失效 → 数组**只增不减**（内存泄漏，每次 resize 把全部僵尸各报一次）。

**修复**：改为**整体清空**（同一时刻只存在一个提示条——仅 `MobileLayout` 渲染、`ResponsiveLayout` 整壳切换）+ `invokeMethodAsync(...).catch()` 兜底 dispose/resize 竞态。
**触发场景**：手机**竖屏→横屏**时 `ResponsiveLayout` 判定 `innerWidth≥700` 整壳切 `MainLayout` → banner 随之销毁；而触发该切换的正是同一个 resize/orientationchange 事件。

**⚠️ 发布注意**：`web\js\pwa-install.js` 在线上会作为**孤儿文件残留**（覆盖发布不删文件），已无引用不会加载，可手动删除。
**验证**：`dotnet build MES.Blazor` **0 错 0 警**；定向 `LandscapeHintRuleTests` + `AppMenuTests` **17/17** 通过。界面生效待发布后核对：手机竖屏⇄横屏来回切换，控制台不应再出现 `no tracked object`；`apple-mobile-web-app-capable is deprecated` 应消失；`Banner not shown` **保留**（info 级、有意压制横幅，见上②）。
