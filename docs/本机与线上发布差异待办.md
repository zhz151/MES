## 待发布清单：打印富布局 35 列误伤修复

| 文件 | 改动 | 性质 |
|---|---|---|
| `MES.Blazor/wwwroot/js/print.js` | `openPdfFromApi(apiUrl, jsonBody, skipColumnCheck)` 加第三参，富布局请求跳过 35 列校验 | 静态文件 |
| `MES.Blazor/wwwroot/index.html` | `js/print.js?v=13` → `v=14`（强制浏览器拉新版，绕过旧缓存） | 静态文件（⚠️ 同文件还含已上线的移动端改动，重复覆盖幂等，无害） |
| `MES.Blazor/Pages/Batches/ProcessCardPrint.razor` | 工艺卡打印调用传第三参 `true` | WASM（须重新 publish 编译） |
| `MES.Blazor/Pages/Quality/Ncrs.razor.cs` | NCR「打印选中」去掉后端忽略的 columns、只发 ids + 传第三参 `true` | WASM（须重新 publish 编译） |

**问题背景**：工艺卡/质保 NCR 报告属富布局打印，但请求体携带 `Columns`（区块字段布局参数，工艺卡默认约 97 个），被 `print.js` 通用 35 列校验误拦，请求根本发不出去；后端 `ProcessCardPrintHelper` 富布局本不受 35 列限制。全仓 73 处 `openPdfFromApi` 审计：富布局误伤仅此 2 处（其余富布局单据不带 Columns，安全）。
**后端结论**：MES.Api **零改动**、无 EF 迁移、无数据变更。

## 待发布清单：手机扫码无反馈修复（scanner.js 双保险 + 加固）

| 文件 | 改动 | 性质 |
|---|---|---|
| `MES.Blazor/wwwroot/js/scanner.js` | 原生 BarcodeDetector 探测改 `getSupportedFormats()` 含 `qr_code`（原 `'BarcodeDetector' in window` 误判伪支持）；原生连续 1.5s 无结果自动降级 jsQR；jsQR 预加载 + 降采样到 480 + 帧率门限 100ms + 全程 try-catch 防中断 | 静态文件 |
| `MES.Blazor/wwwroot/index.html` | `js/scanner.js` → `js/scanner.js?v=1`（首引版本号，强制浏览器拉新版） | 静态文件 |
| `MES.Blazor/Pages/Equipment/EquipmentScan.razor.cs` | `DotNetObjectReference.Create(this)` 改存 `_dotNetRef` 字段 + OnInitialized 创建 + Dispose 释放（原 Create 不存字段 → GC 后扫码命中 JS 回调打空对象、页面无反应） | WASM（须重新 publish 编译） |

**问题背景**：夸克/微信内置等国产浏览器内核常「BarcodeDetector 有 API 无底座」（Android 原生实现依赖 Google Play 服务），`detect()` 恒空且被旧代码 try-catch 吞掉 → 卡死在原生死分支，jsQR 永远轮不到 → 摄像头画面在动但一直「扫描中」不识别。附 jsQR 老代码无 try-catch，单帧抛错即永久中断扫描循环。
**验证**：浏览器开 `https://zhz.js.cn/js/scanner.js?v=1`；夸克/微信内置进扫码页对准二维码应在约 1s 内识别（伪支持会自动降级 jsQR，识别延迟略增属正常）。

## 发布操作（下次正式发版时）

1. 💻 开发机跑 `scripts/deploy-windows/03-publish-local.ps1` 打包；
2. 🖥️ 服务器**只解压 zip 的 `web\` 覆盖 `C:\mes\web`**（**不要覆盖 `C:\mes\api`**——运行中的 MES.API 服务锁着 dll，覆盖会失败；本次 api 也无改动）；
3. `nginx` 无需重启（静态文件即时生效）；
4. 🌐 浏览器 **Ctrl+F5** 强刷；手机 PWA 已装的关闭重开/等自动更新（否则走旧 service worker 缓存）；
5. ✅ 验证：浏览器开 `https://zhz.js.cn/js/print.js?v=14`，内容应含 `skipColumnCheck`；进工艺卡打印不再弹「列过多」。

> 若某次发布还夹带其它后端改动，才需按 README 流程先 `nssm restart MES.API` 再覆盖 api。
