## 三、部署步骤

### 3.1 环境安装

```bash
# 安装.NET 8
sudo apt-get update
sudo apt-get install -y aspnetcore-runtime-8.0

# 安装SQL Server
# 添加 Microsoft 仓库（Ubuntu 22.04+ 推荐方式）
wget -qO- https://packages.microsoft.com/keys/microsoft.asc | gpg --dearmor | sudo tee /etc/apt/keyrings/microsoft.gpg > /dev/null
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/microsoft.gpg] https://packages.microsoft.com/ubuntu/22.04/prod jammy main" | sudo tee /etc/apt/sources.list.d/mssql-release.list
sudo apt-get update
sudo apt-get install -y mssql-server
# 安装后运行初始化配置
sudo /opt/mssql/bin/mssql-conf setup

# 安装Nginx
sudo apt-get install -y nginx
 ```

### 3.2 应用部署

```bash
# 发布应用
dotnet publish MES.Api -c Release -o ./publish/api
dotnet publish MES.Blazor -c Release -o ./publish/blazor

# 复制到服务器
scp -r ./publish/* user@server:/app/

# 配置systemd服务
sudo cat > /etc/systemd/system/mes-api.service << EOF
[Unit]
Description=MES API Service

[Service]
WorkingDirectory=/app/api
ExecStart=/usr/bin/dotnet /app/api/MES.Api.dll
Restart=always

[Install]
WantedBy=multi-user.target
EOF

# 启动服务
sudo systemctl enable mes-api
sudo systemctl start mes-api
 ```

### 3.3 Nginx配置

```nginx
server {
    listen 80;
    server_name mes.example.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name mes.example.com;
    
    ssl_certificate /etc/letsencrypt/live/mes.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mes.example.com/privkey.pem;
    
    # Blazor静态文件
    location / {
        root /app/blazor;
        try_files $uri /index.html =404;
    }
    
    # API代理
    location /api/ {
        proxy_pass http://localhost:7001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    
    # SignalR（规划中）
    location /hub/ {
        proxy_pass http://localhost:7001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
 ```

## 四、上线后增量更新

### 4.1 核心原则

| 原则 | 说明 |
|------|------|
| **数据库只加不减** | 只 `AddColumn` / `CreateTable`，禁止 `DropColumn` / `RenameColumn` |
| **新代码不动旧代码** | 新功能用新文件，不改已上线的 Controller / Service / Page 签名 |
| **API 向前兼容** | 响应只能加字段不能删字段；旧前端依然可调旧接口 |
| **回滚只回滚代码** | 数据库 Migration 不回滚，代码直接重新部署旧版本即可 |

### 4.2 更新部署步骤

```bash
# 第一步：跑数据库 Migration（如果有）
dotnet ef database update -p MES.Data -s MES.Api

# 第二步：发布 API
dotnet publish MES.Api -c Release -o ./publish/api
scp -r ./publish/api/* user@server:/app/api/

# 第三步：重启 API 服务
ssh user@server "sudo systemctl restart mes-api"

# 第四步：发布 Blazor WASM 前端
dotnet publish MES.Blazor -c Release -o ./publish/blazor
scp -r ./publish/blazor/wwwroot/* user@server:/app/blazor/
```

**顺序不可颠倒**：数据库 Migration 最先执行 → API 其次 → 前端最后。数据库不先跑，新版 API 可能因找不到新字段而启动失败。

### 4.3 一键部署脚本

在项目根目录创建 `deploy.sh`：

```bash
#!/bin/bash
set -e

SERVER="user@mes.example.com"
APP_DIR="/app"

echo "=== 1. 数据库 Migration ==="
dotnet ef database update -p MES.Data -s MES.Api

echo "=== 2. 发布 API ==="
dotnet publish MES.Api -c Release -o ./publish/api -q

echo "=== 3. 发布 Blazor ==="
dotnet publish MES.Blazor -c Release -o ./publish/blazor -q

echo "=== 4. 上传到服务器 ==="
scp -r ./publish/api/* $SERVER:$APP_DIR/api/
scp -r ./publish/blazor/wwwroot/* $SERVER:$APP_DIR/blazor/

echo "=== 5. 重启服务 ==="
ssh $SERVER "sudo systemctl restart mes-api"

echo "=== 部署完成 ==="
```

### 4.4 回滚方案

```bash
# API 回滚：重新部署旧版本即可（数据库不动）
# 前置条件：旧版本的 publish 产物有备份
ssh user@server "sudo systemctl stop mes-api"
scp -r ./backup/api/* user@server:/app/api/
ssh user@server "sudo systemctl start mes-api"

# 前端回滚：覆盖静态文件即可，无需重启服务
scp -r ./backup/blazor/* user@server:/app/blazor/
```

**注意**：数据库 Migration 不回滚。因为只加不减的原则保证了旧代码可以兼容新数据库（旧代码不读新增的列，新表旧代码无视）。

## 五、备份策略

### 5.1 数据库备份

```bash
# 每日全量备份（通过 sqlcmd 执行，文件名含日期）
sqlcmd -S localhost -U sa -P 'YourPassword' -Q "BACKUP DATABASE MES TO DISK = '/backup/MES_FULL_$(date +%Y%m%d).bak' WITH INIT, COMPRESSION;"

# 每小时增量备份
sqlcmd -S localhost -U sa -P 'YourPassword' -Q "BACKUP LOG MES TO DISK = '/backup/MES_LOG_$(date +%Y%m%d_%H%M).trn' WITH INIT, COMPRESSION;"
 ```

### 5.2 文件备份

```bash
# 每日同步到COS
#!/bin/bash
DATE=$(date +%Y%m%d)
tar -czf /backup/files_$DATE.tar.gz /app/files/
coscli cp /backup/files_$DATE.tar.gz cos://mes-backup/
 ```

### 5.3 备份保留策略

| 备份类型 | 保留时间 | 存储位置 |
|----------|----------|----------|
| 每日全量 | 30天 | 本地 + COS |
| 每小时增量 | 7天 | 本地 |
| 每月归档 | 12个月 | COS归档 |

## 七、Hangfire 后台任务配置

### 7.1 已配置的定时任务

| 任务名称 | 执行时间 | 说明 |
|----------|----------|------|
| 清理过期通知 | 每日凌晨2点 | 清理30天前的通知记录 |
| 质量过程跟踪物化表刷新 | 每小时（7 分触发，避开整点） | 兜底刷新最近1小时有变更或从未刷新的成检到料（QualityProcessTracking 增量刷新） |
| 全项目数据更新（中午） | 每日 11:55 | 兜底重建物化读模型 + 失效派生缓存（`FullProjectDataRefreshJob`：工单执行状况→订单列表→用料计划总览→质量过程跟踪→派生缓存失效，每步独立 scope，单步失败不中断） |
| 全项目数据更新（晚上） | 每日 23:55 | 同上（与中午任务同源，每日两次全量兜底，修复增量刷新漏网导致的读模型过期） |

### 7.2 Hangfire Dashboard

- 访问地址：`{API_BASE_URL}/hangfire`（开发环境默认可用，生产环境通过自定义授权过滤器保护）
- 认证方式：`HangfireCustomBasicAuthorizationFilter` 提供基本认证，生产环境建议额外通过 Nginx 限制访问

### 7.3 配置说明

Hangfire Dashboard 使用 `HangfireCustomBasicAuthorizationFilter`（C# 自定义类）进行授权，支持 appsettings 配置（默认值：admin/hangfire123）。Hangfire 使用 SQL Server 作为任务存储（在 MES 数据库中自动创建 Hangfire 相关表），支持任务持久化和重启恢复。
