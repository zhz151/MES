# 物料上下文数据库设计

**版本：V3.5**
**最后更新：2026-09-04**

---

## 一、概述

本文档定义物料上下文的数据库设计。物料上下文负责物资获取的全流程管理，包括采购执行和委外加工，通过字符串引用与工单上下文和仓库上下文松耦合衔接。

**当前范围：**
- 供应商档案（SupplierProfile）
- 采购订单（PurchaseOrder）
- 委外加工单（SubcontractOrder）
- 委外明细要求（SubcontractReturnItem）

**设计原则：**
- 一个采购订单只对应一项物料，无需采购项次（PurchaseOrderItem）
- 所有跨上下文的关联字段均为 **字符串（nvarchar）**，无物理FK约束
- 采购/委外单可选关联工单（SourceWorkOrderNo），通过工单中转查询销售订单/项次

`PurchaseOrder`

### 4.4 采购单号生成规则

格式：`CG + yyMMdd + 3位流水号`

示例：`CG260501001`

### 4.5 索引

| 索引名 | 字段 | 类型 |
|--------|------|------|
| PK_PurchaseOrder | Id | 聚集 |
| UK_PurchaseOrder_OrderNo | OrderNo | 唯一 |
| IX_PurchaseOrder_SupplierId | SupplierId | 非聚集 |
| IX_PurchaseOrder_Status | Status | 非聚集 |
| IX_PurchaseOrder_SourceWO | SourceWorkOrderNo | 非聚集 |
| IX_PurchaseOrder_RequiredDate | RequiredDate | 非聚集 |

### 4.6 业务规则

| 规则ID | 规则说明 |
|--------|----------|
| PO-001 | 采购单号由系统自动生成，格式 CG+yyMMdd+3位流水 |
| PO-002 | Status 枚举：Open=已下单，Partial=部分到货，Completed=已完成，OverReceived=超量到货（存储为字符串枚举名） |
| PO-003 | 采购单可独立存在，不强制关联工单（备料采购、常规补库） |
| PO-004 | SourceWorkOrderNo 为可选字段，用于追溯用料计划来源（字符串，无FK） |
| PO-005 | 一单一料：一个采购订单只包含一项物料，无需独立的项次表 |
| PO-006 | 到货进度由仓库入库记录触发：Service 按 SourceOrderNo 汇总 InventoryBatch 的入库数量/日期，入库/编辑/删除时自动增量同步，无需手动操作 |
| PO-007 | Status 自动计算规则（4 档）：IsForceCompleted 为 false 时，ReceivedWeight=0 → Open；否则若 到料重量>Weight×超额比率(PurchaseOverRatio 默认1.05) 且 超出量>超额偏差(PurchaseOverDeviation 默认100kg) → OverReceived（**优先于完成判定**）；否则若 IsThresholdMet(ReceivedWeight, Weight, PurchaseCompleteRatio, PurchaseCompleteDeviation)（默认完成率≥96.5% 且绝对偏差≤200kg）→ Completed；其余 → Partial；IsForceCompleted 为 true 时直接设为 Completed（不判超量） |
| PO-008 | TotalAmount = Quantity × UnitPrice（若数量和单价均有值） |
| PO-009 | 物料字段（Category/Grade/Spec）为自由文本（存储 MaterialType 枚举名），无物理关联（物料档案表已删除） |
| PO-010 | 实物入库由仓库上下文完成，入库时记录 SourceOrderNo 追溯（仓库侧字段） |
| PO-011 | 如需追溯销售订单/项次，通过 SourceWorkOrderNo → WorkOrder.OrderNo 中转查询 |

| 索引名 | 字段 | 类型 |
|--------|------|------|
| PK_SubcontractReturnItem | Id | 聚集 |

| IX_ReturnItem_OrderId | SubcontractOrderId | 非聚集 |

### 6.5 业务规则

| 规则ID | 规则说明 |
|--------|----------|
| RI-001 | ProcessStatus 枚举：Sent=已发出，PartialReturned=部分回收，Completed=已完成，OverReceived=超量到货（已移除 Cancelled；主表 SubcontractOrder.Status 聚合仍为 3 态，不产生 OverReceived） |
| RI-002 | ReturnedQuantity/ReturnedWeight 由仓库入库事件驱动（SyncSourceOrdersAsync → SubcontractHelper.SyncReturnItemFromBatches，带 overRatio/overDeviation 配置参数）从 InventoryBatch 汇总：批次已按 SourceOrderNo 过滤，匹配键为 SourceOrderSequence == SubcontractReturnItem.Sequence |
| RI-003 | ProcessStatus 自动计算（RecalcReturnItemStatus，仿采购订单超量到货）：IsForceCompleted=true → Completed；已回收=0 → Sent；否则若 回收重量>需求重量×超额比率(SubcontractOverRatio 默认1.05) 且 超出量>超额偏差(SubcontractOverDeviation 默认100kg) → **OverReceived（优先于完成判定）**；否则已回收≥需求量 → Completed；否则 PartialReturned |
| RI-004 | IsForceCompleted 可由用户手动勾选，也可由主表 IsForceCompleted 级联设置（主表强制完成→子表全部强制完成） |
| RI-005 | MaterialCategory 在圆棒穿孔场景下始终为"荒管"，表示实际消耗的原料分类 |

## 九、总结

```yaml
已定义内容:
  - SupplierProfile 供应商档案 ✅
  - PurchaseOrder 采购订单（一单一料） ✅
  - SubcontractOrder 委外加工单（主表：发出+收回汇总） ✅
  - SubcontractReturnItem 委外明细要求（子表：加工要求+费用+工单号） ✅
  - 统一编号规则 ✅
  - 跨上下文字符串引用规则 ✅
  - 通过工单中转查销售订单 ✅

设计变更:
  - 去除了PurchaseOrderItem（采购项次），简化为一单一料
  - 新增SubcontractReturnItem（委外明细要求），支持一单多规格收回，含SourceWorkOrderNo
  - 采购/委外通过SourceWorkOrderNo关联工单，通过工单中转查询销售订单/项次
  - 委外状态按收回重量达到发出重量×96.5%（且绝对偏差≤200kg）自动计算完成
  - 委外子项回收超量判定：回收重量>需求×超额比率(1.05) 且 超出量>超额偏差(100kg) → 超量到货（优先于完成）

一句话:
  - 物料上下文涵盖"买（采购）+ 委外（加工）+ 供应商档案"，
  - 通过字符串与工单、仓库上下文松耦合衔接。
```
