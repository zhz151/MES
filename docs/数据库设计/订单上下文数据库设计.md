## 三、SalesOrder（销售单）

### 3.1 表名
`SalesOrder`

### 3.2 字段定义

| 字段 | 类型 | 必填 | 默认值 | 说明 | 生成方式 |
|------|------|------|--------|------|----------|
| Id | int | ✅ | 自增 | 主键 | 🔄 数据库自动生成 |
| OrderNumber | nvarchar(50) | ✅ | - | 订单号，唯一索引 | 👤 用户输入 |
| SignDate | datetime2 | ✅ | - | 签订日期 | 👤 用户输入 |
| CustomerId | int | ✅ | - | 外键 → CustomerProfile.Id | 👤 用户选择 |
| CustomerName | nvarchar(200) | ✅ | '' | 客户名称（订单签约时的快照，从 CustomerProfile 复制） | 🔗 系统自动填充 |
| Salesman | nvarchar(50) | ✅ | '' | 业务员（订单签约时的快照，从 CustomerProfile 复制） | 🔗 系统自动填充 |
| EndCustomer | nvarchar(200) | ❌ | NULL | 最终用户（订单签约时的快照，从 CustomerProfile 复制） | 🔗 系统自动填充 |
| Status | nvarchar(20) | ✅ | 'Pending' | 订单状态枚举，存储为字符串 | 👤 用户选择 |
| RowVersion | timestamp | ✅ | - | 乐观并发控制 | 🔄 数据库自动生成 |
| LastItemChangeTime | datetimeoffset | ❌ | NULL | 订单下项次的最后变更时间（用于工单变更检测） | 📅 系统自动赋值 |
| CreatedTime | datetimeoffset | ✅ | GETUTCDATE() | 创建时间 | 📅 系统自动赋值 |
| CreatedBy | nvarchar(50) | ✅ | - | 创建人 | 📅 系统自动赋值 |
| UpdatedTime | datetimeoffset | ✅ | GETUTCDATE() | 更新时间 | 📅 系统自动赋值 |
| UpdatedBy | nvarchar(50) | ✅ | - | 更新人 | 📅 系统自动赋值 |

### 3.3 索引

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| PK_SalesOrder | Id | 聚集 | 主键 |
| UK_SalesOrder_OrderNumber | OrderNumber | 唯一 | 订单号唯一约束 |
| IX_SalesOrder_CustomerId | CustomerId | 非聚集 | 外键列 |
| IX_SalesOrder_SignDate | SignDate | 非聚集 | 日期查询 |
| IX_SalesOrder_Status | Status | 非聚集 | 状态筛选 |

### 3.4 业务规则

- 订单号全局唯一
- 状态流转：Pending → Confirmed → Cancelled
- `LastItemChangeTime` 在订单项次增、删、改时由系统自动更新为当前时间

## 四、OrderItem（销售项次）

`OrderItem`

| DeliveryDate | datetime2 | ✅ | - | 交货日期 | 👤 用户输入 |
| DelayPenalty | bit | ✅ | 0 | 是否延期罚款 | 👤 用户选择 |
| SettlementMethod | nvarchar(20) | ✅ | - | 结算方式（枚举） | 👤 用户选择 |
| PipeManufacturingType | nvarchar(20) | ✅ | - | 钢管制造类别（枚举） | 👤 用户选择 |
| StandardNo | nvarchar(100) | ❌ | NULL | 标准号（弱引用 StandardRegister，无 FK 约束） | 👤 用户选择 |
| DeliveryState | nvarchar(50) | ✅ | - | 交货状态（枚举） | 👤 用户选择 |

| OuterDiameter | decimal(18,3) | ✅ | - | 外径 | 👤 用户输入 |
| WallThickness | decimal(18,3) | ✅ | - | 壁厚 | 👤 用户输入 |
| Specification | nvarchar(50) | ✅ | - | 规格（外径*壁厚，冗余） | ⚙️ 系统自动生成 |
| OuterDiameterNegative | decimal(18,3) | ✅ | 0 | 外径下偏差 | 👤 用户输入 |

| WallThicknessNegative | decimal(18,3) | ✅ | 0 | 壁厚下偏差 | 👤 用户输入 |
| WallThicknessPositive | decimal(18,3) | ✅ | 0 | 壁厚上偏差 | 👤 用户输入 |
| LengthStatus | nvarchar(20) | ✅ | - | 长度状态（枚举） | 👤 用户选择 |
| MinLength | decimal(18,2) | ❌ | null | 最小长度（mm） | 👤 用户输入 |
| MaxLength | decimal(18,2) | ❌ | null | 最大长度（mm） | 👤 用户输入 |
| Quantity | int | ❌ | 0 | 支数 | 👤 用户输入 |
| Meters | decimal(18,2) | ❌ | null | 米数 | 👤 用户输入 |

| TheoreticalWeight | decimal(18,3) | ✅ | 0 | 理算重量 | 🧮 系统自动计算 |
| Remark | nvarchar(500) | ❌ | - | 备注 | 👤 用户输入 |
| CreatedTime | datetimeoffset | ✅ | GETUTCDATE() | 创建时间 | 📅 系统自动赋值 |
| CreatedBy | nvarchar(50) | ✅ | - | 创建人 | 📅 系统自动赋值 |
| UpdatedTime | datetimeoffset | ✅ | GETUTCDATE() | 更新时间 | 📅 系统自动赋值 |
| UpdatedBy | nvarchar(50) | ✅ | - | 更新人 | 📅 系统自动赋值 |

> **注：公差字段使用 HasColumnName 映射：OuterDiameterNegative → OuterDiameterMinus, OuterDiameterPositive → OuterDiameterPlus, WallThicknessNegative → WallThicknessMinus, WallThicknessPositive → WallThicknessPlus**

### 4.3 索引

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| PK_OrderItem | Id | 聚集 | 主键 |
| UK_OrderItem_Sequence_Active | SalesOrderId, Sequence | 唯一 | 订单内项次唯一 |
| IX_OrderItem_SalesOrderId | SalesOrderId | 非聚集 | 外键列 |
| IX_OrderItem_StandardGrade | StandardGrade | 非聚集 | 牌号查询 |

### 4.4 业务规则

- Sequence（项次号）在同一订单内自动递增，从 1 开始
- Specification 自动生成为 {OuterDiameter}*{WallThickness}
- 当 LengthStatus = Range 时，MinLength 和 MaxLength 必须大于 0
- PlantGrade 和 Density 根据 StandardGrade 从牌号对照表自动填充

## 八、OrderChangeNotification（订单变更通知）

### 8.1 表名

`OrderChangeNotification`

### 8.2 设计说明

订单变更通知表，用于记录订单项次变更事件。当订单下的项次发生增/删/改操作时，系统自动生成通知记录，供工单模块轮询检测并触发工单状态变更（已确定→待修正）。

### 8.3 字段定义

| 字段 | 类型 | 必填 | 默认值 | 说明 | 生成方式 |
|------|------|------|--------|------|----------|
| Id | uniqueidentifier | ✅ | NEWID() | 主键 | 🔄 数据库自动生成 |
| OrderNumber | nvarchar(50) | ✅ | - | 订单号 | 🔗 系统自动填充 |
| ChangeType | nvarchar(50) | ✅ | - | 变更类型（ItemAdded/ItemRemoved/ItemModified） | ⚙️ 系统自动生成 |
| WorkOrderCount | int | ✅ | 0 | 关联工单数 | ⚙️ 系统自动计算 |
| IsRead | bit | ✅ | 0 | 是否已读 | 👤 用户标记 |
| CreatedTime | datetimeoffset | ✅ | GETUTCDATE() | 创建时间 | 📅 系统自动赋值 |
| CreatedBy | nvarchar(50) | ✅ | - | 创建人 | 📅 系统自动赋值 |
| UpdatedTime | datetimeoffset | ✅ | GETUTCDATE() | 更新时间 | 📅 系统自动赋值 |
| UpdatedBy | nvarchar(50) | ✅ | - | 更新人 | 📅 系统自动赋值 |

### 8.4 索引

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| PK_OrderChangeNotification | Id | 聚集 | 主键 |
| IX_OCN_OrderNumber | OrderNumber | 非聚集 | 按订单号查询 |
| IX_OCN_IsRead | IsRead | 非聚集 | 按已读状态筛选 |

## 九、操作日志（基础设施统一管理）

订单上下文的操作日志由基础设施统一管理，不在订单上下文中维护独立实体。

详见 `基础设施数据库设计.md` 中的 OperationLog 统一表设计。

> **说明**：通过 `IOperationLogService.AddLogAsync("Order", entityId, ...)` 记录日志，`GetLogsAsync("Order", entityId)` 查询。OperationLog 表通过 Module="Order" 字段区分订单上下文。
