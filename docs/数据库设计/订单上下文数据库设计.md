## 一、概述

本文档定义订单上下文的数据库设计，包括实体、字段、索引、外键关系等。订单上下文是生产主线的起点：客户档案 → 销售订单 → 销售项次 → 产品要求（技术要求），并通过 `SalesOrder.OrderNumber` / `OrderItem.Sequence` 作为字符串引用被工单、仓库等上下文跨上下文消费。

**当前范围（6 个实体）：**
- 客户档案（CustomerProfile）
- 销售订单（SalesOrder）
- 销售项次（OrderItem）
- 产品要求（ProductRequirement）
- 牌号对照（StandardGradeMapping）——**实体现归属产品标准上下文**，本文档仅保留指针（见 §七）
- 订单列表读模型（OrderListSummary）——物化表，非业务表（见 §七之一）

**设计原则：**
- 上下文内（SalesOrder ↔ OrderItem ↔ ProductRequirement）使用物理外键；跨上下文一律 **字符串（nvarchar）** 引用，无物理 FK
- 客户的业务员/最终用户等信息在订单签约时**快照冗余**到 SalesOrder，避免客户档案变更影响历史订单
- 项次长度/公差等差异字段由 `OrderItem.StandardNo` 指向标准号弱引用（无 FK）
- 列表查询走 `OrderListSummary` 物化读模型，避免多表聚合实时计算

### 4.4 业务规则

- Sequence（项次号）在同一订单内自动递增，从 1 开始
- Specification 自动生成为 {OuterDiameter}*{WallThickness}
- 当 LengthStatus = Range 时，MinLength 和 MaxLength 必须大于 0
- PlantGrade 和 Density 根据 StandardGrade 从牌号对照表自动填充
- 总价自动计算口径（由计价单位决定取量）：元/Kg → 合同重量、元/米 → 米数、元/支 → 支数，即 总价 = 单价 × 对应取量；前端默认自动计算并实时刷新，**用户可手动覆盖总价**（覆盖后不再被自动刷新，除非点「恢复自动」）
- 金额字段由操作人员手工填写，系统不强制自动规则；**存量模拟数据回填规则（仅回填，非新建口径）**：计价单位=PerKg；单价按工厂牌号（含「316」→30、以「2」开头→35、其它→25）；总价=ROUND(单价×合同重量,2)（迁移 `20260907113212_AddOrderItemPricingUnitPriceColumns`，仅仿真数据）

## 七之一、OrderListSummary（订单列表读模型）

### 7.1.1 表名

`OrderListSummary`

### 7.1.2 设计说明

**物化读模型**（非业务表）：从 `SalesOrder` + `OrderItem` + `ProductRequirement` 聚合计算，再由 `WorkOrderExecutionSummary` / `InventoryBatch` / `OutboundRecord` 补充执行与库存聚合列。一个订单一条记录，通过 `OrderService.RefreshByOrderIdAsync()` **按订单增量刷新**（订单/项次/产品要求 CRUD、客户信息变更、工单执行状况增量路径触发）；`RefreshAllAsync()` 全量路径末尾连带刷新全部订单。

刷新机制详见 `docs/06_读模型架构.md` §1。

### 7.1.3 字段定义

| 字段 | 类型 | 必填 | 默认值 | 说明 | 生成方式 |

## 九、主外键关系汇总

| 子表 | 外键字段 | 主表 | 主键字段 | 关系类型 | 说明 |
|------|----------|------|----------|----------|------|
| OrderItem | SalesOrderId | SalesOrder | Id | 多对一 | 一个销售单可以有多个项次 |
| ProductRequirement | OrderItemId | OrderItem | Id | 一对一 | 一个项次只有一个产品要求 |

> **无 `SalesOrder → CustomerProfile` 外键**：订单仅持有客户信息快照（`CustomerName`/`Salesman`/`EndCustomer`），客户档案变更不回写历史订单。`OrderListSummary` 同理不建任何 FK（物化读模型，`OrderId` 为普通列）。
