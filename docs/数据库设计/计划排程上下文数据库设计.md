# 计划排程上下文数据库设计

**版本：V5.9**
**最后更新：2026-08-05**

---

## 一、概述

本文档定义计划排程上下文（Scheduling Context）的数据库设计。计划排程上下文包含两个独立实体、一个薄表和多个纯查询聚合：工单需求调整（OrderDemandAdjustment，API/UI 已迁移至工单上下文，数据库实体保留在此）、原锁计划（LEFT JOIN 实时查询模式，使用 RawMaterialLockPreExecution 独立表）、工单排程（WorkOrderSchedule，LEFT JOIN 实时查询模式，使用 WorkOrderPlan 薄表）、订单总况（ProductionOverview，无独立表）和成检计划（FinalInspectionPlan，无独立表）。所有实体均不通过外键关联到其他表（WorkOrderId 为逻辑关联）。

**当前范围（V5.3）：**
- 订单总况（ProductionOverview）：纯查询聚合，无独立实体/表
- 工单需求调整（OrderDemandAdjustment）：手工填写调整信息的独立实体
- 原锁计划：LEFT JOIN 实时查询模式（WorkOrderExecutionSummary + RawMaterialLockPreExecution），G13 直接从实体读取，无物化表
- **工单排程（WorkOrderSchedule）：LEFT JOIN 实时查询 + WorkOrderPlan 薄表，WorkOrderSchedules 物化表已删除（V4.5）**
- **段落分类设置（SectionFlowCategorySetting + SectionFlowCategoryItem）：流转量分析预设参数表（V1.2 新增，V5.1 重构为 K 荒管检/L 在制检/M 成品待检）**
- **批次计划（BatchPlan）：LEFT JOIN 实时查询视图（ProductionBatch + WorkOrderExecutionSummary + WorkOrderPlan + OrderDemandAdjustment），G4 在 Service 投影时 COALESCE（Plan优先）**
- **冷轧计划（ColdRollPlan）：LEFT JOIN 实时查询视图（ProductionBatch + WorkOrderExecutionSummary），无独立表**
- **冷轧排程（ColdRollSpecSchedule）：独立实体表，存储排程员在冷轧计划上作出的按规格的滚动排程决策**
- **批次计划薄表（BatchPlanSchedule）：独立实体表，存储排程员在批次计划上的批次级流转计划决策（8 个自动计算字段 + 抢单/备注），通过"计划安排"按钮自动快照，支持手工内联编辑**
- **成检计划（FinalInspectionPlan）：纯查询聚合，基于 ProductionBatch + MaterialReceiveCheck + FinalInspection 实时查询，无独立实体/表**
- **批次计划产量目标（BatchPlanTarget）：独立实体表，存储每个工段在本次计划周期的日产目标(吨)，批次计划页面 Tab 栏下方以内联编辑框展示，全量覆盖保存，默认值 0 表示未设目标（V5.3 新增）**

**设计原则：**
- 六个独立实体（OrderDemandAdjustment、RawMaterialLockPreExecution、ColdRollSpecSchedule、WorkOrderPlan、BatchPlanSchedule、BatchPlanTarget）均为独立实体，非读模型——包含需要持久化的手工覆盖字段
- 原锁计划、批次计划、冷轧计划、工单排程使用 LEFT JOIN 实时查询，不再存储物化表
- G15 预执行标记存储在 RawMaterialLockPreExecution 独立表（含 IsPreInput/BudgetInputDate/IsMainNoMaterialComplete/IsBudgetComplete 四个业务字段）
- G15 工单计划覆盖值存储在 WorkOrderPlan 薄表（仅含 WorkOrderId + 4 个可 null 覆盖字段）
- 订单总况为纯查询聚合，数据来自 WorkOrderExecutionSummary + ProductionBatch/ProcessGroup，不涉及数据写入
- WorkOrderId 均为唯一索引（每个工单一条记录）
- 工单排程为 LEFT JOIN 实时查询（WorkOrderExecutionSummary LEFT JOIN WorkOrderPlan），筛选条件：ProductionFlowProperty != "略"；WorkOrderSchedules 物化表已删除
- 批次计划为 LEFT JOIN 实时查询视图（ProductionBatch LEFT JOIN WorkOrderExecutionSummary + WorkOrderPlan + OrderDemandAdjustment），筛选条件：Status=None 或 InProgress
- 冷轧计划为 LEFT JOIN 实时查询视图（ProductionBatch LEFT JOIN WorkOrderExecutionSummary），按规格维度聚合冷轧时间桶分布，筛选条件：Status=None 或 InProgress
- 冷轧排程（ColdRollSpecSchedule）为独立实体表，是冷轧计划只读聚合的写入目标，使排程员能保存滚动排程决策，全量同步模式（增/改 + 删除不在列表中的旧记录）
- 段落分类设置表（SectionFlowCategorySetting + SectionFlowCategoryItem）为 AdminOnly 预设参数，前端管理页在"参数表"菜单下

## 四、RawMaterialLockPreExecution（原锁预执行 — G15 独立表）

### 4.1 表名

`RawMaterialLockPreExecution`

### 4.2 概述

原锁计划页面**不再使用物化表**，改为 LEFT JOIN 实时查询模式。`RawMaterialLockPreExecution` 是 G15 预执行数据的独立存储表，仅包含工单 ID 和用户编辑字段。

G1~G12 字段从 `WorkOrderExecutionSummary` 实时读取，G13 直接从 WorkOrderExecutionSummary 实体读取（由 RefreshAllAsync 从 OrderDemandAdjustment 同步），G15 从本表 LEFT JOIN 实时读取。

### 4.3 字段定义

| 字段 | 类型 | 必填 | 默认值 | 说明 | 生成方式 |
|------|------|------|--------|------|----------|
| Id | int | ✅ | 自增 | 主键 | 🔄 |
| WorkOrderId | int | ✅ | - | 工单ID（唯一约束） | ⚙️ |
| IsPreInput | bit | ✅ | 0 | 执行（近几日会投料） | 👤 |
| BudgetInputDate | date | ❌ | - | 预算投料日 | 👤 |
| IsMainNoMaterialComplete | bit | ✅ | 0 | 主号齐全（系统自动计算） | ⚙️ |
| IsBudgetComplete | bit | ✅ | 0 | 预算主号齐全（用户手工设置，级联影响 IsMainNoMaterialComplete） | 👤 |
| CreatedTime | datetimeoffset | ✅ | - | 创建时间 | 🔄 |
| CreatedBy | nvarchar(50) | ✅ | - | 创建人 | 🔄 |
| UpdatedTime | datetimeoffset | ✅ | - | 更新时间 | 🔄 |
| UpdatedBy | nvarchar(50) | ✅ | - | 更新人 | 🔄 |

### 4.4 索引

| 索引名 | 类型 | 列 | 说明 |
|--------|------|----|------|
| PK_RawMaterialLockPreExecution | PRIMARY KEY | Id | 主键 |
| UK_RMLPE_WorkOrderId | UNIQUE | WorkOrderId | 每工单一条 |

### 4.5 业务说明

- `IsMainNoMaterialComplete` 为**系统自动计算**，勾选或取消 IsPreInput 均触发重算，支持设 true 和回退 false：
  - **A质量影响**：`IsMainNoMaterialComplete = IsPreInput`（直接跟随）
  - **B已购未回/C计划未执行/D未完善计划**：按 `(SalesOrderNo, ProductionMainNo, RawMaterialLockRemark)` 分组，组内**全部**工单"就绪" → 全部 IsMainNoMaterialComplete=true；**任一**未就绪 → 全部 false。
    某工单"就绪"条件（三选一）：
    - 用户显式标记`IsPreInput=true`，**或**
    - **B类型**：`G5.PendingRoughTubeQty == 0 && G5.PendingOutsourceFinishQty == 0`（待回物料已回），**或**
    - **C/D类型**：`G7.FlowStatus >= 1`（已开始流转）
  - 组内无 PreExecution 记录的成员自动创建一条
- `BudgetInputDate` 为用户手工输入的日期（MudTextField，失焦保存），仅当 IsPreInput=true 时显示输入框
- `ExecutionError` 为 DTO 计算字段（不存储）：`IsPreInput && (!BudgetInputDate.HasValue || BudgetInputDate.Value.Date < DateTime.Today)`
- `IsBudgetComplete` 为用户手工切换的 MudSwitch 字段，切换为 true 时级联设置同组全部工单 `IsMainNoMaterialComplete=true`，false 时强制同组全部 `IsMainNoMaterialComplete=false`

## 七、WorkOrderPlan（工单计划薄表 — G15 覆盖值）

### 7.1 表名

`WorkOrderPlan`

### 7.2 概述

工单计划薄表存储用户在工单排程页面对 G15 分组字段的手工覆盖值。WorkOrderSchedules 物化表已于 V4.5 删除，工单排程改为 LEFT JOIN 实时查询模式。WorkOrderPlan 是唯一的持久化覆盖表。

**覆盖展示模式（COALESCE）：** `DisplayXxx = PlanXxx ?? SystemXxx`
- PlanXxx 有值（非 null）→ 使用用户覆盖值
- PlanXxx 为 null → 使用 WorkOrderExecutionSummary 中的系统值

### 7.3 字段定义

| # | 字段名 | 类型 | 必填 | 默认值 | 说明 |
|---|--------|------|------|--------|------|
| 1 | Id | int | ✅ | 自增 | 主键 |
| 2 | WorkOrderId | int | ✅ | — | 工单ID（唯一约束） |
| 3 | ScheduleStage | int | ❌ | NULL | 工单状态覆盖值（0=工单完成 1=原料锁定 2=生产执行 3=成品检验；null=使用系统值） |
| 4 | UrgencyLevel | nvarchar(50) | ❌ | NULL | 紧急性覆盖值（A+急/A急/B顺/C缓/D缓；null=使用系统值） |
| 5 | ProductionAttentionProcess | nvarchar(200) | ❌ | NULL | 生产关注工序覆盖值（null=使用系统值） |
| 6 | ProductionFlowProperty | nvarchar(50) | ❌ | NULL | 生产流转性覆盖值（正常/暂停/待料/疑问/略；null=使用系统值） |
| — | 审计字段（继承 BaseEntity） |
| 7 | CreatedTime | datetime2 | ✅ | — | 创建时间 |
| 8 | CreatedBy | nvarchar(50) | ✅ | — | 创建人 |
| 9 | UpdatedTime | datetime2 | ✅ | — | 更新时间 |
| 10 | UpdatedBy | nvarchar(50) | ✅ | — | 更新人 |

**字段数：** 5 业务字段 + 4 审计字段 = 10 字段

### 7.4 索引

| 索引名 | 类型 | 列 | 说明 |
|--------|------|----|------|
| PK_WorkOrderPlans | PRIMARY KEY | Id | 主键 |
| UK_WOP_WorkOrderId | UNIQUE | WorkOrderId | 每工单一条 |

### 7.5 业务说明

- WorkOrderPlan 为薄表，仅存储用户手工覆盖值，主数据来自 WorkOrderExecutionSummary
- 4 个字段全部可 null：null = 使用系统值
- 当用户将 4 个覆盖字段全部清空（全部为 null）时，后端自动删除该行记录（无需保留无意义的空行）
- 保存 `SavePlanAsync` 实现 Upsert 语义：存在则更新，不存在则插入，全部 null 则删除
- "计划安排"按钮：批量将匹配查询的工单 Plan 覆盖值设为系统值（等于重置为用户未覆盖状态），并删除不匹配查询的 Plan 行（清理僵尸数据）

| UK_BPT_SectionName | UNIQUE | SectionName | 每个工段一条记录 |

### 9.5 业务说明

- DailyTarget=0 表示该工段未设定产量目标，前端淡化显示（白色字体）
- DailyTarget>0 时前端蓝底蓝字高亮显示
- 保存模式为全量覆盖：前端编辑任一目标值后调用 `SaveAllAsync(dtos)` 全量保存，后端先 DELETE 所有旧记录再 INSERT 新记录
- 默认值来自 SectionFlowCategorySetting.DailyProductionTarget（变异量预算日产），用户可手工调整
- 数据仅在批次计划页面使用，无其他消费方

## 十三、ColdRollSpecSchedule（冷轧排程）

### 13.1 表名

`ColdRollSpecSchedule`

### 13.2 概述

冷轧排程是冷轧计划的写入目标实体，存储排程员在冷轧计划简化视图上所作出的滚动排程决策（3-4 天短期排程）。按 `(ProcessType, BilletSpec, RollingSpec, IsFinished)` 四字段唯一约束，全量同步模式（前端全量加载 + 全量保存，增/改 + 删除不在列表中的旧记录）。

冷轧计划为只读 LEFT JOIN 实时聚合视图，排程员在 UI 上编辑排程计划后保存到本表，系统将排程数据反推应用到 `ProductionBatch` 进行工单锁定。

### 13.3 字段定义

### 13.5 业务说明

- 排程数据由冷轧计划简化视图的"编辑排程"模式生成，通过工具栏按钮进入/退出编辑模式
- 简化视图保存时展开到明细级别（`_rawAllItems` 匹配明细行），确保每个明细行均保存排程数据
- 前端通过 `ColdRollSpecScheduleService.GetAllAsync()` 加载全部排程数据，通过 `SaveAllAsync(list)` 全量同步保存（增/改 + 删除不在列表中的旧记录）
