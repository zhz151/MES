## 一、概述

本文档定义工单上下文的数据库设计，共 16 张表：工单主表（WorkOrder）、统一通知表（Notification）、4 种外购/库存类计划表（PurchaseSemiPlan / PurchaseFinishedPlan / InventoryPlan / RoundBarPiercingPlan）、3 张计划工序组子表（SemiPlanProcessGroup / InventoryPlanProcessGroup / PiercingPlanProcessGroup）、在产改制计划表（InProcessReworkPlan）及其工序组子表、在产主工单计划表（InMainWorkOrderPlan）、工单需求调整表（OrderDemandAdjustment）、定尺工单冗余表（FixedLengthWorkOrder），以及 2 张物化读模型（WorkOrderExecutionSummary / WorkOrderListSummary）。

> **上下文边界**：`InventoryPlan` / `InventoryPlanProcessGroup` 实体文件位于 `MES.Data.Entities.Warehouse`（数据归属工单上下文管理）；`PurchaseSemiPlan` / `PurchaseFinishedPlan` 位于 `MES.Data.Entities.Materials`。

## 十六、订单变更检测机制说明

### 16.1 依赖字段

工单变更检测依赖订单表（SalesOrder）中的 `LastItemChangeTime` 字段，该字段定义在**订单上下文**中：

| 字段 | 类型 | 说明 |
|------|------|------|
| LastItemChangeTime | datetimeoffset | 订单下项次的最后变更时间，在项次增、删、改时由系统自动更新 |

### 16.2 检测逻辑

```csharp
// 伪代码示例
// 订单项次 CRUD 增量触发
var confirmedOrders = await _context.SalesOrders
    .Where(so => so.Status == SalesOrderStatus.Confirmed)
    .ToListAsync();

foreach (var order in confirmedOrders)
{
    var workOrders = await _context.WorkOrders
        .Where(wo => wo.SalesOrderNo == order.OrderNumber)
        .ToListAsync();

    if (!workOrders.Any()) continue;

    // 比较项次最后变更时间与工单创建时间
    if (order.LastItemChangeTime.HasValue && 
        order.LastItemChangeTime > workOrders.Max(wo => wo.CreatedTime))
    {
        // 订单项次发生过变更，工单状态变更为待修正
        foreach (var workOrder in workOrders)
        {
            if (workOrder.Status == WorkOrderStatus.Confirmed) // 已确定状态
                workOrder.Status = WorkOrderStatus.Pending;      // 变更为待修正
        }
    }
}
```

### 16.3 时序说明

| 场景 | LastItemChangeTime | 工单创建时间 | 检测结果 |
|------|-------------------|--------------|----------|
| 首次生成工单 | NULL | 2026-04-24 10:00 | 无变更，状态保持已确定 |
| 订单项次未变更 | 2026-04-24 09:00 | 2026-04-24 10:00 | 工单创建时间更新，无变更 |
| 订单项次已变更 | 2026-04-24 11:00 | 2026-04-24 10:00 | **检测到变更，状态变更为待修正** |
