# 批次上下文数据库设计（V4.9）

**版本**：V4.9
**最后更新**：2026-08-01

---

## 一、概述

本文档定义批次上下文的数据库设计。批次上下文负责生产批量管理，包括生产批次创建、工序组管理、生产跟踪等核心功能。

**当前范围**：
- 生产批次（ProductionBatch）
- 工序组（ProcessGroup）
- 生产记录（ProductionRecord）
- 工段委外（SectionOutsource）
- 委外回收（OutsourceRecovery）
- 成检到料（MaterialReceiveCheck）← 菜单归属质量管理，后端仍在批次上下文
- 操作日志（OperationLog，由基础设施统一管理）
- 去油/酸洗入缸记录（PicklingInRecord）
- 去油/酸洗完工记录（PicklingOutRecord）
- 批次-库存关联（ProductionBatchInventory）

> 过程检验（ProcessInspection）已独立为质量管理模块实体，详见 `质量管理上下文数据库设计.md`

**关联上下文**：
- **→ 工单上下文**：ProductionBatch.WorkOrderNo 字符串引用 WorkOrder.WorkOrderNo（冗余29个字段）
- **→ 仓库上下文**：ProductionBatch.SourceBatchNo 字符串引用 InventoryBatch.BatchNo（冗余18个仓库字段）
- **→ 批次上下文内部**：ProductionRecord/SectionOutsource 引用 ProductionBatch 和 ProcessGroup；OutsourceRecovery 引用 SectionOutsource；PicklingInRecord 引用 ProductionBatch 和 ProcessGroup；PicklingOutRecord 引用 PicklingInRecord
- **↔ 质量管理上下文**：ProcessInspection 引用 ProductionBatch 和 ProcessGroup（过程检验独立模块，但影响批次跟踪计算）

---

## 二、实体清单

| 序号 | 实体 | 表名 | 说明 |
|------|------|------|------|
| 1 | ProductionBatch | ProductionBatch | 生产批次（生产编号），核心实体 |
| 2 | ProcessGroup | ProcessGroup | 工序组，对应工艺卡中的一行生产工序 |
| 3 | ProductionRecord | ProductionRecord | 内部生产记录，工段内部执行记录 |
| 4 | SectionOutsource | SectionOutsource | 工段委外，工段委外发出记录 |
| 5 | OutsourceRecovery | OutsourceRecovery | 委外回收，委外加工完成后回收记录 |
| 6 | MaterialReceiveCheck | MaterialReceiveCheck | 成检到料，所有工序完成后料到成品检验处 |
| 7 | PicklingInRecord | PicklingInRecord | 去油/酸洗入缸记录，入缸报工，关联批次+工序组 |
| 8 | PicklingOutRecord | PicklingOutRecord | 去油/酸洗完工记录，出缸登记，关联入缸记录 |
| 9 | ProductionBatchInventory | ProductionBatchInventory | 生产批次与库存批次多对多关联（合并投料） |

## 五、设计说明

### 5.1 生产编号规则

格式：`YYMM-XXXX`
- YY：年份后两位
- MM：月份（两位）
- XXXX：当月序号（从0001开始，每月重置）
- 示例：`2605-0001`、`2605-0042`

### 5.2 制几率计算与验证

定尺（LengthStatus="Fixed"）时自动计算值，不定尺时默认0。
提交时无条件验证生产批次 `ProductionRatio > 0`（统一必填）。
```
制几率 = floor(投料单重 / 工单单重)
       = floor((领料重量/领料支数) / (总重量/总支数))
```

### 5.3 字段冗余策略

ProductionBatch 冗余了29个工单字段和18个仓库字段，原因是：
- 工单和库存批次可能在批次创建后被修改/删除，批次需要保留创建时的快照
- 减少查询时的跨上下文 Join 操作
- 前端新建批次时一次性展示所有信息，避免多次请求

### 5.4 工序组设计

- 每个批次包含多个工序组（ProcessGroup），按 SequenceNumber 排序
- 工序名称目前支持：引用 `ProcessNames.All` 常量数组（荒管处理/在制修检/60冷轧/50冷轧/30冷轧/20冷轧/三辊冷轧/冷拔/附加成检），前端 MudSelect 选项由此生成
- 每个工序组包含15个工段执行顺序字段（ColdRollDraw 到 Warehouse），值为 null 表示该工段不涉及该工序
- 前端支持"复制上个工序组"功能：从最新批次复制所有工序组及其明细数据

### 5.5 去油/酸洗设计说明

- 去油/酸洗采用**两阶段模式**：先入缸（PicklingInRecord）→ 浸泡中 → 完工出缸（PicklingOutRecord）
- 每个入缸记录最多关联一条完工记录（UK 约束），但数据库设计为 1:N，支持未来可能的多次出缸场景
- 入缸状态由 PicklingStatus 枚举管理：Soaking（浸泡中）→ Completed（已完工），状态在创建完工记录时自动更新，删除完工记录时自动恢复为 Soaking
- 入缸记录与批次的关系为 NO ACTION（不级联删除），防止误删批次时丢失酸洗记录
- PicklingInRecord 通过 ProductionBatchId 关联 ProductionBatch，冗余 BatchNo/ProcessName/ManufacturingSpec/TagNo/PlantGrade 字段用于列表展示

### 5.6 制造状态（ProductStatus）计算规则

**适用范围**：ProductionRecord、SectionOutsource、PicklingInRecord、PicklingOutRecord、ProcessInspection

**计算规则**（由 `ProductStatusHelper.Calculate` 统一实现）：

1. **成品**（优先级最高，判定顺序先成品后荒管）：制造规格 `ManufacturingSpec == 成品规格`（成品规格 = 批次 `batch.Specification`）&& **制造物品为成品类**（ManufacturingItem ∈ {Finished, OrderFinished, CriticalFinished, SpecialDeliveryStatus}）→ **"成品"**；不再按 SequenceNumber 最大工序组判定（成品工序组 = ManufacturingSpec == 成品规格 的工序组，可能多个，含"附加成检"）
2. **工序 == "荒管处理" → "荒管"**
3. **工序 == "在制修检" + 非末道工序（工序名 ≠ SequenceNumber 最大工序组的工序名）+ 批次存在"荒管处理"工序组 + 规格匹配其制造规格 → "荒管"**
4. **以上均不满足 → "在制"**

**关键约束**：
- 判定顺序：先"成品"后"荒管"（成品检查在荒管检查之前执行）
- "在制修检"的荒管判定仍需排除末道工序（SequenceNumber 最大的工序组），末道工序绝不可能是"荒管"
- 非"荒管处理"也非"在制修检"的工序（如"50冷轧""60冷轧""冷拔"等），制造规格 == 成品规格 且为成品类则为"成品"，否则为"在制"，绝不可能是"荒管"
