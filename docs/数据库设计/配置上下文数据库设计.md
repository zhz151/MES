# 配置上下文数据库设计

**版本：V1.9**
**最后更新：2026-08-08**

---

## 一、概述

本文档定义配置上下文（Configuration Context）的数据库设计。配置上下文包含六张系统参数表：标准工量天数（StandardWorkDays）、交货状态附加天数（StandardWorkDayDeliveryStates）、业务参数配置（ConfigParameters）、日产估算（DailyOutputEstimates）、重点工段日产（DailyProductionCapacities）和员工管理（Employees），用于替代原有硬编码逻辑，支持管理员页面动态配置。此外，配置上下文的管理页面还包括段落分类及变异量系数设置（SectionFlowCategorySettings，数据表属 Scheduling 上下文）和工位管理（Workstations，扫码报工基础配置）。

**当前范围（V1.6）：**
- StandardWorkDays：各工段标准天数配置，支持牌号前缀覆盖
- StandardWorkDayDeliveryStates：各交货状态附加天数配置，含默认值
- ConfigParameters：通用数值型业务参数配置（EAV 模式），替代约 50+ 处硬编码业务数值常量
- DailyOutputEstimates：日产估算配置，按成品外径区间设定日产能（吨/天），用于产能工量计算
- DailyProductionCapacities：重点工段日产配置，各工段日产能力（吨/天），用于工单总览产能负荷计算
- Employees：员工基础信息（工号/姓名/部门/岗位/工资结算模式），为扫码报工和工资结算提供基础数据
- Workstations（扫码报工基础配置）：工位管理，绑定工位编码 → 工段 + 设备 + 报工模板类型
- SectionFlowCategorySetting + SectionFlowCategoryItem（跨上下文引用）：段落分类及变异量系数预设表，数据实体属 Scheduling 上下文，管理 UI 在配置上下文参数表菜单下

**设计原则：**
- 五张表均为独立参数表，不通过外键关联任何业务表
- 业务模块通过 Service 层提供的 `GetStandardDaysMapAsync` / `GetDeliveryStateExtraDaysMapAsync` / `GetConfigMapAsync` 方法读取参数
- CRUD 统一通过内联编辑页面，AdminOnly 权限

|--------|------|------|------|
| PK_ConfigParameters | 主键 | Id | |
| UK_CP_Category_ParamKey | 唯一 | Category + ParamKey | 同一分类下参数键唯一 |
| IX_CP_Category | 非聚集 | Category | 按分类快速查询 |

### 5.4 设计说明

ConfigParameter 采用 EAV（Entity-Attribute-Value）模式，将散落在10+个 Service 中的硬编码数值常量统一为数据库配置：

- **Category**：按功能模块分组，如 `MaterialPlanStatus`（用料计划状态阈值）、`DefaultValue`（通用默认值）、`DimensionTolerance`（尺寸公差系数）、`WarehouseThreshold`（仓库阈值）、`ReworkRatio`（改制系数）、`SequenceJump`（序号跳步）等
- **ParamKey**：每个 Category 下的唯一键名
- **ParamValue**：decimal 类型，Service 通过 `GetConfigMapAsync(category)` 获取整个分类的字典映射

> **存量库幂等补行：** DbInitializer 种子仅全新库自动写入；存量库升级时需手动执行以下 SQL 补行（以 PurchaseOverRatio 为例）：

```sql
-- 存量库幂等补行：PurchaseOverRatio（采购超额比率）
IF NOT EXISTS (
    SELECT 1 FROM ConfigParameters
    WHERE Category = 'WarehouseThreshold' AND ParamKey = 'PurchaseOverRatio'
)
INSERT INTO ConfigParameters (Category, CategoryDisplay, Context, ParamKey, ParamValue, Remark, CreatedTime, CreatedBy, UpdatedTime, UpdatedBy)
VALUES ('WarehouseThreshold', '采购-超额比率', '物料', 'PurchaseOverRatio', 1.05, '采购超额比率阈值(实际采购/委外量>计划量×此比率判定超额采购/超额穿孔)', GETDATE(), 'system', GETDATE(), 'system');
```

### 5.6 缓存策略

Service 层通过 `IConfigParameterService.GetConfigMapAsync(category)` 获取参数映射。由于 Service 注册为 `Scoped` 生命周期（每次 HTTP 请求创建新实例），各 Service 内部的 `_configMaps` 字典仅缓存单次请求内的重复查询，修改参数后下一次请求自动加载新值，无需重启。
