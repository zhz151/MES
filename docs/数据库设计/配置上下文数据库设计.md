# 配置上下文数据库设计

**版本：V1.15**
**最后更新：2026-09-04**

---

## 一、概述

本文档定义配置上下文（Configuration Context）的数据库设计。配置上下文包含九张系统参数表：工段工量天数（StandardWorkDays）、交货状态附加天数（StandardWorkDayDeliveryStates）、系统参数（ConfigParameters）、规格日产预估（DailyOutputEstimates）、重点工段日产（DailyProductionCapacities）、员工管理（Employees）、枚举显示配置（EnumDisplayDefinitions）、字典显示配置（DictValueDefinitions）和工序组定义（ProcessDefinitions），用于替代原有硬编码逻辑，支持管理员页面动态配置。此外，配置上下文的管理页面还包括工位管理（Workstations，扫码报工基础配置）。

**当前范围：**
- StandardWorkDays：各工段标准天数配置，支持牌号前缀覆盖；含 SectionKey/DisplayOrder/IsEnabled 展示层动态化字段
- StandardWorkDayDeliveryStates：各交货状态附加天数配置，含默认值
- ConfigParameters：通用数值型系统参数（EAV 模式），替代约 50+ 处硬编码业务数值常量
- DailyOutputEstimates：规格日产预估配置，按成品外径区间设定日产能（吨/天），用于产能工量计算
- DailyProductionCapacities：重点工段日产配置，各工段日产能力（吨/天），用于工单总览产能负荷计算
- Employees：员工基础信息（工号/姓名/部门/岗位/工资模式与靠工参数/成检资质/扫码报工工段工序），为扫码报工和工资结算提供基础数据
- EnumDisplayDefinitions：枚举显示配置（EnumKey/Value/DisplayName/DisplayOrder/Remark），管理枚举值的中文显示名与排序（不可加值）
- DictValueDefinitions：字典显示配置（DictKey/Value/DisplayName/DisplayOrder/IsEnabled/Remark），管理字典值的显示名/排序/启停（可隐藏加值）
- ProcessDefinitions：工序组定义（ProcessKey/ProcessName/DisplayOrder/IsEnabled/IsColdRoll/IsColdDraw/DefaultSections/Remark），管理工序组中文名/启停/默认工段
- Workstations（扫码报工基础配置）：工位管理，绑定工位编码 → 工段 + 设备 + 报工模板类型

**设计原则：**
- 各参数表均为独立参数表，不通过外键关联任何业务表
- 业务模块通过 Service 层提供的 `GetStandardDaysMapAsync` / `GetDeliveryStateExtraDaysMapAsync` / `GetConfigMapAsync` 方法读取参数
- CRUD 统一通过内联编辑页面，AdminOnly 权限

### 5.4 设计说明

ConfigParameter 采用 EAV（Entity-Attribute-Value）模式，将散落在10+个 Service 中的硬编码数值常量统一为数据库配置：

- **Category**：按功能模块分组，如 `MaterialPlanStatus`（用料计划状态阈值）、`DefaultValue`（通用默认值）、`DimensionTolerance`（尺寸公差系数）、`WarehouseThreshold`（仓库阈值）、`ReworkRatio`（改制系数）、`SequenceJump`（序号跳步）等
- **ParamKey**：每个 Category 下的唯一键名
- **ParamValue**：decimal 类型，Service 通过 `GetConfigMapAsync(category)` 获取整个分类的字典映射

### 5.6 缓存策略

Service 层通过 `IConfigParameterService.GetConfigMapAsync(category)` 获取参数映射。由于 Service 注册为 `Scoped` 生命周期（每次 HTTP 请求创建新实例），各 Service 内部的 `_configMaps` 字典仅缓存单次请求内的重复查询，修改参数后下一次请求自动加载新值，无需重启。
