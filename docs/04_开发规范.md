## 三、分层约束规则

### 3.1 跨层调用规则

- Controller → 只能调用 Service，不能直接操作 DbContext
- Service → 可以调用 DbContext 和其他 Service
- 禁止跨层调用

### 3.2 分层职责表

| 层级 | 职责 | 禁止行为 |
|------|------|----------|
| Controller | 接收请求、参数验证、调用Service、返回响应 | 编写业务逻辑 |
| Service | 核心业务逻辑、事务管理 | 直接返回 Entity（用 DTO） |
| Data | 数据库操作、实体定义 | 包含业务逻辑 |

### 3.3 DTO 投影原则（列表页查询）🔥

列表页 Service 的 `GetPagedAsync`，**无论是否有跨表字段，一律优先使用 DTO 投影模式**（`IQueryable<Dto>` 而非 `IQueryable<Entity>`），原因：

1. **`ApplyFilters`/`ApplySort` 需要 DTO 属性名** — 反射基于 DTO 属性匹配 `FilterDescriptor.Field`/`SortBy`，若用实体模式 + `select new Dto` 在投影后，筛选排序条件会因属性名不一致而失效
2. **跨表字段统一处理** — 写时冗余（§4.8 读模型）优先：列表页优先读目标表冗余字段、**禁止 JOIN 来源表**；仅当冗余字段缺失或为历史字段时，才用 LINQ `join` + `select new Dto` 投影
3. **性能与可维护性** — 投影仅取所需字段，避免整表加载

```csharp
// ✅ 正确：DTO 投影，ApplyFilters/ApplySort 反射 DTO 属性，跨表字段统一处理
var query = from p in _context.PurchaseOrders
            select new PurchaseOrderDto {
                Id = p.Id,
                OrderNo = p.OrderNo,
                // 不含跨表字段也使用投影
            };
// 无跨表字段时也可用 Select() 链式投影：
var query = _context.PurchaseOrders
    .Select(p => new PurchaseOrderDto {
        Id = p.Id,
        OrderNo = p.OrderNo,
    });
query = query.ApplyFilters(queryParams.Filters);
query = query.ApplySort(queryParams.SortBy, queryParams.IsDescending);

// ❌ 禁止（即使无跨表字段）：
var query = _context.PurchaseOrders.AsQueryable();  // IQueryable<Entity> 而非 DTO
query = query.ApplyFilters(...);  // 反射 Entity 属性而非 DTO 属性
query = query.Select(e => new PurchaseOrderDto { ... });  // 后置投影
```

**禁止的实体查询模式**：
```csharp
// ❌ 错误：实体 IQueryable + crossTableFields HashSet + 后置填充
var query = _context.PurchaseOrders.AsQueryable();
if (crossTableFields.Contains("workOrderNo"))
    query = query.Where(...);  // 手动子查询
// ... 手动判断跨表字段、30 分支 sort switch
// ... 后置填充 WorkOrder 字段
```

**分层边界**：
- 投影能处理的（聚合/子查询/条件逻辑/字符串处理）→ 直接在投影中完成
- 投影翻译不了的（调 Service/复杂业务规则）→ Hybrid 模式：先投影查询，再内存补充
- Create/Update 操作仍使用实体查询模式（DTO 投影只读）

## 四、实体设计规则

### 4.1 审计字段

每实体必须继承 `BaseEntity`（含 Id/CreatedTime/CreatedBy/UpdatedTime/UpdatedBy）。使用 bigint 主键的实体可不继承但需实现 `IAuditableEntity` 接口。

### 4.2 字段与主键

- 主键：`Id`（自增INT），禁用业务字段做主键
- 外键：`{主表名}Id`（如 `CustomerId`）
- 时间字段以 `Time` 结尾，状态字段用枚举

### 4.3 状态枚举定义

```csharp
public enum SalesOrderStatus { Pending = 0, Confirmed = 1, Cancelled = 2 }
```

### 4.4 物理删除

所有实体统一物理删除（`_context.Remove(entity)`）。

### 4.5 枚举存储规范

- 所有枚举字段存储为字符串（`HasConversion<string>()`）
- 例外（存储为 int）：`WorkOrder.MaterialPlanStatus`、`WorkOrderExecutionSummary` 中约 20 个状态字段——**int 档位字段**（第三类·算法档位），中文显示统一走 `IntStatusDisplayHelper`（§4.11.1），禁止内嵌 switch
- **EF Core 查询**：对 `HasConversion<string>()` 枚举字段筛选时，禁止 `.ToString()` 字符串比对，应 `TryParse` 为枚举后直接比对枚举值

### 4.6 枚举中文显示规范 🔥

枚举字段在页面/打印显示时必须中文，统一通过 **`EnumHelper.GetDisplayName()`**（后端/打印）或 **`DisplayHelper.GetXxxText()`**（前端）转换，两者最终委托同一 `EnumHelper` 映射源：

```csharp
// 单一事实源：EnumHelper 中注册（MES.Core.Helpers.EnumHelper）
Register<DeliveryState>(("SolutionAnnealedAndPickled", "固溶酸洗"), ...);

// 前端委托：DisplayHelper → EnumHelper（MES.Blazor.Helpers.DisplayHelper）
public static string GetDeliveryStateText(DeliveryState status) => EnumHelper.GetDisplayName(status);
public static string GetDeliveryStateText(string? status) => EnumHelper.GetDisplayName<DeliveryState>(status);

// 列定义 DisplayConverter（优先方式，§6.34）
new() { Key = "DeliveryState", FilterType = "enum",
    DisplayConverter = v => v is DeliveryState s ? EnumHelper.GetDisplayName(s) : null }
```

**规则**：
- 禁止 `.ToString()` 直出枚举（Razor 的 `@item.Status` 或 builder.AddContent 输出）
- 新增枚举时必须在 `EnumHelper` 中通过 `Register<T>()` 注册中文映射（`_ => value.ToString()` 回退等于显示英文，违规）
- **显示名可配置覆盖**：`EnumDisplayDefinitions` 配置表优先（改名/排序，不可加值），`EnumHelper` 静态注册兜底；配置写操作后刷新进程内静态快照（`ApplyEnumOverrides`/`ApplyEnumOrder`），保存即生效，无需重启 API
- `DisplayHelper.GetXxxText()` 只做委托，禁止 switch/case 硬编码中文（历史遗留代码已完成清理）
- **此约束适用于全代码库**：任何枚举/整数字段转中文显示的场合（包括页面私有方法、ResolvePrintValue 内联 switch、GetCellDisplayText 等），均须委托 `DisplayHelper` 或 `ColumnDef.DisplayConverter`，禁止手写 switch 映射
- **int 档位字段例外（第三类·算法档位）**：存储为 `int` 的非枚举字段（投料/流转/主号关注/入库/计划执行/到料实投一致性等档位），不走 `EnumHelper`，统一走 `IntStatusDisplayHelper.GetXxxText()`/`GetXxxOptions()`（§4.11.1）
- 筛选下拉框通过 `DisplayHelper.GetEnumFilterOptions<T>()` 从 EnumHelper 生成，确保筛选/显示/打印三处中文一致（见 §6.26）

### 4.7 DTO 枚举属性类型规范 🔥

DTO 中代表枚举值的属性 **必须使用实际的枚举类型**，禁止使用 `string`。这是从根源杜绝枚举显示问题的核心架构决策：

```csharp
// ✅ 正确：DTO 使用实际枚举类型
public class EquipmentListDto
{
    public LifecycleStatus LifecycleStatus { get; set; }
    public UsageType UsageType { get; set; }
    public RunningStatus RunningStatus { get; set; }
}

// ❌ 禁止：DTO 使用 string 存储枚举值
public class EquipmentListDto
{
    public string LifecycleStatus { get; set; }  // ❌ 编译不检查，每处显示/打印需手动转换，遗漏即显示英文
}
```

**收益**（DTO 用枚举类型后自动获得的保障）：

| 场景 | string DTO | enum DTO |
|------|-----------|---------|
| 打印 `TablePrintHelper.FormatValue` | 反射见 string 不处理，原样输出 | 反射见 IsEnum，自动调用 `EnumHelper.GetDisplayName()` |
| DataExchange 导入导出 | 需声明 `EnumType` 元数据 | EnumHelper 自动识别 |
| Service 投影 | `e.Status.ToString()` → 运行时异常 | `e.Status` → 编译期校验 |
| 前端编辑器 | 人肉记得调用 GetDisplayName | 编译器要求匹配类型 |

**实现细则**：

1. **DTO 属性使用枚举类型**，可空字段用 `EnumType?`，非可空字段设默认值：
   ```csharp
   public LifecycleStatus LifecycleStatus { get; set; } = LifecycleStatus.Active;
   public DeliveryState? DeliveryState { get; set; }  // 可选字段用可空
   ```

2. **Service LINQ 投影**：实体已是枚举时直接赋值，实体存 string 时用 `Enum.Parse<T>()`（加 null/empty 守卫）：
   ```csharp
   // 实体存 enum → 直接赋值
   Status = e.Status,
   // 实体存 string → Enum.Parse + 守卫
   LengthStatus = string.IsNullOrEmpty(e.LengthStatus) ? null : Enum.Parse<LengthStatus>(e.LengthStatus),
   ```

3. **Entity → string DB 写入**：实体属性仍按 §4.5 存 `string`，Service 在 `CreateAsync`/`UpdateAsync` 中通过 `.ToString()` 转为实体 string：
   ```csharp
   entity.LifecycleStatus = request.LifecycleStatus.ToString();
   ```

4. **JSON 序列化**：API 全局已配置 `JsonStringEnumConverter`，枚举序列化为字符串名而非数字，API 契约不变。

5. **前端绑定**：
   - `MudSelect` 泛型参数 `T` 使用实际枚举类型（`MudSelect<LifecycleStatus>`），`MudSelectItem.Value` 使用枚举成员
   - 字符串比较 `status == "Fixed"` → 枚举比较 `status == LengthStatus.Fixed`
   - `string.IsNullOrWhiteSpace(status)` → 可空枚举 `status == null`

**业务标记 Key 例外（§4.7 豁免）**：

`RawMaterialLockRemark`（原料锁定备注）属**固定值域业务标记 Key**，与工段/工序/紧急度同模式（英文 Key 存储 + `XxxKeys` 常量类 + `ToChinese` 显示 + `FilterType="string"`），但**非配置字典**（值域固定四类不可加值），故 DTO 保持 `string`、豁免转枚举类型：

| 项 | 说明 |
|----|------|
| 存储值 | 英文 Key（`RawMaterialLockRemarkKeys`，MES.Core.Constants）：`QualityReplenish`(A质量补料) / `ExecuteRework`(B执行返整) / `ExecutePlan`(C执行计划) / `ImprovePlan`(D完善计划)；主号级判定，仅 `ScheduleStage=2` 原料锁定时有值。存量中文由迁移 `20260806082411_RawMaterialLockRemarkToEnglishKey` 统一转英文 |
| 豁免理由 | 固定四值状态机（同 `UrgencyLevelKeys` 紧急度六值），值域编译期锁定不参与配置表；DTO 保持 `string`、前端 `FilterType="string"`；显示/打印/筛选 Display 一律 `RawMaterialLockRemarkKeys.ToChinese(...)`（`?? "-"`/`?? ""` 兜底），禁止直出 Key |
| 消费方 | `RawMaterialLockPlanAndExecutionService.IsMainNoMaterialComplete` `case RawMaterialLockRemarkKeys.*` 匹配，按 `(订单号, 主号, 备注)` 分组、组内全部就绪→全部齐全 |
| 判定逻辑 | 见 WorkOrderExecutionService：投料满足+返整满足→`ExecuteRework`；投料满足→`QualityReplenish`；投料不满足+计划∈{满足,超量}→`ExecutePlan`；否则→`ImprovePlan` |

> 若未来该字段需要参与中英文切换/国际化，再评估改为枚举；当前它属固定值域的业务标记 Key。

### 4.8 冗余快照规范（写时冗余，读时分场景）🔥

| 场景 | 规则 |
|------|------|
| 写入时 | 从来源表读取当前值写入目标表冗余字段 |
| 列表页（ServerData 分页） | **禁止 JOIN 来源表**，直接读冗余字段 |
| 详情页/编辑页 | 如需要最新值可 JOIN 来源表；如"历史定格"则直接读 |
| 历史定格字段 | 注释标注 `// 历史定格，无需溯源`，写入后永不 JOIN |

### 4.9 批次跟踪字段刷新规范

跟踪字段（`CurrentExecDate`/`CurrentGroupName`/`CurrentSectionName` 等）系统自动计算，禁止手动编辑。`IsForceCompleted = true` 时跳过自动刷新。`UpdateProductionBatchRequest` 不得包含跟踪字段。

### 4.10 枚举类字段中英标准（全局总纲 + 工段特殊枚举）🔥

**适用范围**：所有"枚举类字段" = 存储字符串的枚举（`Status`/`ProductionType`/`DeliveryState` 等，`HasConversion<string>`）+ 数据库字典/关键字枚举（如工段 `SectionName` 存英文 Key）。

**全局总纲**：

| 层级 | 约定 |
|------|------|
| 后端（含数据库） | 一律英文 —— 枚举存英文名（`Enum.ToString()`），工段存英文 Key（`SectionKeys`） |
| 前端 | 一律中文 —— 显示（列表/详情/Chip/统计）、打印（后端 PDF + 前端打印）、下拉选择（MudSelect 选项）、列表字段筛选（ExcelFilter 下拉 Display）；**筛选 Value 保持英文 Key，仅 Display 转中文** |
| 数据工具（DataExchange Excel 上传/下载） | 一律中文 —— 导出转中文、导入中文转回英文/Key |
| 唯一例外 | 搜索/排序后端按英文 Key 匹配；前端 Keyword 关键字搜索可命中英文或中文（见 §4.10.3） |

> 普通枚举的存储/显示/DTO 规范见 §4.5/§4.6/§4.7；本节是全局总纲 + 工段特殊枚举链路，两者互补。

#### 4.10.1 普通枚举（§4.5-§4.7 的全局总纲）

- 存储：`HasConversion<string>()` 存枚举英文名（§4.5）
- DTO：实际枚举类型，禁止 `string`（§4.7）
- 显示：`EnumHelper.GetDisplayName()` / `DisplayHelper.GetXxxText()` / `ColumnDef.DisplayConverter`（§4.6）

#### 4.10.2 工段特殊枚举（SectionName 存英文 Key）🔥

**背景**：工段在 `StandardWorkDays` 配置表可改名（中文），若存储层用中文，改名会破坏后端 `SectionName == SectionDefs.X`（中文常量）匹配。因此**存储与后端匹配一律用稳定英文 Key，前端显示用中文**，配置表改中文名不再破坏任何匹配。

**存储契约**：

- `SectionKeys`（`MES.Core.Constants`）：26 个英文 Key 常量（`ColdRollDraw`/`OilPipeCut`/`Cut`/.../`Extra2`），与 `SectionDefs` 常量名一一对应；提供 `IsKey`/`ToKey`/`ToChinese`（对遗留中文/别名/未知值幂等兼容）。**26 预置超集**（原 19 → 2026-08-05 扩展）：新增 乳液浸洗/光亮退火/喷丸/打头/包装/备用1/备用2（备用1/2 为槽位列默认隐藏）；改名 喷砂丸→喷砂、打焊头→焊头（`SectionDefs.Aliases` 保留旧中文兼容，数据导入/修复匹配变体名称用）
- 业务表存储层 `SectionName`（生产记录/去油酸洗入缸/工段委外/过程检验/工位/工序组配置等）存英文 Key（如 `"Cut"`）；`StandardWorkDays` 配置表本身 `SectionName` 存中文 + `SectionKey` 存英文
- 后端匹配点判断左操作数来源（**执行时最高优先**）：
  - **存储值**（记录/请求/批次派生字段 `.SectionName`）→ 匹配用 `== SectionKeys.X`
  - **ProcessGroup 派生**（`GetNonEmptySections`/`GetSectionsFromProcessGroup`）→ 仍是中文，保持 `== SectionDefs.X` 或中文比较
  - **跨表比较**（存储 Key vs 工序组中文）→ 必须经 `SectionKeys.ToKey()` 归一
- 新增下拉/提交：Value=英文 Key、Text=中文

**前端显示（SectionDisplayHelper）**：

```csharp
// MES.Blazor.Helpers.SectionDisplayHelper（静态，MainLayout 启动经 section-name-map 加载 OverrideMap）
public static string GetSectionNameText(string? value)
{
    if (string.IsNullOrEmpty(value)) return value ?? string.Empty;
    if (OverrideMap != null && OverrideMap.TryGetValue(value, out var cn)) return cn;
    return SectionKeys.ToChinese(value) ?? value;
}
```

- 优先级：配置表 OverrideMap（`StandardWorkDay.SectionName`，可随配置改名）→ 兜底 `SectionKeys.ToChinese` → 原样返回
- 所有工段显示点（列表单元格/详情/Chip/统计/对话框）必须走 `GetSectionNameText`，禁止直出存库 Key
- ⚠️ `GetSectionNameText(null)` 返回 `""`（非 null），占位须用 `string.IsNullOrEmpty(x) ? "-" : SectionDisplayHelper.GetSectionNameText(x)`，禁止 `?? "-"`

**筛选（ExcelFilter）**：

- `_selectedValues` 存 **Value(英文 Key)** 供后端匹配 —— `GetCellRawValue`/`GetFilterValue`/filter-contexts 返回 Key 是**正确**的
- `@opt.Display` 转中文显示（`BuildFilterContextOptions` 中映射）
- 修复筛选维度只改 Display，**禁止**把 Value 也改成中文（会失配）

**关键字搜索**：前端 Keyword 搜索工段须中文可命中：

```csharp
(x.SectionName != null && (SectionDisplayHelper.GetSectionNameText(x.SectionName).Contains(kw, StringComparison.OrdinalIgnoreCase)
    || x.SectionName.Contains(kw, StringComparison.OrdinalIgnoreCase)))
```

> ⚠️ 上例是 **ToList 后内存过滤**（`GetSectionNameText` 静态 helper 不可翻译为 SQL），故可用 `OrdinalIgnoreCase`；若该 Keyword 走 EF 查询（IQueryable），字符串比较必须用 `==`，见 §10.5.1。

**打印**：

- 前端 Mode B ⓪ 打印：字典值已由 `ResolvePrintValue`/`DisplayConverter` 转中文（§6.33/§6.34）
- 后端 Mode B ⓫ 打印：`TablePrintHelper.GeneratePdf` 无 resolver 直接渲染字典 → **手工构造的打印字典必须预转中文**，用 `SectionDisplayText(key, sectionNameMap)` 辅助（配置表 `ISectionNameDisplayService.GetSectionNameMapAsync()` 优先 + `SectionKeys.ToChinese` 兜底 + `?? ""`）

**数据工具（DataExchange）**：

- 导出：`Property=="SectionName"` 时 `ToDisplayAsync()` 转中文；FK 反向导出（工段委外/去油酸洗入缸）返回后转中文

后端 Keyword 搜索/排序按英文 Key 匹配（SQL 层）；前端 Keyword 关键字搜索可命中英文或中文（提交前归一或双匹配，见各模块实现）。数据库字典/关键字枚举不适用 §4.7 的 DTO 枚举类型规则（存 Key 的字段 DTO 仍为 `string`）。

#### 4.10.4 字典类字段（配置表可扩展）与枚举同标准 🔥

**结论**：字典类字段（工序组 `ProcessName`、责任类型 `LiabilityType`、工段 `SectionName` 等配置表驱动字段）与枚举类字段在「存储英文 + 显示中文」上**同一标准**。两者中文名**均经配置表可改名**：枚举走 `EnumDisplayDefinitions`（只改中文名/排序，**不可加值**，值域受 C# 枚举成员约束），字典走 `DictValueDefinitions`（改名/排序/`IsEnabled` 隐藏/**可加值**）；英文名/Key 均不可改。

**选型标准（新增字段时）**：因两者中文名均可配置，唯一实质区别是**值域是否可扩展**，故按值域可变性决策：

- **值域可能增长 / 需业务方自行加值** → 用**字典**（`DictValueDefinitions` 可加值，加值无需改代码）。例：责任类型（LiabilityType 原为枚举，P7 并入字典）
- **值域固定 / 编译期锁定** → 用**枚举** + `EnumDisplayDefinitions` 更轻（DTO 强类型，§4.7）。例：新增的固定值域字段建议走枚举；**存量例外**：产类（ProductStatus）虽值域固定，但为支持中文改名/统一配置管理已并入字典（`DbInitializer.DictValueSeedKeys` 之一，配置页可改中文名）

规则一句话：**"可能加值 → 字典；固定值域 → 枚举"，默认倾向字典**（低成本支持扩展）。产类入字典属历史决策，新增字段仍按此规则选型。

**与枚举的对照**：

| 维度 | 枚举类字段 | 字典类字段 |
|------|-----------|-----------|
| 存储层/后端匹配 | 英文枚举名（`Enum.ToString()`） | 稳定英文 Key（`XxxKeys` 常量） |
| 前端显示 | `DisplayHelper.GetXxxText()`（→ `EnumHelper`，`EnumDisplayDefinitions` 覆盖优先 → 静态注册兜底） | `XxxDisplayHelper.GetXxxText()`（配置 OverrideMap 优先 → `KeyToChinese` 兜底） |
| 后端打印 | `EnumHelper.GetDisplayName()`（配置覆盖，写操作后刷新进程内静态 → 保存即生效，无需重启） | `XxxService.ToDisplayAsync()`（配置优先 → 兜底） |
| 下拉/筛选 | Value=英文、Display=中文 | 同左 |
| DataExchange | 导出中文、导入转回英文 | 同左 |
| 可改名性 | 中文 ✅ 经 `EnumDisplayDefinitions` 可改（**不可加值**）；英文名 ❌ 不可改 | 中文 ✅ 经 `DictValueDefinitions` 可改（**可加值**）；英文 Key ❌ 不可改 |

**落地清单（新增字典字段/配置表时）**：

1. `XxxKeys`（`MES.Core.Constants`）：英文 Key 常量 + `IsKey`/`ToKey`/`ToChinese`/`KeyToChinese`/`ChineseToKey`
2. 配置实体 + `AppDbContext` 配置（唯一索引 `UK_Xxx_XxxKey`）+ 种子
3. `IXxxService`/`XxxService`：`GetXxxNameMapAsync()`（IMemoryCache 5 分钟）+ `ToDisplayAsync`/`ToKeyAsync`
4. 前端 `XxxDisplayHelper`（静态 `OverrideMap`）+ `MainLayout` 启动预加载映射
5. `XxxDefinitionService`（Blazor）拉取 `enabled-values`（`GET /api/dict-value-definition/enabled-values?key=`）/`xxx-name-map` 端点；下拉/筛选 Display 转中文
6. DataExchange：导出 `ToDisplayAsync`、导入 `ToKeyAsync`
7. 迁移：存量中文 → Key（未知值按策略处理，如置 NULL 或保留）

**代码分支匹配铁律**：参与分支/状态推进的字段（如 `MaterialPlanService` 的 `LiabilityType == LiabilityTypeKeys.FactoryDepartment`、`ProductStatusHelper` 产类判定）一律用英文 Key 常量，**禁止 `== "中文"`** —— 这样配置表改中文名后逻辑仍正确。

**到料实投一致性判定**（PlanInputConsistency，2026-08-11 七档定稿）：判定基准=实际已投料量（InputWeight）vs 现可投料总重（TotalAvailableWeight=**到货量口径**，G4~G6 用到货量 PiercingSubInWeight+SemiInWeight+FinishInWeight，下单未到货不视为现可；G7~G10 仍为出库/投料量）。**阶段门控（判定顺序最前）**：主号关注=生产执行(3)/成品检验(4)/主号完成(1) 已过投料期 → 仅按缺失量判定——理论缺失总料重（TotalMissingWeight=计划7项−现可7项）>计划投料总重×3% → **5 错误-无需投料**（业务已完成还在投料计划，缺口率>3% 必须修正）；其余（含缺口≤3% 容差内）→ **6 略**（降噪不细看）。原料锁定期(2)/主号暂停(0) 走原五态：4=错误-无料已投（已投>0 且现可=0，计划外投料最异常）；3=疑问-到料超投（已投>现可×1.03）；2=疑问-到料少投（已投<现可×0.97 且截止到料日<今天）；1=待投（滞后且截止到料日=今天）；0=一致（±3% 内/双零/滞后但截止到料日空或>今天）。**截止到料日 CutoffArrivalDate**（实体+DTO）= G4~G6 仓库进库（InventoryBatch.SourceOrderNo 经采购/委外来源单号映射回工单）InboundDate 与 G7/G8 出库（OutboundRecord.OutboundDate）的最大值，主号级 MainNoCutoffArrivalDate 取组内 Max。三处同步：DTO 计算属性 / SQL 表达式（G3PlanInputConsistencyExpr 嵌套三元含 DateTime.Today）/ ApplyComputedFilters；前端七档 MudChip 颜色 `GetPlanInputConsistencyColor`（0绿/1蓝/2橙/3橙/4红/5红/6灰）。

#### 4.11.2 第一类枚举字段

**场景**：C# 枚举，存储英文名（`HasConversion<string>`），值域编译期锁定（§4.5/§4.7）。

**新增纪律**：

1. 枚举定义后 `EnumHelper.Register<T>()` 注册中文名（`EnumDisplayDefinitions` 配置表覆盖优先，静态注册兜底）
2. DTO 用**实际枚举类型**，禁止 `string` 直存 + `.ToString()` 直出（§4.7）
3. 显示 `DisplayHelper.GetXxxText()` / `EnumHelper.GetDisplayName()`，筛选 Value=英文、Display=中文
4. DataExchange 登记 `isEnum: true`（导出转中文、导入转回枚举名）

#### 4.11.3 字典类字段

**场景**：值域可扩展、配置表驱动（工段/工序组/责任类型/紧急度等），存储英文 Key（§4.10.4）。

**新增纪律**：

1. `XxxKeys` 常量（`MES.Core.Constants`）+ `IsKey`/`ToKey`/`ToChinese`/`KeyToChinese`/`ChineseToKey`
2. 字典 key 常量登记到 `DictValueDefaults`，种子写入 `DictValueDefinitions`
3. 显示走 `XxxDisplayHelper` / `DictValueDisplayHelper`（配置 OverrideMap 优先 → `KeyToChinese` 兜底）
4. 下拉选项优先 `DictValueDefinitionService.GetEnabledValuesAsync(dictKey)`（`/enabled-values` 端点），失败兜底静态 `KeyToChinese` —— 隐藏（`IsEnabled=false`）与加值即时生效
5. 分支/状态推进用英文 Key 常量比较，禁止 `== "中文"`

**存量状态**（2026-08-06）：表单/内联编辑下拉已全量收敛 `GetEnumOptions<T>()`（B4）；字典下拉已接入 `GetEnabledValuesAsync(dictKey)`（`/enabled-values` 端点）：InboundHistory 责任类型、FinalInspectionPlan/WorkOrderSchedules 紧急度、BatchPlans/WorkOrderSchedules 流转与关注目标等，`IsEnabled` 隐藏/加值即时生效，失败兜底静态 `KeyToChinese` —— 新字段一律按上表执行。

### 4.12 工单号规则（主号/次号）🔥

- **主号 ProductionMainNo** = 管型前缀（`PipeManufacturingType`：焊管 `WeldedPipe`→`H` / 无缝管→`X`，`WorkOrderService.GetMainNoPrefix`）+ 2 位序号（如 `X01`/`H01`），随订单明细按管型分组生成
- **次号 ProductionSubNo** 2 位**全模式非空**（新规则）：定尺（`LengthStatus.Fixed`）→ `01`~`99` 两位数字（正则 `^\d{2}$`）；范围尺/非定尺 → 固定 `F0`。后端 `WorkOrderService.ValidateSubNo` + 前端 `WorkOrderGenerate` **双校验**，防止脏数据入库
- 工单号 = 主号 + 次号；唯一索引 `SalesOrderNo + ProductionMainNo + ProductionSubNo`（`AppDbContext.WorkOrder.cs`）
- 后端 Keyword/排序/匹配一律按主号/次号英文原值；主号级聚合键 = `订单号|主号` 转大写归一（`OrdinalIgnoreCase`）

### 4.13 仓库订单信息组·主号（ProductionMainNo）🔥

2026-08-09 起，仓库（`InventoryBatch`）的订单信息维度由「项次（OrderItemIds/SourceOrderSequence）」改为「**主号（ProductionMainNo）**」：

- `InventoryBatch.ProductionMainNo`（实体+迁移+refresh-all 回填，回填自 `WorkOrder.ProductionMainNo`；索引 `IX_InventoryBatch_ProductionMainNo`）
- **订单信息组查询用「订单号+主号」**：待发货（`PendingDeliveryQueryService`）Keyword `(d.ProductionMainNo ?? "").Contains(kw, ...)`、筛选上下文 `AddDistinct("ProductionMainNo")`；`OrderItemIds` 仅作内部解析「产品标准/标准等级/交货状态」的关联键，**查询/显示已改用主号**
- 前端项次列（`OrderItemIds`/`SourceOrderSequence`）按仓库适用性 `SetNotApplicable(cols, ...)` 隐藏/禁用，列表新增「主号」列替代「项次」
- 批量查生产批次/记录 IN 查询用 `Chunk(batchIds, 1000)` 防 SQL Server 2100 参数上限

### 4.14 定尺切割长度匹配（CutLengthMatchType）🔥

**标识枚举**（`MES.Core.Enums`，存枚举名 `"FullMatch"`/`"MainNoMatch"`，null=不适用）：

- `FullMatch` = 完全匹配：成品长度 ∈ **本工单号**（订单+主号+次号）的定尺长度集合
- `MainNoMatch` = 主号匹配：成品长度仅 ∈ **订单+主号** 的定尺长度集合（非本工单号，补料尾批/返整批跨次号流转）
- null = 不适用：非成品切割 / 非定尺 / 预成切 / 无成品长度 / 定尺集合为空

**统一出口**：

- 纯判定 `CutLengthMatchHelper.Match(HashSet<decimal>? workOrderLengths, HashSet<decimal>? mainNoLengths, decimal? length)`（`MES.Core.Helpers`）+ 中文 `GetText`（完全匹配/主号匹配/空串）
- 前端 `DisplayHelper.GetCutLengthMatchText`/`GetCutLengthMatchColor`（绿/橙/默认）/`GetCutLengthMatchOptions`
- 长度集合 `FixedLengthWorkOrder`：`GetLengthMapsAsync()` 一次取全表 → `ByWorkOrderNo`（工单号→长度）+ `ByMainKey`（`订单号|主号`→长度）；跨模块校验用 `GetLengthsByMainNoAsync`/`GetLengthsByWorkOrderNoAsync`

**三模块落地**（2026-08-08/09）：生产记录（成品切割断切长度）、成检（`FinalInspectionService`）、成品入库（`InventoryBatchWriteService`）。入库仅 **成品库(FG) + 订单类成品（排除备料 Finished 无工单号）+ 定尺 + 关联可解析** 才核查。**批次编辑级联重算**：批次（工单号/长度）变更后，其生产记录/成检到料/成品入库的 `CutLengthMatchType` 必须重算（旧值清空/重算，勿残留）。

**硬校验**（`EnforceCutLengthMatch`）：仅**自动填充第2种「检验入库」按生产批号**时由前端置 `EnforceCutLengthMatch=true`，且同时满足 FG 成品库 + 订单类成品 + 定尺 + 生产批号非空 + 工单号非空，此时入库长度必须命中「订单号+主号」定尺长度集合，否则抛 `BusinessException` 禁止入库（采购/委外与手动填写不受影响）。**内联编辑核查条件**=「生产批次 + 工单号都非空」才核查，否则标识清空。排序：`FullMatch=0 / MainNoMatch=1 / null=2`。

```csharp
public class QueryParams
```

```csharp
var query = new QueryParams { PageIndex = state.Page + 1, PageSize = state.PageSize };
```

### 6.4 ServerData + ExcelFilter 标准模式 🔥

**布局特点：**
- MudTable 绑定 `ServerData="@LoadDataFromServer"`，列筛选通过 `_columnFilters` → `SerializeFilters()` → `FilterDescriptor` 传给后端
- 筛选上下文通过独立 `GET /api/xxx/filter-contexts` 从后端获取

- 表格 `Class` 必须使用 `mt-0 auto-table`（必选），通常叠加 `compact-table`（推荐），纯文本列少列表页可忽略
- checkbox 选择列：若实现了分组列标题栏（§6.23，`initGroupHeaders` JS），必须使用 `col-selection-th`/`col-selection-td` CSS 类；无分组标题栏的页面使用简单内联 `Style="width:40px;padding:0 4px;"` 即可

**工具栏布局**：工具栏为独立 `div.woe-toolbar` 位于 MudTable 上方（不在 `<ToolBarContent>` 内），详见 §6.33 工具栏标准布局。

**列宽设置方式**：仅表头设宽度，数据行/汇总行不设宽度，详见 §6.29 列宽绑定规则。

**代码骨架**（完整模板详见 SKILL.md）。

**LoadDataFromServer 回调要点**：
1. 首行 `_pageSize = state.PageSize;`（B22 分页行数持久化）
2. `_isFirstLoad` 标记覆盖 `state.Page` 为 `_restoredPageIndex`
3. `SerializeFilters()` 将 `_columnFilters` 转为 FilterDescriptor JSON
4. query.Filters 由 Controller 反序列化（禁止依赖 `[FromQuery]` 自动绑定）
5. 末尾调用 `SavePageStateAsync()`

**筛选陷阱（7 条）：**
1. **数据源同源**：filter-contexts 必须与显示数据同源（后处理覆盖须同样处理）
2. **后处理覆盖字段的筛选**：ApplyFilters 前单独处理，从 Filters 中 Remove
3. **布尔 EnumOptions 大小写**：`"True"`/`"False"`（大写开头）
4. **filters 独立参数**：禁止内嵌在 QueryParams 中
5. **🔥 filter-contexts key 大小写**：`GetFilterContextsAsync` 返回字典的 key **必须与前端 `ColumnDef.Key` 完全一致**（PascalCase），禁止使用全小写或其他格式。前端 `_filterContextOptions.GetValueOrDefault(col.Key)` 是**大小写敏感**的 Ordinal 匹配，大小写不一致会导致筛选下拉为空
6. **🔥 [后端] DbContext 非线程安全 — 禁止并行查询**：EF Core DbContext **非线程安全**，`GetFilterContextsAsync` 中多个 DISTINCT 查询**必须顺序 await**，禁止 `Task.WhenAll`（仅前端可用，见 §6.7）。**注意**：5 分钟静态缓存已缓解性能损耗，无需优化。
7. **🔥 LoadFilterContextsAsync 错误可见性**：前端 `LoadFilterContextsAsync` 禁止使用空 `catch { }` 静默吞异常。应记录日志或 Snackbar 提示，确保后端 `GetFilterContextsAsync` 调用失败时用户可见。API 返回 `result.Success == false` 时也应显示错误消息。

```csharp
List<SelectOption<string>>? EnumOptions { get; set; } // 枚举列的筛选选项（通过 `DisplayHelper.GetEnumFilterOptions<T>()` 从 EnumHelper 生成）
Func<object?, string?>? DisplayConverter { get; set; } // 显示转换器（§6.34）
int? GroupKey { get; set; }        // 分组编号
string? GroupName { get; set; }    // 分组名称
ColumnLevel Level { get; set; }    // 列语义层级：WorkOrder(默认无标色)/MainNo(主号级，表头青色 col-level-mainno)/Order(订单级，表头橙色 col-level-order)
string? Width { get; set; }         // 列宽数值字符串（如"120"），Razor 中需解析为数值并加 px
string? BoolTrueLabel { get; set; }  // 布尔列为 true 时显示文本（默认"是"）
string? BoolFalseLabel { get; set; } // 布尔列为 false 时显示文本（默认"否"）
```

**🔥 列层级命名与标色（ColumnDef.Level，2026-08-07 全 5 页面完成）**：主号级列 Label 加 `主号-` 前缀、订单级加 `订单-` 前缀（如 `主号-关注`/`主号-入库状态`/`订单-入库状态`）；`ColumnDef.Level` 表头标色——主号级青色（`col-level-mainno`）、订单级橙色（`col-level-order`）、工单级无标色；新增列时按字段实际语义层级设置 `Level`，禁止混用前缀/标色。

列显示偏好通过 `ColumnPrefsService` 持久化。使用 `ColumnDisplaySelect` 的页面，HeaderContent/RowTemplate 必须用 `@foreach (var col in _visibleColumns)` 动态迭代（禁止硬编码 `@if` 块）。

### 6.23 分组列标题栏 + 选择列对齐（B23）🔥

**适用范围**：列数量 ≥15 且需要按业务域分组标识时使用。列数少（<10 列）或无需分组标识的列表页**不应**实现分组标题栏。

列使用 `GroupKey`/`GroupName` 分组时，必须实现独立分组标题栏，**紧邻 MudTable 表头上方**（位于工具栏下方、表头上方）。禁止在 `<MudTh>` 中使用内联分组 badge。详见 SKILL.md 完整模板。

**页面元素固定顺序**（从上到下）：
1. 模糊搜索框（`MudGrid`）
2. 工具栏（`div.woe-toolbar`）：列显隐 + 重置 | 打印按钮 + 记录数
3. 分组标题栏（`div.col-group-header-scroll`）：紧邻 MudTable
4. MudTable（不含 `<ToolBarContent>`）

**分组标题栏生成规则**：
- `GetGroupHeaders()` 按 `GroupKey` 聚合列宽；`_totalTableWidth` 公式见下
- `OnAfterRenderAsync` 调用 `initGroupHeaders("#xxx-list-table")`，且必须包裹 try-catch 防止 JS 异常中断页面加载

**⚠️ `_totalTableWidth` 公式规则**：
- 占位宽度必须与表格实际结构精确对齐，按需包含，不可机械套用 `+40+90`：
  - **有选择列** → `+ 40`（checkbox 宽度固定 40px）
  - **无选择列** → 不加
  - **有操作列** → `+ N`（N 取操作列 `<MudTh>` 的实际 `width`，通常 90px，按需可调整如 Ncrs 用 160px）
  - **无操作列** → 不加

| 场景 | 公式 | 示例页面 |
|------|------|----------|
| 有选择列 + 有操作列 | `cols + 40 + N` | Batches(90), PurchaseOrders(90) |
| 有选择列 + 无操作列 | `cols + 40` | WorkOrderSchedules, BatchPlans, FinalInspectionPlan, OrderDemandAdjustment, QualityProcessTracking, WorkOrderExecution |
| 无选择列 + 有操作列 | `cols + N` | Ncrs(160) |
| 无选择列 + 无操作列 | `cols` | ColdRollPlans |

**选择列 40px 起始占位**：
- 含 checkbox 列的表格必须在 `GetGroupHeaders()` 最前添加 40px 空白占位，否则 JS 会将 checkbox 列宽计入首组导致偏移
- FooterContent 中亦须在 `@foreach` 前加 `<MudTd Style="width:40px;min-width:40px;max-width:40px;"></MudTd>` 占位

**操作列尾部占位**：
- 含操作按钮列的表格必须在 `GetGroupHeaders()` 末尾添加空白占位（宽度取操作列 `<MudTh>` 的实际 `width`，通常 90px），否则操作列宽度不被计入
- FooterContent 中亦须在 `@foreach` 后加对应宽度的 `<MudTd Class="col-footer-cell"></MudTd>` 占位

**checkbox 列 CSS 类**：
- 表头 `<MudTh>` 使用 `Class="col-selection-th"`
- 行 `<MudTd>` 使用 `Class="col-selection-td"`
- FooterContent `<MudTd>` 不设 CSS 类（只设 `Style` 宽度）
- 禁止省略，否则 `initGroupHeaders` 无法正确识别选择列

**表头 checkbox Value 表达式**：
- 必须判断当前页所有行是否都在 `_selectedIds` 中，而非比较 `_selectedIds.Count == _totalCount`（跨页时永远不等，导致无法取消全选）：
```razor
Value="@(_pageItems.Count > 0 && _pageItems.All(i => _selectedIds.Contains(i.WorkOrderId)))"
```

**`OnAfterRenderAsync` 标准写法**：
```csharp
protected override async Task OnAfterRenderAsync(bool firstRender)
{
    try
    {
        await JS.InvokeVoidAsync("initGroupHeaders", "#xxx-list-table");
    }
    catch { }
    // ... 可选的方向键导航
}
```

### 6.27 内存全量加载 Items 模式（B32）

**适用**：Items 模式页面（批次计划、冷轧计划、原锁计划等），数据量 <50000 条。

**核心字段**：`_allItems`（服务端全量数据）+ `_filteredItems`（筛选排序后数据）

**关键规则**：
1. `LoadDataAsync()` 全量获取数据（调用 `GetAllAsync()` 或 `PageSize=50000` 大分页）
2. `BuildFilterContextOptions()` 从 `_allItems` 内存构建筛选上下文（无服务端 `GetFilterContextsAsync`）
3. `ApplyFiltersAndSort()` 统一处理搜索/筛选/排序
4. MudTable 绑定 `Items="@_filteredItems"`（非 ServerData）
5. **内联编辑后禁止 `LoadDataAsync()` 全量重载**，改为本地更新 + `ApplyFiltersAndSort()`
6. `GetFilterValue()` 逐列映射筛选值，非可空 bool 用 `.ToString()`
7. **组合显示字段一致性**：表格列显示为多个属性拼接（如 `CategoryCode + CategoryName`）时，`GetStringValue`（筛选上下文构建）和 `GetRawPropertyValue`（打印值提取）必须使用相同的组合逻辑，禁止只取单一属性导致筛选/打印与显示不一致

### 6.28 记录类列表页审计时间列与 DataSource 显示规则（B33）🔥

**适用**：所有记录类列表页（生产记录、去油酸洗、委外、过程检验、成检到料、成品检验等）。

**规则**：
1. **DataSource 列** — 凡实体含 `DataSource` 字段的列表页，必须显示该列。
   - `FilterType = "enum"`，EnumOptions：`new("SCAN", "扫码"), new("MANUAL", "手动")`
   - RenderCell 中通过 switch 映射为中文显示
   - Service 层必须支持 `datasource` 排序和筛选上下文
2. **CreatedTime 统一不显示** — 不属于业务字段，列表页 `GetAllColumnDefs()` 中不定义此列，RenderCell/GetCellRawValue/GetCellPrintValue 中无对应 case。
3. **UpdatedTime 统一显示** — 所有记录类列表页必须在列定义末尾包含 UpdatedTime 列，RenderCell 中渲染 `yyyy-MM-dd HH:mm` 格式。

**常见违规**：遗漏 DataSource 列、CreatedTime 残留列定义或 RenderCell 死代码、缺少 UpdatedTime 列。

### 6.29 列表页表格横向滚动（B34）🔥

**机制**：
- `mud-table-container { overflow-x: auto !important; }` 内置横向滚动
- 使用 `table-layout: auto`（默认），不设 `table-layout: fixed`（fixed 会强制各列等比例分配剩余空间，导致列宽失真）
- 列数较多（超过容器宽度）时自动出现横向滚动条

**列宽绑定规则**：**仅表头设宽度，数据行不设宽度**

```razor
@* 表头：设宽度 *@
<MudTh Style="@($"width:{col.Width}px")">

@* 数据行：不设宽度（由浏览器根据列内容自动计算，与表头一致）*@
<MudTd>

@* 汇总行（可选）：不设宽度 *@
<MudTd Class="col-footer-cell">
```

> ⚠️ 常见错误：给数据行 `<MudTd>` 设置 `width/min-width/max-width`，会干扰 `table-layout: auto` 下的列宽计算，导致表头与数据列不对齐。

**要求**：
- 所有 ServerData/Items 模式的列表页 MudTable 外必须套一层 `<div id="xxx-list-table">`
- 列定义 `Width` 必须为数字字符串（如 `"120"`），表头中通过 `@($"width:{col.Width}px")` 绑定
- 禁止在表格容器上手动设置 `overflow: hidden` 截断列

### 6.30 搜索框统一规范（B36）

#### 6.30.1 模糊搜索框

**布局**：`MudGrid`/`MudItem` 布局，禁止内联样式。单搜索框 `md="12"` 全宽；搭配日期范围时搜索框 `md="6"`。

### 6.33 PDF 打印标准（B06）🔥

详见 `docs/11_打印设计.md`。**关键规则**：
- **Mode B 打印（TablePrintHelper 驱动）必须使用纯 Mode B 模式**（Mode A=自包含富布局硬编码，仅详情/报表类；Mode B=动态列表，定义见 `docs/11_打印设计.md`）：
  - 列定义完全由前端掌控（`_visibleColumns.Select(c => c.ToPrintColumnDef()).ToList()`），通过 `OrderPrintBatchRequest.Columns` / `OrderPrintAllRequest.Columns` 传递
  - 后端 Service 中禁止维护 `GetPrintColumns()` / `GetPrintValueResolvers()` / `GetFilteredPrintColumns()`
  - 需要特殊格式化的枚举/bool/decimal 字段，在 `ToPrintDict()` 中预格式化后转为 `Dictionary<string, object>` 传递
  - 不需要特殊格式化的模块可直接传 DTO（`TablePrintHelper.FormatValue` 反射自动处理枚举）
- Mode B 两种子模式：⓪ 前端准备数据（前端通过 `DisplayConverter` 或 `DisplayHelper.GetXxxText()` 将枚举转为中文后传后端） / ⓫ 后端查询数据（后端查库后通过 `EnumHelper.GetDisplayName()` 处理枚举）
- **打印中枚举字段统一通过 `EnumHelper.GetDisplayName()`** 解析。DTO 属性已是枚举类型时，`TablePrintHelper.FormatValue` 反射自动处理；dict 手动组装时调用 `EnumHelper.GetDisplayName(typeof(T), value)`
- 禁止通过 C#→JS base64 传递 PDF，使用 `fetch` + Blob URL + iframe 覆盖层
- 后端 `print-file` 端点返回 `File(pdfBytes, "application/pdf")`，不包裹 `ApiResponse<T>`
- 工具栏布局：左"列显隐+重置" | 右"打印+共X条记录"，详见 SKILL.md 完整模板

### 6.34 DisplayConverter 统一显示转换模式（B35）🔥

**目的**：解决枚举字段在列表显示/PDF 打印/筛选下拉三处重复维护中文映射的问题。

**机制**：在 `ColumnDef` 中通过 `DisplayConverter` 属性定义"原始值→中文"的映射，`RenderCell`/`ResolvePrintValue`/`BuildFilterOptionsFromData` 三处统一调用。

#### 6.34.1 列定义中设置

```csharp
new() { Key = "DeliveryState", Label = "交货状态", FilterType = "enum",
    EnumOptions = DisplayHelper.GetEnumFilterOptions<DeliveryState>(),
    DisplayConverter = v => v is DeliveryState s ? EnumHelper.GetDisplayName(s) : null }
```

- `DisplayConverter` 签名：`Func<object?, string?>`
- 入参为 DTO 属性原始值（因 §4.7 要求 DTO 使用实际枚举类型，入参为枚举而非 string），需用 `is` 模式匹配后调用 `EnumHelper.GetDisplayName()`
- ❌ 禁止 `v as string` — DTO 现为枚举类型，`v as string` 永远返回 null
- `EnumOptions` 通过 `DisplayHelper.GetEnumFilterOptions<T>()` 从 EnumHelper 自动生成，禁止硬编码
- 简单枚举（int→中文）用 switch 表达式：`v => v is int s ? s switch { 0 => "状态A", ... } : null`

#### 6.34.2 RenderCell 中使用

```csharp
case "DeliveryState":
    builder.AddContent(0, col.DisplayConverter?.Invoke(item.DeliveryState) ?? "-");
    break;
```

仅适用于**纯文本显示**的枚举列。带 MudChip/颜色标记的枚举列（如 ScheduleStage/UrgencyLevel/FlowLevel）仍保持自定义渲染，DisplayConverter 仅用于打印。

#### 6.34.3 ResolvePrintValue 中使用

```csharp
private static object ResolvePrintValue(T item, ColumnDef col)
{
    if (col.DisplayConverter != null)
        return col.DisplayConverter(GetRawPropertyValue(item, col.Key)) ?? "";

    if (col.FilterType == "boolean")
    {
        var raw = GetRawPropertyValue(item, col.Key);
        if (raw is bool b) return b ? col.BoolTrueLabel : col.BoolFalseLabel;
        return raw?.ToString() ?? "-";
    }

    return GetRawPropertyValue(item, col.Key);
}
```

调用处传入列定义而非列 key：`dict[col.Key] = ResolvePrintValue(item, col);`

#### 6.34.4 禁止行为

- ❌ 有 `DisplayConverter` 时，`ResolvePrintValue` 中仍保留该列的 switch case
- ❌ `DisplayConverter` 中处理 UI 渲染逻辑（如颜色/样式），只做值→中文文本转换
- ❌ 枚举列的 `DisplayConverter` 与 `EnumOptions.Display` 不一致（两者必须输出相同中文）

#### 6.34.5 迁移策略

1. 新页面强制使用 DisplayConverter 模式
2. 旧页面逐步迁移：列定义加 DisplayConverter → 简化 ResolvePrintValue → 简化 RenderCell

### 6.35 入库自动填充标准

适用于入库页面通过 **MudSwitch 开关按钮** 控制"自动填充"行为的场景（目前 RAW、FG、DEFECT、WIP 库使用），开关开启时字段变更自动查询后端填充，关闭时完全手动输入。

#### 6.35.1 自动填充触发时间点

自动填充在以下 **字段变更事件** 中触发（调用 `TriggerAutoFillAsync`）：

| 触发字段 | 说明 |
|---------|------|
| `InboundSource`（来源类型） | 下拉选择变更时触发 |
| `SourceOrderNo`（来源单号） | 输入变更时触发（含手动输入） |
| `SourceOrderSequence`（来源序号） | 选择变更时触发 |
| `ProductionBatchNo`（生产批号） | 输入变更时触发 |

**页面显示时间点**：页面初始化加载时不触发自动填充（仅创建空行），等待用户交互触发。

#### 6.35.2 填充前清空

每次调用 `TriggerAutoFillAsync` 执行后端查询前，必须先调用 `ClearAutoFillFields()` 清空所有自动填充字段，确保不会残留上一笔数据：

- **RAW（原料库）**：清空 G2 组字段（来源信息）
- **FG（成品库）**：清空 G2 组（来源信息）+ G3 组（规格信息）

```csharp
private void ClearAutoFillFields(InboundRowModel row)
{
    row.SourceName = "";
    row.HeatNo = "";
    row.ProductionBatchNo = "";
    row.MinLength = null;
    row.MaxLength = null;
    // ... 各库对应清空字段
}
```

#### 6.35.3 关闭自动填充时的行为

当 `_autoFillEnabled == false` 时，`TriggerAutoFillAsync` 必须在入口处立即返回，**禁止执行任何后端查询**：

```csharp
private async Task TriggerAutoFillAsync(InboundRowModel row)
{
    if (!_autoFillEnabled)
        return;
    // ... 后续查询逻辑
}
```

关闭自动填充时：
- 所有来源类型均放开（不限仅"外购"+"委外"）
- 所有字段手动输入，不做任何后端数据填充
- 提交时验证规则照常执行

#### 6.35.4 手动"获取来源信息"

无论自动填充开启或关闭，"获取来源信息"按钮始终可用，点击时独立触发 `TriggerAutoFillAsync()`，不受 `_autoFillEnabled` 开关限制。

#### 6.35.5 DEFECT（次品库）自动填充行为

次品库（DEFECT）的自动填充规则与 RAW/FG 不同：

**触发方式**：仅通过"获取来源信息"按钮手动触发，**不支持 MudSwitch 自动填充模式**（`_autoFillEnabled` 在 DEFECT 库无实际作用）。

**填充逻辑**：以 `ProductionBatchNo`（生产批号）为查询条件，从原始批次（来源为正品库的批次）反查以下字段：

| DTO 字段 | 数据来源 | 说明 |
|----------|----------|------|
| `MaterialType` | 批次 MaterialType | 保持原物料类型，不改变 |
| `PlantGrade` | 工厂牌号 | 保持原值 |
| `Specification` | 名义规格 | 保持原值 |
| `SurfaceStatus` | 表面状态 | 保持原值 |
| `HeatNo` | 炉号 | 保持原值 |
| `SourceName` | 来料单位 | 保持原值 |

**与 RAW/FG 的关键差异**：
- DEFECT 不填充 MaterialType（次品入库时物料类型通常由用户手动选择为 DefectSemi/DefectFinished 等）
- DEFECT 以 ProductionBatchNo 为主键查询，而非 InboundSource+SourceOrderNo
- DEFECT 无来源单号（SourceOrderNo）概念，该字段在次品库不可用

#### 6.35.6 WIP（在制品库）自动填充行为

在制品库（WIP）的自动填充规则与 FG 类似，以 `ProductionBatchNo` 为查询条件自动填充规格信息（实际规格/外径/壁厚/长度），不填充来源信息。WIP 的自动填充通过 MudSwitch 开关控制，与 RAW/FG 相同。

## 八、DbContext 配置

### 8.1 审计字段自动赋值

```csharp
public override async Task<int> SaveChangesAsync(CancellationToken ct = default)
{
    var entries = ChangeTracker.Entries<IAuditableEntity>();
    var currentUser = _currentUser?.GetUserName() ?? "system";
    var now = DateTimeOffset.Now;
    foreach (var entry in entries)
    {
        switch (entry.State)
        {
            case EntityState.Added:
                entry.Entity.CreatedTime = now; entry.Entity.CreatedBy = currentUser;
                entry.Entity.UpdatedTime = now; entry.Entity.UpdatedBy = currentUser;
                break;
            case EntityState.Modified:
                entry.Entity.UpdatedTime = now; entry.Entity.UpdatedBy = currentUser;
                break;
            case EntityState.Deleted: break; // 物理删除，不拦截
        }
    }
    return await base.SaveChangesAsync(ct);
}
```

> **审计机制**：`AppDbContext` 注入 `ICurrentUser` 接口（定义于 `MES.Core.Interfaces.Infrastructure`），
> 在 `MES.Api` 层通过 `CurrentUserService` 从 JWT Token 中提取用户名。
> Data/Services 层不再直接依赖 `IHttpContextAccessor`，保持分层架构纯净。

### 8.2 枚举存储

所有枚举字段使用 `HasConversion<string>()` 例外见 §4.5。

### 8.3 乐观并发

需要并发控制的实体添加 `byte[] RowVersion` + `.IsRowVersion()`。当前已实现：SalesOrder、WorkOrder、ProductionBatch、InventoryBatch。

### 8.4 读模型 RowVersion

读模型表（如 `WorkOrderExecutionSummary`）的 rowversion 仅用于该表并发控制，不得返回给前端作为业务表的 RowVersion。列表 DTO 的 RowVersion 必须来自业务表。

### 8.5 SqlTransaction 事务使用规范 🔥

`CommitAsync()` 后事务标记为已完成，其 `using` 作用域内的任何数据库操作都会抛出 `SqlTransaction completed` 异常。

**关键原则：**
1. `CommitAsync()` 后的数据库操作必须在 `using (transaction) { }` 块之外执行——这是选择作用域形式的唯一标准：
   ```csharp
   // Commit 后还有 DB 操作 → 必须显式 {} 作用域
   var transaction = await _context.Database.BeginTransactionAsync();
   using (transaction) { try { /* DB操作 */ await transaction.CommitAsync(); } catch { await transaction.RollbackAsync(); throw; } }
   // 事务已提交销毁，在此之后执行后续DB操作

   // Commit 后无后续 DB 操作 → using var 可接受（等价于显式作用域）
   using var transaction2 = await _context.Database.BeginTransactionAsync();
   /* DB操作 */
   await transaction2.CommitAsync();
   // 方法结束，using 自动释放（此时事务已提交，dispose 是空操作）
   ```
2. `CommitAsync()` 成功后若后续代码异常，**不可再调用 `RollbackAsync()`**（事务已提交，会导致另一个异常）
3. 变量声明推荐 `var transaction` + `using(transaction) { }` 显式作用域（清晰，无歧义）；若 Commit 在方法末尾，`using var` 可接受

## 十、数值与字符串格式规范

### 10.1 核心规则

| 操作 | 规则 |
|------|------|
| 显示去零 | `ToString("G29")` 去除末尾无效零（`76.00` → `76`） |
| 存储原值 | 数据库存储原始精度，不截断 |
| 计算精确 | 使用原始精度，不格式化 |
| 编辑原样 | 保持用户输入原样 |

### 10.2 数据库存储精度

| 字段 | SQL 类型 | 精度 |
|------|----------|------|
| 外径/壁厚 | decimal(18,3) | 3位 |
| 重量 | decimal(18,3) | 3位 |
| 理论重量 | decimal(18,6) | 6位 |
| 长度/米数 | decimal(18,2) | 2位 |
| 比例/百分比 | decimal(18,2) | 2位 |

### 10.3 整数显示规则（列表页）（B19）🔥

支数/米数/重量/批次数在列表页显示为整数值：
```csharp
// decimal 属性
builder.AddContent(0, ((int)item.TotalWeight).ToString());
// int 属性
builder.AddContent(0, item.TotalQuantity.ToString());
```
编辑/详情页保留原始精度（`Format="G29"`）。

### 10.4 百分比显示规则（列表页）（B20）🔥

百分比/比率列显示 1 位小数：
```csharp
builder.AddContent(0, item.Ratio > 0 ? $"{item.Ratio:F1}%" : "-");
```

### 10.5 字符串大小写规范

SQL Server 默认 **case-insensitive**（collation 大小写不敏感），但 C# 内存默认 `Ordinal` **区分大小写**。**关键分界：EF 查询（IQueryable，未物化）与内存（ToList 后）两套规则**：

#### 10.5.1 🔥 EF 查询（IQueryable）内字符串比较

EF Core 查询（LINQ-to-SQL 翻译阶段）内**禁止** `string.Equals(x, y, StringComparison.OrdinalIgnoreCase)`——该重载**不可翻译为 SQL，运行抛异常**（Expression translation error）。

| 操作 | ✅ 正确 | ❌ 错误 |
|------|---------|---------|
| EF 查询相等 | `query.Where(w => w.WorkOrderNo == workOrderNo)` | `query.Where(w => string.Equals(w.WorkOrderNo, workOrderNo, StringComparison.OrdinalIgnoreCase))` |

- SQL Server collation 大小写不敏感，`==`（`Expression.Equal`）在 SQL 层天然不区分大小写，**EF 查询内一律用 `==`**
- `==` 仅用于 **ToList/ToDictionary 之后的内存比较**（此时 SQL collation 已失效，需 `OrdinalIgnoreCase`）
- EF 查询内的 `Contains`/`StartsWith` 可用（QueryableExtensions 的 `BuildStringContains`/`BuildStartsWith` 即走此路），但**不可带 `StringComparison` 参数**

#### 10.5.2 内存比较（ToList 后）

业务编码的集合比较必须指定 `StringComparer.OrdinalIgnoreCase`：

| 操作 | ✅ 正确 | ❌ 错误 |
|------|---------|---------|
| HashSet.Contains | `list.ToHashSet(StringComparer.OrdinalIgnoreCase)` | `list.ToHashSet()` |
| Dictionary 查找 | `dict.ToDictionary(x => x.Key, StringComparer.OrdinalIgnoreCase)` | `dict.ToDictionary(x => x.Key)` |
| LINQ 内存比较 | `string.Equals(x, y, StringComparison.OrdinalIgnoreCase)` | `x == y` |

**必须忽略大小写**：工单号、订单号、批次号、主号、其他业务编码字符串
**不需要**：int、枚举值、bool 标志
