## 三、分层约束规则

### 3.1 跨层调用规则

- Controller → 只能调用 Service，不能直接操作 DbContext
- Service → 可以调用 DbContext 和其他 Service
- 禁止跨层调用

### 3.2 分层职责表

| 层级 | 职责 | 禁止行为 |
|------|------|----------|
| Controller | 接收请求、参数验证、调用Service、返回响应 | 编写业务逻辑 |
| Service | 核心业务逻辑、事务管理 | 直接返回 Entity（用 DTO） |
| Data | 数据库操作、实体定义 | 包含业务逻辑 |

### 3.3 DTO 投影原则（列表页查询）🔥

列表页 Service 的 `GetPagedAsync`，**无论是否有跨表字段，一律优先使用 DTO 投影模式**（`IQueryable<Dto>` 而非 `IQueryable<Entity>`），原因：

1. **`ApplyFilters`/`ApplySort` 需要 DTO 属性名** — 反射基于 DTO 属性匹配 `FilterDescriptor.Field`/`SortBy`，若用实体模式 + `select new Dto` 在投影后，筛选排序条件会因属性名不一致而失效
2. **跨表字段统一处理** — 有跨表字段时，LINQ `join` + `select new Dto` 是唯一正确方式
3. **性能与可维护性** — 投影仅取所需字段，避免整表加载

```csharp
// ✅ 正确：DTO 投影，ApplyFilters/ApplySort 反射 DTO 属性，跨表字段统一处理
var query = from p in _context.PurchaseOrders
            select new PurchaseOrderDto {
                Id = p.Id,
                OrderNo = p.OrderNo,
                // 不含跨表字段也使用投影
            };
// 无跨表字段时也可用 Select() 链式投影：
var query = _context.PurchaseOrders
    .Select(p => new PurchaseOrderDto {
        Id = p.Id,
        OrderNo = p.OrderNo,
    });
query = query.ApplyFilters(queryParams.Filters);
query = query.ApplySort(queryParams.SortBy, queryParams.IsDescending);

// ❌ 禁止（即使无跨表字段）：
var query = _context.PurchaseOrders.AsQueryable();  // IQueryable<Entity> 而非 DTO
query = query.ApplyFilters(...);  // 反射 Entity 属性而非 DTO 属性
query = query.Select(e => new PurchaseOrderDto { ... });  // 后置投影
```

**禁止的实体查询模式**：
```csharp
// ❌ 错误：实体 IQueryable + crossTableFields HashSet + 后置填充
var query = _context.PurchaseOrders.AsQueryable();
if (crossTableFields.Contains("workOrderNo"))
    query = query.Where(...);  // 手动子查询
// ... 手动判断跨表字段、30 分支 sort switch
// ... 后置填充 WorkOrder 字段
```

**分层边界**：
- 投影能处理的（聚合/子查询/条件逻辑/字符串处理）→ 直接在投影中完成
- 投影翻译不了的（调 Service/复杂业务规则）→ Hybrid 模式：先投影查询，再内存补充
- Create/Update 操作仍使用实体查询模式（DTO 投影只读）

## 四、实体设计规则

### 4.1 审计字段

每实体必须继承 `BaseEntity`（含 Id/CreatedTime/CreatedBy/UpdatedTime/UpdatedBy）。使用 bigint 主键的实体可不继承但需实现 `IAuditableEntity` 接口。

### 4.2 字段与主键

- 主键：`Id`（自增INT），禁用业务字段做主键
- 外键：`{主表名}Id`（如 `CustomerId`）
- 时间字段以 `Time` 结尾，状态字段用枚举

### 4.3 状态枚举定义

```csharp
public enum SalesOrderStatus { Pending = 0, Confirmed = 1, Cancelled = 2 }
```

### 4.4 物理删除

所有实体统一物理删除（`_context.Remove(entity)`）。

### 4.5 枚举存储规范

- 所有枚举字段存储为字符串（`HasConversion<string>()`）
- 例外（存储为 int）：`WorkOrder.MaterialPlanStatus`、`WorkOrderExecutionSummary` 中 10 个状态字段
- **EF Core 查询**：对 `HasConversion<string>()` 枚举字段筛选时，禁止 `.ToString()` 字符串比对，应 `TryParse` 为枚举后直接比对枚举值

### 4.6 枚举中文显示规范 🔥

枚举字段在页面/打印显示时必须中文，统一通过 **`EnumHelper.GetDisplayName()`**（后端/打印）或 **`DisplayHelper.GetXxxText()`**（前端）转换，两者最终委托同一 `EnumHelper` 映射源：

```csharp
// 单一事实源：EnumHelper 中注册（MES.Core.Helpers.EnumHelper）
Register<DeliveryState>(("SolutionAnnealedAndPickled", "固溶酸洗"), ...);

// 前端委托：DisplayHelper → EnumHelper（MES.Blazor.Helpers.DisplayHelper）
public static string GetDeliveryStateText(DeliveryState status) => EnumHelper.GetDisplayName(status);
public static string GetDeliveryStateText(string? status) => EnumHelper.GetDisplayName<DeliveryState>(status);

// 列定义 DisplayConverter（优先方式，§6.34）
new() { Key = "DeliveryState", FilterType = "enum",
    DisplayConverter = v => v is DeliveryState s ? EnumHelper.GetDisplayName(s) : null }
```

**规则**：
- 禁止 `.ToString()` 直出枚举（Razor 的 `@item.Status` 或 builder.AddContent 输出）
- 新增枚举时必须在 `EnumHelper` 中通过 `Register<T>()` 注册中文映射（`_ => value.ToString()` 回退等于显示英文，违规）
- `DisplayHelper.GetXxxText()` 只做委托，禁止 switch/case 硬编码中文（历史遗留代码已完成清理）
- **此约束适用于全代码库**：任何枚举/整数字段转中文显示的场合（包括页面私有方法、ResolvePrintValue 内联 switch、GetCellDisplayText 等），均须委托 `DisplayHelper` 或 `ColumnDef.DisplayConverter`，禁止手写 switch 映射
- 筛选下拉框通过 `DisplayHelper.GetEnumFilterOptions<T>()` 从 EnumHelper 生成，确保筛选/显示/打印三处中文一致（见 §6.26）

### 4.7 DTO 枚举属性类型规范 🔥

DTO 中代表枚举值的属性 **必须使用实际的枚举类型**，禁止使用 `string`。这是从根源杜绝枚举显示问题的核心架构决策：

```csharp
// ✅ 正确：DTO 使用实际枚举类型
public class EquipmentListDto
{
    public LifecycleStatus LifecycleStatus { get; set; }
    public UsageType UsageType { get; set; }
    public RunningStatus RunningStatus { get; set; }
}

// ❌ 禁止：DTO 使用 string 存储枚举值
public class EquipmentListDto
{
    public string LifecycleStatus { get; set; }  // ❌ 编译不检查，每处显示/打印需手动转换，遗漏即显示英文
}
```

**收益**（DTO 用枚举类型后自动获得的保障）：

| 场景 | string DTO | enum DTO |
|------|-----------|---------|
| 打印 `TablePrintHelper.FormatValue` | 反射见 string 不处理，原样输出 | 反射见 IsEnum，自动调用 `EnumHelper.GetDisplayName()` |
| DataExchange 导入导出 | 需声明 `EnumType` 元数据 | EnumHelper 自动识别 |
| Service 投影 | `e.Status.ToString()` → 运行时异常 | `e.Status` → 编译期校验 |
| 前端编辑器 | 人肉记得调用 GetDisplayName | 编译器要求匹配类型 |

**实现细则**：

1. **DTO 属性使用枚举类型**，可空字段用 `EnumType?`，非可空字段设默认值：
   ```csharp
   public LifecycleStatus LifecycleStatus { get; set; } = LifecycleStatus.Active;
   public DeliveryState? DeliveryState { get; set; }  // 可选字段用可空
   ```

2. **Service LINQ 投影**：实体已是枚举时直接赋值，实体存 string 时用 `Enum.Parse<T>()`（加 null/empty 守卫）：
   ```csharp
   // 实体存 enum → 直接赋值
   Status = e.Status,
   // 实体存 string → Enum.Parse + 守卫
   LengthStatus = string.IsNullOrEmpty(e.LengthStatus) ? null : Enum.Parse<LengthStatus>(e.LengthStatus),
   ```

3. **Entity → string DB 写入**：实体属性仍按 §4.5 存 `string`，Service 在 `CreateAsync`/`UpdateAsync` 中通过 `.ToString()` 转为实体 string：
   ```csharp
   entity.LifecycleStatus = request.LifecycleStatus.ToString();
   ```

4. **JSON 序列化**：API 全局已配置 `JsonStringEnumConverter`，枚举序列化为字符串名而非数字，API 契约不变。

5. **前端绑定**：
   - `MudSelect` 泛型参数 `T` 使用实际枚举类型（`MudSelect<LifecycleStatus>`），`MudSelectItem.Value` 使用枚举成员
   - 字符串比较 `status == "Fixed"` → 枚举比较 `status == LengthStatus.Fixed`
   - `string.IsNullOrWhiteSpace(status)` → 可空枚举 `status == null`

### 4.8 冗余快照规范（写时冗余，读时分场景）🔥

| 场景 | 规则 |
|------|------|
| 写入时 | 从来源表读取当前值写入目标表冗余字段 |
| 列表页（ServerData 分页） | **禁止 JOIN 来源表**，直接读冗余字段 |
| 详情页/编辑页 | 如需要最新值可 JOIN 来源表；如"历史定格"则直接读 |
| 历史定格字段 | 注释标注 `// 历史定格，无需溯源`，写入后永不 JOIN |

### 4.9 批次跟踪字段刷新规范

跟踪字段（`CurrentExecDate`/`CurrentGroupName`/`CurrentSectionName` 等）系统自动计算，禁止手动编辑。`IsForceCompleted = true` 时跳过自动刷新。`UpdateProductionBatchRequest` 不得包含跟踪字段。

```csharp

{
    var result = await _service.GetByIdAsync(id);
    return Ok(ApiResponse<OrderDto>.Ok(result));
}
```

|------|------|------|
| 查询列表 | GET | GET /api/order/list |
| 查询单个 | GET | GET /api/order/{id} |
| 创建 | POST | POST /api/order |
| 更新 | PUT | PUT /api/order/{id} |
| 删除 | DELETE | DELETE /api/order/{id} |

### 5.3 分页查询规范

```csharp
public class QueryParams
{
    public int PageIndex { get; set; } = 1;
    public int PageSize { get; set; } = 20;
    public string? Keyword { get; set; }
    public string? SortBy { get; set; }
    public bool IsDescending { get; set; } = true;
    public List<FilterDescriptor>? Filters { get; set; }
    public int Skip => (PageIndex - 1) * PageSize;
}
```
**SortBy 默认**：`SortBy = null` 时默认按 `CreatedTime` 降序。

**⚠️ PageIndex 前后端转换**：后端 `QueryParams.PageIndex` 为 **1-based**（`Skip = (PageIndex - 1) * PageSize`）。MudBlazor `ServerData` 回调的 `state.Page` 为 **0-based**，前端 `LoadDataFromServer` 中必须转换：

```csharp
var query = new QueryParams { PageIndex = state.Page + 1, PageSize = state.PageSize };
```

**FilterDescriptor**（动态筛选）：
```csharp
public class FilterDescriptor
{
    public string Field { get; set; } = "";
    public string Operator { get; set; } = "contains";  // 多选须显式设为 "in"
    public List<string> Values { get; set; } = new();
}
```

**PagedResult**：
```csharp
public class PagedResult<T>
{
    public List<T> Items { get; set; }
    public int TotalCount { get; set; }
    public int PageIndex { get; set; }
    public int PageSize { get; set; }
    // TotalPages / HasPreviousPage / HasNextPage 为计算属性
}
```

### 5.4 安全要求

- 所有 API 加 `[Authorize]`（Controller 类级别），登录/登出/刷新用 `[AllowAnonymous]`
- 敏感接口加角色限制

### 5.5 必需后端端点（列表页）

```csharp
// 分页列表（filters 必须独立 [FromQuery] 参数，禁止依赖 QueryParams 自动绑定）
[HttpGet("list")]
public async Task<ActionResult<ApiResponse<PagedResult<XxxDto>>>> GetPaged(
    [FromQuery] QueryParams query, [FromQuery] string? filters = null)
{
    if (!string.IsNullOrEmpty(filters))
        query.Filters = JsonSerializer.Deserialize<List<FilterDescriptor>>(
            filters, new JsonSerializerOptions { PropertyNameCaseInsensitive = true });
    return Ok(ApiResponse<PagedResult<XxxDto>>.Ok(await _service.GetPagedAsync(query)));
}

// 筛选上下文
[HttpGet("filter-contexts")]
public async Task<ActionResult<ApiResponse<Dictionary<string, List<string>>>>> GetFilterContexts()
{
    return Ok(ApiResponse<Dictionary<string, List<string>>>.Ok(await _service.GetFilterContextsAsync()));
}
```

### 6.2 页面统一布局

- 列表页加 `Class="mt-4 pl-0"`，详情/创建页加 `Class="mt-4"`

### 6.3 标准列表页模式选择

| 模式 | 适用场景 | 核心特征 |
|------|----------|----------|
| **ServerData + ExcelFilter**（§6.4） | 标准业务列表页（数据量大/持续增长） | 服务端分页/排序/筛选，`ServerData="LoadDataFromServer"` |
| **Items 模式**（§6.27） | Items 模式页面（数据量可控 <50000 条） | 内存全量加载，`Items="@_filteredItems"`，客户端筛选排序 |

### 6.4 ServerData + ExcelFilter 标准模式 🔥

**布局特点：**
- MudTable 绑定 `ServerData="@LoadDataFromServer"`，列筛选通过 `_columnFilters` → `SerializeFilters()` → `FilterDescriptor` 传给后端
- 筛选上下文通过独立 `GET /api/xxx/filter-contexts` 从后端获取
- 排序由列名点击 `ToggleSort(col.Key)` 触发 `ReloadServerData()`
- 分页汇总行（有支数/米数/重量/批次数等数值列时必须实现，纯文本列列表页可省略）
- 表格 `Class` 必须使用 `mt-0 auto-table`（必选），通常叠加 `compact-table`（推荐），纯文本列少列表页可忽略
- checkbox 选择列：若实现了分组列标题栏（§6.23，`initGroupHeaders` JS），必须使用 `col-selection-th`/`col-selection-td` CSS 类；无分组标题栏的页面使用简单内联 `Style="width:40px;padding:0 4px;"` 即可

**工具栏布局**：工具栏为独立 `div.woe-toolbar` 位于 MudTable 上方（不在 `<ToolBarContent>` 内），详见 §6.33 工具栏标准布局。

**列宽设置方式**：仅表头设宽度，数据行/汇总行不设宽度，详见 §6.29 列宽绑定规则。

**代码骨架**（完整模板详见 SKILL.md）。

**LoadDataFromServer 回调要点**：
1. 首行 `_pageSize = state.PageSize;`（B22 分页行数持久化）
2. `_isFirstLoad` 标记覆盖 `state.Page` 为 `_restoredPageIndex`
3. `SerializeFilters()` 将 `_columnFilters` 转为 FilterDescriptor JSON
4. query.Filters 由 Controller 反序列化（禁止依赖 `[FromQuery]` 自动绑定）
5. 末尾调用 `SavePageStateAsync()`

**筛选陷阱（9 条）：**
1. **枚举列排除**：`GetFilterContextsAsync` 禁止返回有固定 `EnumOptions` 的枚举列
2. **数据源同源**：filter-contexts 必须与显示数据同源（后处理覆盖须同样处理）
3. **后处理覆盖字段的筛选**：ApplyFilters 前单独处理，从 Filters 中 Remove
4. **布尔 EnumOptions 大小写**：`"True"`/`"False"`（大写开头）
5. **filters 独立参数**：禁止内嵌在 QueryParams 中
6. **独立 MudSelect 移除**：列筛选统一由列头 ExcelFilter 提供
7. **🔥 filter-contexts key 大小写**：`GetFilterContextsAsync` 返回字典的 key **必须与前端 `ColumnDef.Key` 完全一致**（PascalCase），禁止使用全小写或其他格式。前端 `_filterContextOptions.GetValueOrDefault(col.Key)` 是**大小写敏感**的 Ordinal 匹配，大小写不一致会导致筛选下拉为空
8. **🔥 [后端] DbContext 非线程安全 — 禁止并行查询**：EF Core DbContext **非线程安全**，`GetFilterContextsAsync` 中多个 DISTINCT 查询**必须顺序 await**，禁止 `Task.WhenAll`（仅前端可用，见 §6.7）。**注意**：5 分钟静态缓存已缓解性能损耗，无需优化。
9. **🔥 LoadFilterContextsAsync 错误可见性**：前端 `LoadFilterContextsAsync` 禁止使用空 `catch { }` 静默吞异常。应记录日志或 Snackbar 提示，确保后端 `GetFilterContextsAsync` 调用失败时用户可见。API 返回 `result.Success == false` 时也应显示错误消息。

### 6.21 页面状态持久化（PageStateService）🔥

使用 localStorage 通过 `PageStateService` 持久化。**关键字段**：
```csharp
private int _restoredPageIndex;
private int _currentPageIndex;
private bool _isFirstLoad = true;
private string sortColumn = "...";
private bool sortDescending = false;
private string _searchKeyword = "";
private Dictionary<string, HashSet<string>> _columnFilters = new();
private Dictionary<string, List<ExcelFilterOption>> _filterContextOptions = new();
```

**OnInitializedAsync** 中恢复状态（**注意**：不在此处调用 `ReloadServerData`——组件未完成首次渲染，`table` ref 为 null。改为通过 `_isFirstLoad` + `_restoredPageIndex` 在首次 `LoadDataFromServer` 回调中自动恢复）：
```csharp
var savedState = await PageState.LoadAsync("page_key");
if (savedState != null)
{
    /* 恢复 sortColumn/sortDescending/_searchKeyword/_columnFilters/_pageSize */
    _isFirstLoad = true;
    _restoredPageIndex = savedState.PageIndex; // 由首次 ServerData 回调消费
}
await LoadFilterContextsAsync();
```

**SavePageStateAsync** 保存所有交互状态，在 ToggleSort/OnSearchChanged/OnColumnFilterChanged/LoadDataFromServer 末尾调用。

**Items 模式** 无需 `_restoredPageIndex`/`_isFirstLoad`，`_currentPageIndex` 仍需要（0-base）。

### 6.23 分组列标题栏 + 选择列对齐（B23）🔥

**适用范围**：列数量 ≥15 且需要按业务域分组标识时使用。列数少（<10 列）或无需分组标识的列表页**不应**实现分组标题栏。

列使用 `GroupKey`/`GroupName` 分组时，必须实现独立分组标题栏，**紧邻 MudTable 表头上方**（位于工具栏下方、表头上方）。禁止在 `<MudTh>` 中使用内联分组 badge。详见 SKILL.md 完整模板。

**页面元素固定顺序**（从上到下）：
1. 模糊搜索框（`MudGrid`）
2. 工具栏（`div.woe-toolbar`）：列显隐 + 重置 | 打印按钮 + 记录数
3. 分组标题栏（`div.col-group-header-scroll`）：紧邻 MudTable
4. MudTable（不含 `<ToolBarContent>`）

**分组标题栏生成规则**：
- `GetGroupHeaders()` 按 `GroupKey` 聚合列宽；`_totalTableWidth` 公式见下
- `OnAfterRenderAsync` 调用 `initGroupHeaders("#xxx-list-table")`，且必须包裹 try-catch 防止 JS 异常中断页面加载

**⚠️ `_totalTableWidth` 公式规则**：
- 占位宽度必须与表格实际结构精确对齐，按需包含，不可机械套用 `+40+90`：
  - **有选择列** → `+ 40`（checkbox 宽度固定 40px）
  - **无选择列** → 不加
  - **有操作列** → `+ N`（N 取操作列 `<MudTh>` 的实际 `width`，通常 90px，按需可调整如 Ncrs 用 160px）
  - **无操作列** → 不加

| 场景 | 公式 | 示例页面 |
|------|------|----------|
| 有选择列 + 有操作列 | `cols + 40 + N` | Batches(90), PurchaseOrders(90) |
| 有选择列 + 无操作列 | `cols + 40` | WorkOrderSchedules, BatchPlans, FinalInspectionPlan, OrderDemandAdjustment, QualityProcessTracking, WorkOrderExecution |
| 无选择列 + 有操作列 | `cols + N` | Ncrs(160) |
| 无选择列 + 无操作列 | `cols` | ColdRollPlans |

**选择列 40px 起始占位**：
- 含 checkbox 列的表格必须在 `GetGroupHeaders()` 最前添加 40px 空白占位，否则 JS 会将 checkbox 列宽计入首组导致偏移
- FooterContent 中亦须在 `@foreach` 前加 `<MudTd Style="width:40px;min-width:40px;max-width:40px;"></MudTd>` 占位

**操作列尾部占位**：
- 含操作按钮列的表格必须在 `GetGroupHeaders()` 末尾添加空白占位（宽度取操作列 `<MudTh>` 的实际 `width`，通常 90px），否则操作列宽度不被计入
- FooterContent 中亦须在 `@foreach` 后加对应宽度的 `<MudTd Class="col-footer-cell"></MudTd>` 占位

**checkbox 列 CSS 类**：
- 表头 `<MudTh>` 使用 `Class="col-selection-th"`
- 行 `<MudTd>` 使用 `Class="col-selection-td"`
- FooterContent `<MudTd>` 不设 CSS 类（只设 `Style` 宽度）
- 禁止省略，否则 `initGroupHeaders` 无法正确识别选择列

**表头 checkbox Value 表达式**：
- 必须判断当前页所有行是否都在 `_selectedIds` 中，而非比较 `_selectedIds.Count == _totalCount`（跨页时永远不等，导致无法取消全选）：
```razor
Value="@(_pageItems.Count > 0 && _pageItems.All(i => _selectedIds.Contains(i.WorkOrderId)))"
```

**`OnAfterRenderAsync` 标准写法**：
```csharp
protected override async Task OnAfterRenderAsync(bool firstRender)
{
    try
    {
        await JS.InvokeVoidAsync("initGroupHeaders", "#xxx-list-table");
    }
    catch { }
    // ... 可选的方向键导航
}
```

### 6.27 内存全量加载 Items 模式（B32）

**适用**：Items 模式页面（批次计划、冷轧计划、原锁计划等），数据量 <50000 条。

**核心字段**：`_allItems`（服务端全量数据）+ `_filteredItems`（筛选排序后数据）

**关键规则**：
1. `LoadDataAsync()` 全量获取数据（调用 `GetAllAsync()` 或 `PageSize=50000` 大分页）
2. `BuildFilterContextOptions()` 从 `_allItems` 内存构建筛选上下文（无服务端 `GetFilterContextsAsync`）
3. `ApplyFiltersAndSort()` 统一处理搜索/筛选/排序
4. MudTable 绑定 `Items="@_filteredItems"`（非 ServerData）
5. **内联编辑后禁止 `LoadDataAsync()` 全量重载**，改为本地更新 + `ApplyFiltersAndSort()`
6. `GetFilterValue()` 逐列映射筛选值，非可空 bool 用 `.ToString()`
7. **组合显示字段一致性**：表格列显示为多个属性拼接（如 `CategoryCode + CategoryName`）时，`GetStringValue`（筛选上下文构建）和 `GetRawPropertyValue`（打印值提取）必须使用相同的组合逻辑，禁止只取单一属性导致筛选/打印与显示不一致

### 6.28 记录类列表页审计时间列与 DataSource 显示规则（B33）🔥

**适用**：所有记录类列表页（生产记录、去油酸洗、委外、过程检验、成检到料、成品检验等）。

**规则**：
1. **DataSource 列** — 凡实体含 `DataSource` 字段的列表页，必须显示该列。
   - `FilterType = "enum"`，EnumOptions：`new("SCAN", "扫码"), new("MANUAL", "手动")`
   - RenderCell 中通过 switch 映射为中文显示
   - Service 层必须支持 `datasource` 排序和筛选上下文
2. **CreatedTime 统一不显示** — 不属于业务字段，列表页 `GetAllColumnDefs()` 中不定义此列，RenderCell/GetCellRawValue/GetCellPrintValue 中无对应 case。
3. **UpdatedTime 统一显示** — 所有记录类列表页必须在列定义末尾包含 UpdatedTime 列，RenderCell 中渲染 `yyyy-MM-dd HH:mm` 格式。

**常见违规**：遗漏 DataSource 列、CreatedTime 残留列定义或 RenderCell 死代码、缺少 UpdatedTime 列。

### 6.29 列表页表格横向滚动（B34）🔥

**机制**：
- `mud-table-container { overflow-x: auto !important; }` 内置横向滚动
- 使用 `table-layout: auto`（默认），不设 `table-layout: fixed`（fixed 会强制各列等比例分配剩余空间，导致列宽失真）
- 列数较多（超过容器宽度）时自动出现横向滚动条

**列宽绑定规则**：**仅表头设宽度，数据行不设宽度**

```razor
@* 表头：设宽度 *@
<MudTh Style="@($"width:{col.Width}px")">

@* 数据行：不设宽度（由浏览器根据列内容自动计算，与表头一致）*@
<MudTd>

@* 汇总行（可选）：不设宽度 *@
<MudTd Class="col-footer-cell">
```

> ⚠️ 常见错误：给数据行 `<MudTd>` 设置 `width/min-width/max-width`，会干扰 `table-layout: auto` 下的列宽计算，导致表头与数据列不对齐。

**要求**：
- 所有 ServerData/Items 模式的列表页 MudTable 外必须套一层 `<div id="xxx-list-table">`
- 列定义 `Width` 必须为数字字符串（如 `"120"`），表头中通过 `@($"width:{col.Width}px")` 绑定
- 禁止在表格容器上手动设置 `overflow: hidden` 截断列

### 6.30 搜索框统一规范（B36）

所有列表页的搜索栏在 `MudGrid` 布局中，模糊搜索框为必选项，日期范围搜索根据业务需求可选。

#### 6.30.1 模糊搜索框

**布局**：`MudGrid`/`MudItem` 布局，禁止内联样式。单搜索框 `md="12"` 全宽；搭配日期范围时搜索框 `md="6"`。

**例外**：工具栏区域搜索框（如子表筛选）可维持原有布局。

#### 6.30.2 日期范围搜索（理化检测等按日期筛选的场景）

### 6.33 PDF 打印标准（B06）🔥

详见 `docs/11_打印设计.md`。**关键规则**：
- **A 类打印（TablePrintHelper 驱动）必须使用纯 A 类模式**：
  - 列定义完全由前端掌控（`_visibleColumns.Select(c => c.ToPrintColumnDef()).ToList()`），通过 `OrderPrintBatchRequest.Columns` / `OrderPrintAllRequest.Columns` 传递
  - 后端 Service 中禁止维护 `GetPrintColumns()` / `GetPrintValueResolvers()` / `GetFilteredPrintColumns()`
  - 需要特殊格式化的枚举/bool/decimal 字段，在 `ToPrintDict()` 中预格式化后转为 `Dictionary<string, object>` 传递
  - 不需要特殊格式化的模块可直接传 DTO（`TablePrintHelper.FormatValue` 反射自动处理枚举）
- 两种子模式：⓪ 前端准备数据（前端通过 `DisplayConverter` 或 `DisplayHelper.GetXxxText()` 将枚举转为中文后传后端） / ⓫ 后端查询数据（后端查库后通过 `EnumHelper.GetDisplayName()` 处理枚举）
- **打印中枚举字段统一通过 `EnumHelper.GetDisplayName()`** 解析。DTO 属性已是枚举类型时，`TablePrintHelper.FormatValue` 反射自动处理；dict 手动组装时调用 `EnumHelper.GetDisplayName(typeof(T), value)`
- 禁止通过 C#→JS base64 传递 PDF，使用 `fetch` + Blob URL + iframe 覆盖层
- 后端 `print-file` 端点返回 `File(pdfBytes, "application/pdf")`，不包裹 `ApiResponse<T>`
- 工具栏布局：左"列显隐+重置" | 右"打印+共X条记录"，详见 SKILL.md 完整模板

### 6.34 DisplayConverter 统一显示转换模式（B35）🔥

**目的**：解决枚举字段在列表显示/PDF 打印/筛选下拉三处重复维护中文映射的问题。

**机制**：在 `ColumnDef` 中通过 `DisplayConverter` 属性定义"原始值→中文"的映射，`RenderCell`/`ResolvePrintValue`/`BuildFilterOptionsFromData` 三处统一调用。

#### 6.34.1 列定义中设置

```csharp
new() { Key = "DeliveryState", Label = "交货状态", FilterType = "enum",
    EnumOptions = DisplayHelper.GetEnumFilterOptions<DeliveryState>(),
    DisplayConverter = v => v is DeliveryState s ? EnumHelper.GetDisplayName(s) : null }
```

- `DisplayConverter` 签名：`Func<object?, string?>`
- 入参为 DTO 属性原始值（因 §4.7 要求 DTO 使用实际枚举类型，入参为枚举而非 string），需用 `is` 模式匹配后调用 `EnumHelper.GetDisplayName()`
- ❌ 禁止 `v as string` — DTO 现为枚举类型，`v as string` 永远返回 null
- `EnumOptions` 通过 `DisplayHelper.GetEnumFilterOptions<T>()` 从 EnumHelper 自动生成，禁止硬编码
- 简单枚举（int→中文）用 switch 表达式：`v => v is int s ? s switch { 0 => "状态A", ... } : null`

#### 6.34.2 RenderCell 中使用

```csharp
case "DeliveryState":
    builder.AddContent(0, col.DisplayConverter?.Invoke(item.DeliveryState) ?? "-");
    break;
```

仅适用于**纯文本显示**的枚举列。带 MudChip/颜色标记的枚举列（如 ScheduleStage/UrgencyLevel/FlowLevel）仍保持自定义渲染，DisplayConverter 仅用于打印。

#### 6.34.3 ResolvePrintValue 中使用

```csharp
private static object ResolvePrintValue(T item, ColumnDef col)
{
    if (col.DisplayConverter != null)
        return col.DisplayConverter(GetRawPropertyValue(item, col.Key)) ?? "";

    if (col.FilterType == "boolean")
    {
        var raw = GetRawPropertyValue(item, col.Key);
        if (raw is bool b) return b ? col.BoolTrueLabel : col.BoolFalseLabel;
        return raw?.ToString() ?? "-";
    }

    return GetRawPropertyValue(item, col.Key);
}
```

调用处传入列定义而非列 key：`dict[col.Key] = ResolvePrintValue(item, col);`

#### 6.34.4 禁止行为

- ❌ 有 `DisplayConverter` 时，`ResolvePrintValue` 中仍保留该列的 switch case
- ❌ `DisplayConverter` 中处理 UI 渲染逻辑（如颜色/样式），只做值→中文文本转换
- ❌ 枚举列的 `DisplayConverter` 与 `EnumOptions.Display` 不一致（两者必须输出相同中文）

#### 6.34.5 迁移策略

1. 新页面强制使用 DisplayConverter 模式
2. 旧页面逐步迁移：列定义加 DisplayConverter → 简化 ResolvePrintValue → 简化 RenderCell

### 6.35 入库自动填充标准

适用于入库页面通过 **MudSwitch 开关按钮** 控制"自动填充"行为的场景（目前 RAW、FG、DEFECT、WIP 库使用），开关开启时字段变更自动查询后端填充，关闭时完全手动输入。

#### 6.35.1 自动填充触发时间点

自动填充在以下 **字段变更事件** 中触发（调用 `TriggerAutoFillAsync`）：

| 触发字段 | 说明 |
|---------|------|
| `InboundSource`（来源类型） | 下拉选择变更时触发 |
| `SourceOrderNo`（来源单号） | 输入变更时触发（含手动输入） |
| `SourceOrderSequence`（来源序号） | 选择变更时触发 |
| `ProductionBatchNo`（生产批号） | 输入变更时触发 |

**页面显示时间点**：页面初始化加载时不触发自动填充（仅创建空行），等待用户交互触发。

#### 6.35.2 填充前清空

每次调用 `TriggerAutoFillAsync` 执行后端查询前，必须先调用 `ClearAutoFillFields()` 清空所有自动填充字段，确保不会残留上一笔数据：

- **RAW（原料库）**：清空 G2 组字段（来源信息）
- **FG（成品库）**：清空 G2 组（来源信息）+ G3 组（规格信息）

```csharp
private void ClearAutoFillFields(InboundRowModel row)
{
    row.SourceName = "";
    row.HeatNo = "";
    row.ProductionBatchNo = "";
    row.MinLength = null;
    row.MaxLength = null;
    // ... 各库对应清空字段
}
```

#### 6.35.3 关闭自动填充时的行为

当 `_autoFillEnabled == false` 时，`TriggerAutoFillAsync` 必须在入口处立即返回，**禁止执行任何后端查询**：

```csharp
private async Task TriggerAutoFillAsync(InboundRowModel row)
{
    if (!_autoFillEnabled)
        return;
    // ... 后续查询逻辑
}
```

关闭自动填充时：
- 所有来源类型均放开（不限仅"外购"+"委外"）
- 所有字段手动输入，不做任何后端数据填充
- 提交时验证规则照常执行

#### 6.35.4 手动"获取来源信息"

无论自动填充开启或关闭，"获取来源信息"按钮始终可用，点击时独立触发 `TriggerAutoFillAsync()`，不受 `_autoFillEnabled` 开关限制。

#### 6.35.5 DEFECT（次品库）自动填充行为

次品库（DEFECT）的自动填充规则与 RAW/FG 不同：

**触发方式**：仅通过"获取来源信息"按钮手动触发，**不支持 MudSwitch 自动填充模式**（`_autoFillEnabled` 在 DEFECT 库无实际作用）。

**填充逻辑**：以 `ProductionBatchNo`（生产批号）为查询条件，从原始批次（来源为正品库的批次）反查以下字段：

| DTO 字段 | 数据来源 | 说明 |
|----------|----------|------|
| `MaterialType` | 批次 MaterialType | 保持原物料类型，不改变 |
| `PlantGrade` | 工厂牌号 | 保持原值 |
| `Specification` | 名义规格 | 保持原值 |
| `SurfaceStatus` | 表面状态 | 保持原值 |
| `HeatNo` | 炉号 | 保持原值 |
| `SourceName` | 来料单位 | 保持原值 |

**与 RAW/FG 的关键差异**：
- DEFECT 不填充 MaterialType（次品入库时物料类型通常由用户手动选择为 DefectSemi/DefectFinished 等）
- DEFECT 以 ProductionBatchNo 为主键查询，而非 InboundSource+SourceOrderNo
- DEFECT 无来源单号（SourceOrderNo）概念，该字段在次品库不可用

#### 6.35.6 WIP（在制品库）自动填充行为

在制品库（WIP）的自动填充规则与 FG 类似，以 `ProductionBatchNo` 为查询条件自动填充规格信息（实际规格/外径/壁厚/长度），不填充来源信息。WIP 的自动填充通过 MudSwitch 开关控制，与 RAW/FG 相同。

## 八、DbContext 配置

### 8.1 审计字段自动赋值

```csharp
public override async Task<int> SaveChangesAsync(CancellationToken ct = default)
{
    var entries = ChangeTracker.Entries<IAuditableEntity>();
    var currentUser = _currentUser?.GetUserName() ?? "system";
    var now = DateTimeOffset.Now;
    foreach (var entry in entries)
    {
        switch (entry.State)
        {
            case EntityState.Added:
                entry.Entity.CreatedTime = now; entry.Entity.CreatedBy = currentUser;
                entry.Entity.UpdatedTime = now; entry.Entity.UpdatedBy = currentUser;
                break;
            case EntityState.Modified:
                entry.Entity.UpdatedTime = now; entry.Entity.UpdatedBy = currentUser;
                break;
            case EntityState.Deleted: break; // 物理删除，不拦截
        }
    }
    return await base.SaveChangesAsync(ct);
}
```

> **审计机制**：`AppDbContext` 注入 `ICurrentUser` 接口（定义于 `MES.Core.Interfaces.Infrastructure`），
> 在 `MES.Api` 层通过 `CurrentUserService` 从 JWT Token 中提取用户名。
> Data/Services 层不再直接依赖 `IHttpContextAccessor`，保持分层架构纯净。

### 8.2 枚举存储

所有枚举字段使用 `HasConversion<string>()` 例外见 §4.5。

### 8.3 乐观并发

需要并发控制的实体添加 `byte[] RowVersion` + `.IsRowVersion()`。当前已实现：SalesOrder、WorkOrder。

### 8.4 读模型 RowVersion

读模型表（如 `WorkOrderExecutionSummary`）的 rowversion 仅用于该表并发控制，不得返回给前端作为业务表的 RowVersion。列表 DTO 的 RowVersion 必须来自业务表。

### 8.5 SqlTransaction 事务使用规范 🔥

`CommitAsync()` 后事务标记为已完成，其 `using` 作用域内的任何数据库操作都会抛出 `SqlTransaction completed` 异常。

**关键原则：**
1. `CommitAsync()` 后的数据库操作必须在 `using (transaction) { }` 块之外执行——这是选择作用域形式的唯一标准：
   ```csharp
   // Commit 后还有 DB 操作 → 必须显式 {} 作用域
   var transaction = await _context.Database.BeginTransactionAsync();
   using (transaction) { try { /* DB操作 */ await transaction.CommitAsync(); } catch { await transaction.RollbackAsync(); throw; } }
   // 事务已提交销毁，在此之后执行后续DB操作

   // Commit 后无后续 DB 操作 → using var 可接受（等价于显式作用域）
   using var transaction2 = await _context.Database.BeginTransactionAsync();
   /* DB操作 */
   await transaction2.CommitAsync();
   // 方法结束，using 自动释放（此时事务已提交，dispose 是空操作）
   ```
2. `CommitAsync()` 成功后若后续代码异常，**不可再调用 `RollbackAsync()`**（事务已提交，会导致另一个异常）
3. 变量声明推荐 `var transaction` + `using(transaction) { }` 显式作用域（清晰，无歧义）；若 Commit 在方法末尾，`using var` 可接受

## 九、禁止事项

### 9.1 代码层面

- ❌ 禁止在 Controller 中编写业务逻辑
- ❌ 禁止使用 Task.Result / .Wait() 同步等待
- ❌ 禁止直接返回 Entity 给前端
- ❌ 禁止在实体中编写业务方法（贫血模型）
- ❌ 禁止硬编码连接字符串和密钥
- ❌ **禁止在业务计算中使用硬编码数值常量**（工量天数、阈值、比率等必须通过配置表动态读取）
- ❌ 禁止魔法字符串表示状态（用枚举）
- ❌ **禁止依赖 `[FromQuery]` 自动绑定 `QueryParams.Filters`**（`List<FilterDescriptor>` 无法反序列化，filters 必须独立参数手动反序列化）

### 9.2 数据库层面

- ❌ 禁止使用业务字段作为主键
- ❌ 禁止表名使用复数形式
- ❌ 禁止忘记添加审计字段

### 9.3 安全层面

- ❌ 禁止记录密码、Token 到日志

### 9.4 前端层面

- ❌ 禁止卡片式布局代替表格
- ❌ 禁止弹窗编辑表格（用内联编辑）
- ❌ 禁止 `MudDatePicker`（用 `MudTextField<string>` + `Placeholder="yyyy-MM-dd"`）
- ❌ 禁止 `alert()`（用 Snackbar）
- ❌ 禁止搜索框 `Placeholder`（日期字段例外）
- ❌ 禁止搜索框 `Label` 超出 30 字或无关描述（建议简洁描述搜索范围，如 `Label="模糊搜索 - 单号/物料分类"`）
- ❌ 禁止列表页外部独立 `MudSelect` 状态下拉框（由 ExcelFilter 替代）
- ❌ 禁止 ExcelFilter 提供排序功能（排序由列名点击完成）
- ❌ 禁止后端 `GetFilterContextsAsync` 返回有固定 `EnumOptions` 的枚举列
- ❌ 禁止 `GetCellDisplayText()` 用于列筛选（必须用 `GetCellRawValue()`）
- ❌ 禁止 ServerData 模式缺 `_isFirstLoad`/`_restoredPageIndex` 页码恢复
- ❌ 禁止列表页缺少分页（RowsPerPage + MudTablePager 必配）
- ❌ 禁止在未核实数据库实际值的情况下编造 `EnumOptions` 值
- ❌ 禁止 `MudSelect<int?>` + `Clearable`（改用 `T="int"`）
- ❌ 禁止 `_ = Handler()` fire-and-forget（MudSwitch 必须 `async v => await`）
- ❌ 禁止 `GetCellRawValue` 中 enum 属性不加 `.ToString()`
- ❌ 禁止 `GetStringValue`/`GetRawPropertyValue` 中组合显示字段只取单一属性（须与表格渲染逻辑一致）
- ❌ **禁止 DTO 中使用 `string` 存储枚举值** — DTO 枚举属性必须使用实际枚举类型（见 §4.7）。例外：Record 类 DTO 中数据库字段为纯字符串且无对应枚举定义的字段（如 `DataSource`、`InboundSource`）
- ❌ **禁止 `MudSelect T="string"` 绑定枚举字段** — 必须使用 `T="EnumType"`（如 `MudSelect<LifecycleStatus>`），`MudSelectItem.Value` 使用枚举成员表达式 `Value="@(EnumType.Value)"`

### 9.5 架构层面

- ❌ **禁止 Service 层通过 DbContext 直写跨模块表** — 跨模块写入必须通过目标模块的 Service 接口（如 `IInventoryService`），禁止 `_context.InventoryBatches.Remove()` 绕过业务规则
- ❌ **禁止 Service 层直查跨模块表进行业务决策** — 跨模块读取必须通过目标模块的 Service 接口。例外：纯展示性查询（无需业务规则的读操作）可通过 DbContext 直查，但需加 `// CROSS-MODULE` 注释标记
- ❌ **禁止硬编码 `MudSelectItem` 枚举选项** — 必须使用 `@foreach (var val in Enum.GetValues<T>())` 动态生成全部枚举选项。例外：仓库模块页面可硬编码筛选子集

### 10.3 整数显示规则（列表页）（B19）🔥

```csharp
builder.AddContent(0, item.TotalQuantity.ToString());
```
编辑/详情页保留原始精度（`Format="G29"`）。

### 10.4 百分比显示规则（列表页）（B20）🔥

百分比/比率列显示 1 位小数：
```csharp
builder.AddContent(0, item.Ratio > 0 ? $"{item.Ratio:F1}%" : "-");
```

### 10.5 字符串大小写规范

SQL Server 默认 **case-insensitive**，但 C# 内存默认 `Ordinal` **区分大小写**。从 SQL 查询到内存后，业务编码的集合比较必须指定 `StringComparer.OrdinalIgnoreCase`：

| 操作 | ✅ 正确 | ❌ 错误 |
|------|---------|---------|
| HashSet.Contains | `list.ToHashSet(StringComparer.OrdinalIgnoreCase)` | `list.ToHashSet()` |
| Dictionary 查找 | `dict.ToDictionary(x => x.Key, StringComparer.OrdinalIgnoreCase)` | `dict.ToDictionary(x => x.Key)` |
| LINQ 内存比较 | `string.Equals(x, y, StringComparison.OrdinalIgnoreCase)` | `x == y` |

**必须忽略大小写**：工单号、订单号、批次号、其他业务编码字符串
**不需要**：int、枚举值、bool 标志

## 十一、基础设施与配置规范

### 11.1 角色常量

角色定义在 `MES.Shared/Constants/Roles.cs`：`Roles.Admin` / `Roles.Directors.{Module}` / `Roles.Staffs.{Module}`。计划排程（Scheduling）复用 `WorkOrder` 角色。

### 11.2 认证

JWT Bearer Token + RefreshToken，有效期 8 小时。RBAC 17 角色（1 Admin + 8 主任 + 8 员工）。

### 11.3 ConfigParameter 业务参数配置

**适用**：替代简单 decimal 类型硬编码常量（阈值、比率、系数、默认值等）。

**实体**（EAV 模式）：`ConfigParameter`（Category / ParamKey / ParamValue / Remark），唯一索引 `(Category, ParamKey)`。

**使用模式**：依赖注入 `IConfigParameterService` + `IMemoryCache`，5 分钟 TTL（代码模板详见 SKILL.md）。

**规则**：
- **禁止使用 `Dictionary<string, Dictionary<string, decimal>>` 实例字段缓存**（永不失效，配置变更后仍返回旧值）
- 不适用于有独立业务字段的结构化参数（如工量天数多列联合唯一约束，应使用独立表）
