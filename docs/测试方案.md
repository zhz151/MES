# 测试方案

**版本：V1.2**
**目标：上线前全面自动化检查 + 少量人工验收**
**最后更新：2026-08-09**

---

## 一、分层策略

```
                   高风险 / 高回报                     低风险
             ┌──────────────────────────────────────────────┐
  自动化     │  P0 单元测试 + 编译期可发现（Mock 测试、组件误用）│
             │  P1 运行期通断（API 端点、页面加载）          │
             │  P2 规范符合度（布局、样式、命名）             │
             ├──────────────────────────────────────────────┤
  半自动化   │  P3 数据一致性（枚举、格式交叉验证）           │
             │  P4 关键路径 E2E（跨页面业务流程）             │
             ├──────────────────────────────────────────────┤
  人工       │  P5 业务规则验证、权限矩阵、排版验收、UAT     │
             └──────────────────────────────────────────────┘
```

**原则**：
- 自动化覆盖 80% 的常规问题，人工聚焦 20% 的复杂逻辑
- P0-P1 必须有脚本，P2-P4 逐步补充，P5 只列清单
- 每个类别对应规范附录 A 中的一个或多个检查项

## 六、一键全面测试

项目基本完成后，执行以下两条命令即可覆盖所有自动化项：

```bash
# 第 1 步：Mock 单元测试（无需启动服务，~2min）
dotnet test MES.Tests

# 第 2 步：集成 + E2E 测试（需先启动 API + Blazor，~10min）
node playwright-tests/validate-all.mjs --all
```

> 第 2 步前提：`MES.Api` 和 `MES.Blazor` 已在运行中。
