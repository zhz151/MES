# 测试方案

> 版本：V2.0（2026-09-04）
> 目标/状态：MES.Tests（xUnit + EF InMemory）自动化回归为现行测试主体；构建 + 受影响模块定向单测为日常验证底线。
> 上次实质变更（V2.0）：对齐 2026-09-03 验证力度定格，以 MES.Tests 现行体系为核心重写；删除陈旧测试体系描述与内联跑批计数注记，playwright 真库 E2E / 一键全面测试降为历史遗留。

---

## 一、现行测试体系

现行自动化测试主体 = MES.Tests（xUnit + EF InMemory），覆盖 Service / Controller / Component / Core（常量·Helpers）四层；EF 以内存库注入，不依赖真库。

- 规模：187 个测试文件（MES.Tests/**/*Tests.cs，2026-09-04 清点）。
- 全量用例 0 失败（最近一次全量实测 2026-09-03：3675 用例通过；其后新增用例按模块定向单测，未全量重跑）。
- 近期新增覆盖集中在工资结算：生产计件类别两表模型（PieceRateProductionCategoryServiceTests、PieceRateCategoryImportServiceTests）、成检计件类别（PieceRateFinalInspectionCategoryServiceTests、PieceRateFinalInspectionCategoryImportServiceTests）、产量/成检结算采集（PieceRateCollectorTests）、金额口径（PieceRateAmountHelperTests）、请求映射（ProductionMatchRequestMapperTests、FinalInspectionMatchRequestMapperTests）；另含数据工具（DataExchangeServiceTests、DataExchangeEnumRoundTripTests）、数值边界与计算（OrderServiceNumericTests，10 用例）。
- 文档点名/举例的测试类均已核实存在于 MES.Tests。

### 验证力度（硬约束，2026-09-03 定格）

- 每次改动仅 dotnet build MES.Api（秒级）+ 受影响模块定向单测（如 DataExchangeServiceTests 单个类，十余秒）。
- 禁止自动起服务下载 xlsx、禁止真库 E2E 仪式（ps1/解包解析多轮往返）、禁止 playwright / 全量 dotnet test / build --no-incremental 作为例行门禁。
- 真库增量核验一律走 SQL 直查存量形态（快路径）；仅用户明确点名要求时才上重验证。

## 二、测试分类沿革（P0-P5 历史框架）

早期分层框架（P0-P5）与对应 playwright 脚本已随 2026-09-03 验证力度定格转为历史遗留：playwright-tests/ 下 API 通断 / 页面烟测 / CRUD / 认证 / E2E 脚本仍在仓库，供参考与定向排查，但不再作为例行提交仪式；其运行期真库断言被「build + MES.Tests 定向单测 + SQL 直查」取代。

| 层级 | 原意 | 现行归属 |
|------|------|---------|
| P0 | Mock 单元测试 + 编译期可发现 | MES.Tests（现行，见 §一） |
| P1 | 运行期 API 通断 / 页面烟测 | playwright 冻结，不再作例行门禁 |
| P2 | 规范符合度静态扫描 | 同 P1，冻结 |
| P3 | 数据一致性交叉验证 | 描述已删除；真库口径改 SQL 直查 |
| P4 | 关键路径 E2E | 同 P1，冻结 |
| P5 | 人工验收（权限/业务/打印/UAT） | 仍适用，见 §三 |
