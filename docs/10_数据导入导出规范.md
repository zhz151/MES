# 数据导入导出规范

**版本**：V2.3
**最后更新**：2026-07-26

> 本文件从 `04_开发规范.md` §16 独立拆分而来，内容与之同步维护。

---

数据导入导出服务位于 `MES.Services/DataExchange/DataExchangeService.cs`，使用 EPPlus 库操作 Excel，仅管理员可导入，所有认证用户可导出。

## 注册表结构

所有支持导入导出的实体在 `DataExchangeService.Registry` 字典中注册，每个实体通过 `EntityDef` 定义：

| EntityDef 参数 | 类型 | 说明 |
|---------------|------|------|
| `displayName` | string | 显示名称（用于导出页签） |
| `sheetName` | string | Excel 工作表名 |
| `type` | Type | 对应实体类（typeof） |
| `batch` | int | 导入批次（仅用于分组，实际顺序由 EntityOrder 控制） |
| `keyColumn` | string? | 业务主键属性名（如 "BatchNo"、"OrderNo"），影响重复检测 |
| `columns` | List\<ColumnDef\> | 列定义列表 |
| `compositeKeyColumns` | string[]? | 复合主键属性名数组（如 Material 的 MaterialCategory/PlantGrade/Specification） |

## ColumnDef 参数

| ColumnDef 参数 | 类型 | 说明 |
|---------------|------|------|
| `Header` | string | Excel 表头名（中文字段名） |
| `Property` | string? | 实体属性名（null 表示仅用于 FK 解析，不直接写入实体） |
| `Type` | Type? | 数据类型（缺省为 string） |
| `isRequired` | bool | 是否必填（导出模板中标记红色） |
| `isEnum` | bool | 是否为枚举类型（导出时输出中文名，导入时自动解析） |
| `isSystem` | bool | 是否系统管理字段（系统自动编码如 SupplierCode，或系统计算的跟踪字段如 ValidInputQuestion，导入时跳过写入） |
| `valueConverter` | Func\<string, object\>? | 值转换器（主要用于 bool：`v => v == "是"`） |
| `IsFkColumn` | bool | 是否为外键列（导入时 FK 解析用） |
| `FkEntityKey` | string? | 引用的实体 Registry 键名 |
| `FkLookupProperty` | string? | 引用实体的查询属性（如 "CustomerCode"、"OrderNumber"） |
| `FkTargetProperty` | string? | 本实体的 FK 目标属性（如 "CustomerId"、"SalesOrderId"） |
| `FkRequiresJoin` | bool | FK 是否为复合键（仅用于 OrderItem：SalesOrderNo+Sequence → OrderItemId） |

## EntityOrder 依赖顺序

导入顺序必须满足 **父表先于子表** 的依赖关系，当前顺序如下：

```
Warehouse → StandardGradeMapping → CustomerProfile → SupplierProfile
    → FurnaceRegistration → ChemicalComposition → ChemicalValidationRule → Ncr
    → SalesOrder
    → OrderItem → ProductRequirement
    → WorkOrder → OrderDemandAdjustment → Material
    → PurchaseOrder → SubcontractOrder → SubcontractReturnItem → ProductionBatch
    → ProcessGroup → ProductionRecord → SectionOutsource → OutsourceRecovery → ProductionBatchInventory → MaterialReceiveCheck → ProcessInspection → FinalInspection
    → ChemicalAnalysis → HardnessTest → GrainSizeTest → PittingCorrosionTest → IntergranularCorrosionTest → TensileTest → MetallographicTest → FlatteningTest → FlaringTest
    → PicklingInRecord → PicklingOutRecord → BatchOperationLog → InventoryBatch → OutboundRecord
    → Equipment → RepairOrder → MaintenanceOrder → InspectionRecord
    → InventoryPlan → PurchaseSemiPlan → PurchaseFinishedPlan → RoundBarPiercingPlan → InProcessReworkPlan
    → SemiPlanProcessGroup → InventoryPlanProcessGroup → PiercingPlanProcessGroup → InProcessReworkPlanProcessGroup
    → Workstation → Employee → ConfigParameter
    → StandardRegister → StandardRegisterItem → GradeChemicalComposition → GradePhysicalProperty → StandardInspectionRequirement → SubStandardQuickView
    → StandardWorkDay → StandardWorkDayDeliveryState → DailyOutputEstimate → DailyProductionCapacity → SectionFlowCategorySetting → SectionFlowCategoryItem
```

**核心规则：** `BuildFkCacheAsync` 在导入前查询数据库中已存在的父表记录。如果父表数据还未入库，FK 解析阶段会抛出异常。因此不可跳序导入。

## KeyColumn 与重复检测

`KeyColumn` 决定了导入时的重复检测行为：

| 场景 | GetRowKey 返回值 | 重复检测 | 行为 |
|------|-----------------|---------|------|
| KeyColumn 有值 | 返回业务主键值 | 可通过 existingCache 检测 | `skip` 模式跳过；`overwrite` 模式更新 |
| KeyColumn=null + CompositeKeyColumns | 返回组合键值 | 同上 | 同上 |
| KeyColumn=null + 无 CompositeKeyColumns | **返回 null** | **无法检测**→ 总是 INSERT | 如数据库有数据则唯一约束冲突 |

## 唯一约束处理（重要）

当实体满足以下**全部**条件时，必须在 `ImportAsync` 中添加"先删后插"特殊处理：

1. **KeyColumn = null**（无法检测重复）
2. **CompositKeyColumns = null**（同上）
3. **数据库中有唯一约束**（如 `UK_ProcessGroup_Seq`）

**已识别的实体及处理位置**（在导入主循环之前执行）：

| 实体 | 唯一索引 | 清理规则 | 代码特征 |
|------|---------|---------|---------|
| ProcessGroup | UK_ProcessGroup_Seq (ProductionBatchId, SequenceNumber) | 删除关联批次下所有旧工序组 | `if (entityKey == "ProcessGroup")` |
| OrderItem | UK_OrderItem_Sequence_Active (SalesOrderId, Sequence) | 删除关联订单下所有旧项次 | `if (entityKey == "OrderItem")` |
| ProductRequirement | UK_ProductRequirement_OrderItemId (OrderItemId) | 删除关联项次下所有旧技术要求 | `if (entityKey == "ProductRequirement")` |
| SubcontractReturnItem | UK_ReturnItem_Seq (SubcontractOrderId, Sequence) | 删除关联委外单下所有旧明细项 | `if (entityKey == "SubcontractReturnItem")` |

**注意事项：**
- ProcessGroup 按 ProductionBatchId 清理；OrderItem 按 SalesOrderId 清理；SubcontractReturnItem 按 SubcontractOrderId 清理；ProductRequirement 按 OrderItemId 清理
- 清理在 FK 禁用后、主循环插入前执行，使用 `RemoveRange` + 立即 `SaveChangesAsync`
- ProductRequirement 的 FK 需要 `FkRequiresJoin`，使用 `"{SalesOrderNo}|{Sequence}"` 复合键解析 OrderItemId

**添加新实体时的检查清单：**
```
□ 在 Registry 中添加 EntityDef
□ 在 EntityOrder 中按依赖顺序添加
□ 检查 KeyColumn 是否能唯一标识行（有则设置）
□ 如 KeyColumn=null → 检查数据库有无唯一约束
□ 有唯一约束 → 在 ImportAsync 中添加先删后插特殊处理
□ 确认表头与实体属性名正确对应
□ 运行测试确认（Registry_包含所有N个实体 + ExportAsync_所有实体_无数据时不报错）
```

## 导入策略

`ImportAsync(entityKey, fileData, strategy, userName)` 中的 `strategy` 参数：

| 策略值 | 语义 | 行为 |
|--------|------|------|
| `"skip"` | 新增导入 | 有 KeyColumn 时匹配到已有 → 跳过；无 KeyColumn → 始终 INSERT（依赖唯一约束处理） |
| `"overwrite"` | 覆盖导入 | 有 KeyColumn 时匹配到已有 → UPDATE；未匹配 → INSERT |

**注意：** 覆盖模式是 **upsert（更新+插入）**，不是"删全部重建"。

## FK 约束处理流程

导入事务的完整生命周期：

```
1. BeginTransactionAsync
2. NOCHECK CONSTRAINT ALL（禁用所有外键约束）
3. 唯一约束实体特殊处理（Delete 旧数据）
4. 逐行 ImportRowAsync（含 FK 值解析）
5. SaveChangesAsync（批量提交到数据库）
6. WITH CHECK CHECK CONSTRAINT ALL（启用并校验外键约束）
7. 校验失败 → Rollback；成功 → Commit
```

**FK 解析失败场景：**
- Excel 中的引用值（如客户编码、工单号）在数据库中不存在 → 该行抛异常（计入 FailedCount）
- 批量保存后约束校验失败（如引用了不存在的数据）→ 整个事务回滚

## 导出行为

- `ExportAsync(entityKey)`：查询全表数据，根据 ColumnDef 构建列，解析 FK 显示值，生成 Excel 文件
- `GenerateTemplateAsync(entityKey, withSample)`：生成空模板（表头+可选示例数据行）
- FK 显示值通过 `BuildFkReverseCacheForExportAsync` 将 FK ID 反查回业务主键值
- 枚举类型导出为中文显示值（通过 `GetEnumDisplayName` 反射）

## 添加新实体的完整步骤

1. **在 Registry 中添加定义**（参照已有同类实体）
2. **在 EntityOrder 中添加**（按依赖顺序）
3. **检查唯一约束**（如 KeyColumn=null 且有唯一索引 → 添加特殊处理）
4. **更新测试**：`Registry_包含所有N个实体` 中的计数（当前 68 个实体）
5. **运行测试验证**：所有 DataExchangeServiceTests 通过
