## 一、现有能力总览

当前项目覆盖钢管行业 MES 的完整业务链：

```
订单进来 → 生成工单 → 排程安排 → 批次生产 → 扫码报工 → 检验 → 入库 → 出库
  ✅        ✅         ✅          ✅         ✅         ✅      ✅      ✅
```

| 已实现领域 | 说明 |
|---|---|
| 销售订单管理 | 客户、订单、项次、变更通知、产品需求 |
| 生产标准管理 | 标准维护、牌号映射、工艺参数、标准号检验项要求 |
| 工单管理 | 工单生成、关联、执行、物料/成品/库存/返工/穿孔/在产改制计划 |
| 批次管理 | 批次创建、编辑、跟踪、出入库、操作日志 |
| 批次排程计划 | BatchPlans/ColdRollPlans/FinalInspectionPlan/PlanOverview 等 6 个页面（工段待产量/工段流转分析/段落流转分析三个查询页面已从菜单栏移除） |
| 质量管理 | 化学成分、验证规则、过程检验、成品检验、检验记录、炉号登记、NCR 不合格品闭环（评审/处置/跟踪完整流程） |
| 仓库管理 | 入库、出库、库存、库存计划、出入库历史 |
| 设备管理 | 设备档案、维修工单、保养工单、扫码报修、扫码维修（两步流程+多人协作） |
| 采购/委外 | 采购订单、委外订单、工序外协、供应商档案（物料档案主档已删除） |
| 生产记录 | 生产过程记录（含固溶温度/保温时间/断切倍数）、数据源跟踪 |
| 定尺管控 | 定尺工单联通视图、定尺切割长度匹配（CutLengthMatchType FullMatch/MainNoMatch，生产记录/成品检验/成品入库）、主号/次号工单号规则 |

| 认证授权 | JWT 认证、刷新令牌、角色管理（43 角色 RBAC，14 主菜单 × 三档 + Admin） |
| 配置化 | ConfigParameter EAV 模式 + StandardWorkDay 配置表 + Employee 员工管理 |
| PWA 移动端 | 响应式布局、离线页面、Service Worker 缓存策略 |

## 二、与商业 MES 的核心差异

### 2.1 商业 MES 的典型构成

商业 MES（西门子 Opcenter、鼎捷、用友等）一般包含：

```
核心层（必备）
  ├─ 订单/工单/批次管理
  ├─ 质量管理
  ├─ 仓库管理
  ├─ 设备管理
  ├─ 报表系统
  └─ 质量实验室（理化检测）

扩展层（加分项）
  ├─ APS 高级排程（有限产能算法 + 甘特图）
  ├─ SCADA/IoT 集成（设备数据自动采集）
  ├─ SPC 统计过程控制（控制图 + Cp/Cpk）
  ├─ 模具/工装寿命管理
  ├─ 计件工资统计
  ├─ 能源管理
  ├─ 多租户/多工厂
  └─ 国际化
```

## 三、当前系统的优势

| 优势 | 说明 |
|------|------|
| **架构整洁** | 三层分离 + DTO 映射 + 贫血模型，分层清晰，扩展成本低 |
| **前端交互好** | MudBlazor 内联编辑 + 列显隐 + 列头筛选，体验接近商用 |
| **配置化程度高** | ConfigParameter EAV 模式覆盖 16 类业务参数，替代 50+ 处硬编码 |
| **排程可视化丰富** | 6 个 Scheduling 可路由页面（工单总览 PlanOverview/原锁计划/工单排程/冷轧计划/批次计划/成检计划，另有工段产能负荷组件 WorkOrderLoadOverview），覆盖产能负荷与工段状态等多维度（工段待产量/工段流转分析/段落流转分析三个查询页面已从菜单栏移除） |
| **PWA 移动端** | 响应式布局 + 扫码报工 + 离线页面，车间可用手机/PDA 操作 |
| **权限体系完整** | RBAC 43 角色（14 主菜单 × 三档 + Admin）+ JWT + RefreshToken |
| **模块边界清晰** | Service/页面按业务上下文分目录，无循环依赖 |
| **代码规范严谨** | 3000+ 行开发规范，自动化检查，一致性高 |
| **项目规模成熟** | 143 个 Blazor 页面、90 个 Service 接口、79 个 Controller、88 个实体，覆盖完整业务链 |
| **定尺管控精细** | 定尺切割长度匹配（CutLengthMatchType FullMatch/MainNoMatch）区分本工单号与同主号其他次号的定尺长度，补料尾批/返整批跨次号流转可识别，三模块（生产记录/成品检验/成品入库）联动 |
| **关注粒度主号级** | 读模型「主号关注」（ScheduleStage 五档）全主号级上卷，同主号多工单状态一致判定；「主号计划性」「主号入库状态四档（含超额）」配套 |
| **显示层配置化** | 枚举/字典显示参数化（EnumDisplayDefinition 41 枚举 / DictValueDefinition 8 字典配置表驱动）+ int 档位统一出口（IntStatusDisplayHelper），显示名/排序/隐藏可管理员配置，替代 50+ 处散落 switch |
| **扫码体系完善** | 扫码报工（8 种报工类型）+ 扫码报修（设备故障快速报修）+ 扫码维修（两步流程+多人协作），覆盖生产和设备两大场景 |
| **NCR 闭环完整** | 不合格品报告含评审/处置/跟踪完整流程，G1-G5 五段式表单 |

## 四、当前系统的不足

### 4.1 功能层面

| 不足 | 影响 | 难度 | 建议时机 |
|------|------|------|---------|
| **计件工资统计** | 扫码报工已覆盖 8 种类型，酸洗出缸已预留冗余字段，数据已具备但未计算工人工资 | 低 | 二期 |
| **物料追溯链** | 原料→在制→成品可追溯但不直观，缺少可视化图谱 | 低 | 二期 |
| **模具/工装管理** | 钢管行业模具寿命管理是刚需，缺少寿命追踪和更换提醒 | 中 | 三期 |

### 4.2 技术层面

| 不足 | 影响 | 难度 | 建议时机 |
|------|------|------|---------|
| **无统一缓存** | 频繁读的字典数据每次都查数据库 | 低 | 日常优化 |
| **读模型性能** | ✅ **已优化** — 全量重建已改为增量触发刷新（V2.7 完全 await 化），仅刷新受影响的工单/记录 | 中 | 已优化 |
| **通知单一** | 只有站内通知，无企业微信/钉钉推送 | 低 | 二期 |

## 六、加分项（非必需，仅作备注）

以下功能是商业 MES 的常见卖点，但中小钢管厂实际需求不大，作为技术储备记录：

| 功能 | 投入 | 适用场景 |
|------|------|---------|
| **APS 高级排程** | 算法选型 + 6个月+ 产能数据积累 | 多品种大批量混产时才有明显收益 |
| **SCADA/IoT 集成** | 硬件改造 + 边缘网关 + 时序库 | 设备具备数据接口且自动化程度高时 |
| **SPC 统计过程控制** | 控制图算法 + 规则引擎 | 质检仪器直连或有大量连续检测数据时 |
| **多租户/多工厂** | TenantId 隔离 + 架构调整 | 业务扩展到多厂区时 |
| **国际化** | IStringLocalizer + resx | 有海外工厂或海外客户时 |

## 七、总结

```
当前状态：核心业务链完整，可以支撑工厂日常生产管理
            ↓
最大短板：计件工资统计（理化检测/质保书均已补齐）
            ↓
加分项：APS/SCADA/SPC/多租户 → 当前不需要追
            ↓
立即可做：
  ① 理化检测页面 —— ✅ 已完成
  ② 质量证明书   —— ✅ 已完成
  ③ 计件工资     —— 数据已有，补计算+页面，约 3 天
```

**一句话：核心骨架已经搭好，下一阶段重点不是盲目加功能，而是让数据产生价值（报表深化/计件工资）。** 扫码体系（8 种报工类型 + 报修 + 维修）已经打通最后一米，首页 2×2 看板已落地，理化检测 9 模块、质量证明书、标准号检验项要求均已实现，补齐上述短板后就是一个能真正替代商业 MES 的实用系统。
