# 扫码执行设计

**版本：V4.5**
**最后更新：2026-09-05**

---

## 一、架构总览

扫码执行模块是一套**移动端扫码报工系统**，通过工位二维码确定报工类型，逐步骤引导完成生产/检验/委外等记录的快速录入。

### 1.1 核心概念

| 概念 | 说明 |
|------|------|
| **工位（Workstation）** | 物理工位的二维码编码，绑定 `(工段 + 设备 + 报工类型)`，扫码即确定后续流程 |
| **员工（Employee）** | 操作人/检验员的工号二维码，支持多人同时扫码 |
| **批次（ProductionBatch）** | 扫码解析批次号，获取批次信息和工序组列表 |
| **工序组（ProcessGroup）** | 批次下的工序集合，按工序名+工段匹配确定报工归属 |
| **报工类型（ReportType）** | 工位属性，决定整个流程的模板和数据提交目标 |

### 1.2 交互流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 步骤1     │ →  │ 步骤2     │ →  │ 步骤3     │ →  │ 步骤4     │
│ 扫工位码   │    │ 扫员工码   │    │ 扫批次号   │    │ 填表单     │
│ (确定类型) │    │ (多人可选) │    │ (解析数据) │    │ (提交)     │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                       │
                                                  ┌────┘
                                                  ▼
                                          ┌──────────────┐
                                          │ 提交并继续     │
                                          │ / 提交并完成   │
                                          └──────────────┘
```

### 1.3 8 种报工类型

| ReportType | 中文名 | 步骤3模式 | 提交目标 |
|-----------|--------|----------|---------|
| `ProductionRecord` | 普通报工 | Pattern A：选工序组 | `POST api/production-record/record` |
| `PicklingInRecord` | 酸洗入缸 | Pattern A：选工序组 | `POST api/pickling` |
| `PicklingOutRecord` | 酸洗出缸 | Pattern B：选入缸记录 | `POST api/pickling/out-record` |
| `SectionOutsource` | 工段委外 | Pattern A：选工序组 | `POST api/section-outsource` |
| `OutsourceRecovery` | 委外回收 | Pattern B：选委外记录 | `POST api/section-outsource/recovery` |
| `ProcessInspection` | 过程检验 | Pattern A：选工序组 | `POST api/process-inspection/batch` |
| `MaterialReceiveCheck` | 成检到料 | Pattern C：确认到料（多检验工序组批→选组） | `POST api/material-receive-check` |
| `FinalInspection` | 成品检验 | Pattern D：工位绑定直击 | `POST api/final-inspection` |

### 1.4 三种步骤3模式

| 模式 | 有工序组？ | 有选择列表？ | 适用类型 |
|------|-----------|------------|---------|
| **Pattern A** | ✅ 扫批次→过滤工序组→用户选择 | 工序组列表 | ProductionRecord, PicklingInRecord, SectionOutsource, ProcessInspection |
| **Pattern B** | ❌ 扫批次→加载关联待处理记录→用户选择 | 待处理记录列表 | PicklingOutRecord（入缸记录）, OutsourceRecovery（委外记录） |
| **Pattern C** | 大多直入表单；批次含**多道检验工序组**（Inspection 有值且规格匹配）时需先指定到料组 | 检验工序组（仅多检验组批） | MaterialReceiveCheck |
| **Pattern D** | ❌ 扫批次→（工位绑定检验项目直击）→进入表单 | 无选择 | FinalInspection |

### 1.5 基础配置

| 配置 | 说明 |
|------|------|
| **工位管理（Workstations）** | 工位码绑定（工段 + 设备 + 报工类型），扫码后自动确定目标记录表和表单模板 |
| **员工管理（Employees）** | 员工基础信息（工号/姓名/部门/岗位），扫码识别操作人/检验员，支持多人协作 |

## 二、扫码报工与检验（ScanExecute）

### 2.1 路由与权限

| 项目 | 值 |
|------|-----|
| 页面路由 | `@page "/mobile-report"` |
| 授权角色 | `[Authorize]`（所有登录用户，页面/API 均无角色细分） |
| 返回导航 | 返回批次列表 `/batches` |

### 2.2 条码/二维码格式

```
{批次号}                     → 纯批次号
{批次号}|{工序组ID}          → 带工序组ID（兼容旧标签，直接跳过工序组选择）
```

示例：`BATCH-001` 或 `BATCH-001|5`

### 2.3 扫码技术实现

**文件：** `wwwroot/js/scanner.js`

| 技术 | 说明 |
|------|------|
| 首选解码 | **BarcodeDetector API**（浏览器原生，Chrome/Edge）— 支持 QR码 + Code128/EAN-13/UPC/Code39 等条码 |
| 回退解码 | **jsQR**（CDN加载）— 仅二维码 |
| 摄像头 | `navigator.mediaDevices.getUserMedia`，`facingMode: 'environment'` |
| 扫码方式 | 逐帧扫描 `requestAnimationFrame` → `BarcodeDetector.detect()` 或 `jsQR()` |
| 分辨率 | 640×480 |

### 2.4 解析 API

**端点 1：** `GET /api/scan/resolve?batchNo={batchNo}&processGroupId={processGroupId}`
— 已知工序组ID，直接获取批次详情

**端点 2：** `GET /api/scan/batch-groups?batchNo={batchNo}`
— 仅已知批次号，获取批次信息 + 所有工序组列表（含单支重量 UnitWeight，用于扫码自动算重）

**端点 3：** `GET /api/scan/resolve-equipment?code={code}`
— 解析设备码，返回设备信息，供扫码报修/扫码维修入口使用

**响应 DTO 字段说明详见代码注释。**

### 2.5 提交 API 汇总

### 2.6 表单字段说明

#### 2.6.1 普通报工 / 酸洗入缸

使用同一套表单模板，按工段不同动态显示专用字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| 班次 | 只读 | 自动判定（6:00-18:00 白 / 18:00-24:00 中 / 0:00-6:00 夜，`ShiftHelper.GetShiftByTime()`） |
| 执行日期 | 文本 | yyyy-MM-dd |
| 加工支数 | 数字 | 必填，输入后按单支重量自动算重（支数 × 单重） |
| 加工重量(kg) | 数字 | 可手动修正自动算重结果 |
| 固溶温度/保温时间 | 数字 | 仅普通报工+固溶工段显示 |
| 断切倍数/成品长度/切后支数 | 数字 | 仅普通报工+断切工段显示 |
| 备注 | 文本 | 可选 |

#### 2.6.2 酸洗出缸

| 字段 | 类型 | 说明 |
|------|------|------|
| 完工日期 | 文本 | yyyy-MM-dd，必填 |
| 备注 | 文本 | 可选 |

#### 2.6.3 工段委外

| 字段 | 类型 | 说明 |
|------|------|------|
| 委外单位 * | 自动补全 | 必填，历史委外单位提示 + 支持手输新增 |
| 发出日期 | 文本 | yyyy-MM-dd，默认当天 |
| 要求收回日期 | 文本 | yyyy-MM-dd，可选 |
| 发出支数 | 数字 | 可选，输入后按单支重量自动算重 |
| 发出重量(kg) | 数字 | 可选，可手动修正自动算重结果 |
| 委外规格 | 文本 | 可选 |
| 是否紧急 | 复选框 | 默认否 |
| 厂内加工 | 开关 | **仅冷轧拔工段（SectionKeys.ColdRollDraw）工位显示**。开启=厂内虚拟委外（IsInternal=true，落库 Status=Virtual 而非 PendingRecovery，外发厂=厂内，不产生厂外委外计划） |
| 备注 | 文本 | 可选 |

#### 2.6.4 委外回收

| 字段 | 类型 | 说明 |
|------|------|------|
| 回收日期 | 文本 | yyyy-MM-dd，必填 |
| 正常回收支数/重量 | 数字 | 正常加工后回收，支数输入后按发出单重自动算重 |
| 未加工支数/重量 | 数字 | 非正常未加工退回 |
| 备注 | 文本 | 可选 |

#### 2.6.5 过程检验

| 字段 | 类型 | 说明 |
|------|------|------|
| 检验日期 | 文本 | yyyy-MM-dd |
| 班次 | 只读 | 自动判定（同普通报工） |
| 检验支数/重量 | 数字 | 可选，支数输入后按单支重量自动算重 |
| 检验项目 | 下拉 | InspectionItem 枚举（PMI/表检/尺寸/内窥/水压/水下气压/涡流/超声波/端口着色） |
| 合格(支数/重量/让步放行/让步说明) | 数字/文本 | 合格相关字段 |
| 不合格(返整/入库/报废支数 + 描述) | 数字/文本 | 不合格相关字段 |
| 备注 | 文本 | 可选 |

> 操作人候选 = `ProcessInspectionItems = 是` 且启用 的员工（过程检验工位专属开关）。

#### 2.6.6 成检到料

> **检验工序组**：扫批次后按「`Inspection` 有值（IsInspectionGroup）且制造规格==批次成品规格」过滤候选。批次含**多道检验工序组**时表单顶部显示组按钮、须指定到料组（默认选中首组）；**唯一一组**自动选中并只读提示；**无匹配组**提示无法创建（对齐 MaterialReceiveCheckService「每检验工序组唯一一条到料记录」，ProcessGroupId/ProcessName/SequenceNumber 一并落库）。

| 字段 | 类型 | 说明 |
|------|------|------|
| 到料日期 | 文本 | yyyy-MM-dd |
| 班次 | 只读 | 自动判定（同普通报工） |
| 确认人 | 多选操作人 | 扫码员工，提交时拼接为操作人/确认人 |
| 备注 | 文本 | 可选 |

> 确认人候选 = `MaterialReceiveCheckItems = 是` 且启用 的员工（成检到料工位专属开关）。

#### 2.6.7 成品检验

除基础字段（检验日期/班次/支数/重量/合格/不合格）外，根据检验项目类型有条件显示。检验项目由**工位绑定**（`Workstation.InspectionItem`，成品检验工位必填）直接确定，扫码进入表单即带入，无需手工选择。

**成检类型**：另设下拉 = `AUTO`（自动判定，默认）+ 预检（PreInspection）/ 终检（FormalInspection）。AUTO→不显式传，服务端按到料集合「优先终检」推导；显式选预检/终检→提交时强校验该类型必须在批次成检到料类型集合内，否则拒绝（与桌面/批量口径一致）。

| 检验项目 | 条件字段 |
|---------|---------|
| 尺寸 | 外径范围 / 壁厚范围 / 长度余量范围 |
| 水压 / 水下气压 | 压力(Mpa) / 保压时间(s) |
| 涡流 / 超声波 | 资格等级 / 检验标准 / 验收等级 / 仪器型号（探伤核心 4 项） |
| 其他（PMI/表检/内窥/端口着色） | 无专用字段 |

> 操作人候选 = `InspectionItems` 包含该工位绑定检验项目 且启用 的员工（成品检验工位按检验项目资质过滤）。

### 2.8 工位上下文（Workstation）

工位二维码包含以下属性：

| 属性 | 说明 |
|------|------|
| `Code` | 工位编码（唯一，扫码入口） |
| `Name` | 工位名称 |
| `SectionName` | 关联工段名（成检到料/成品检验工位**选填**，其余类型必填，普通生产扫码按工段过滤操作人） |
| `GroupNames` | 组类选项（逗号串，可空）。有值=扫码先选组类再选人（候选=工位工段 ∩ 员工组类）；留空=不分组直接候选 |
| `InspectionItem` | 绑定检验项目（仅成品检验工位必填）。扫码直击检验项目 + 按项目过滤操作人 |
| `EquipmentName` | 设备名称 |
| `ReportType` | 报工类型（决定整个流程） |

报工类型工作在**单工位绑定模式**：一个工位只对应一个 ReportType，扫码即确定。

### 2.9 员工上下文（Employee）

员工二维码解析后存储到 `_operators` 列表中，多人扫码可叠加。提交时自动拼接为 `姓名(工号)、姓名(工号)` 格式填入操作人/检验员字段。

操作人**必选（可多人）**，按工位类型过滤候选：

| 工位类型 | 操作人过滤依据 | Employee 对应字段 |
|---------|--------------|------------------|
| 普通/入缸/出缸/委外 | 工位工段（+组类，若工位配了 GroupNames） | `SectionName`（工段逗号串）、`GroupName`（组类逗号串） |
| 过程检验 | `ProcessInspectionItems = 是` | `ProcessInspectionItems`（bool?） |
| 成检到料 | `MaterialReceiveCheckItems = 是` | `MaterialReceiveCheckItems`（bool?） |
| 成品检验 | 工位绑定检验项目 ∈ `InspectionItems` | `InspectionItems`（检验项目枚举名逗号串） |

## 四、配置清单

### 4.1 依赖项

- `BarcodeDetector` API — 浏览器原生扫码（Chrome/Edge），支持二维码+条码
- `jsQR` CDN — 前端扫码解码回退方案
- 浏览器 `getUserMedia` API — 摄像头访问

### 4.2 工位配置要求

每台报工终端需在 `Workstations` 表中预配置以下字段：

| 字段 | 示例值 | 说明 |
|------|--------|------|
| Code | D001 | 唯一工位编码，二维码内容 |
| Name | 1号固溶炉 | 工位名称 |
| SectionName | 固溶 | 关联工段（普通生产必填；成检到料/成品检验选填） |
| GroupNames | 甲班,乙班 | 组类选项（逗号串，可空）。有值=扫码先选组类再选人 |
| InspectionItem | 涡流 | 绑定检验项目（仅成品检验工位必填） |
| EquipmentName | 固溶炉-1# | 设备名称 |
| ReportType | ProductionRecord | 报工类型 |
