# 扫码执行设计

**版本：V4.0**
**最后更新：2026-06-16**

---

## 一、架构总览

扫码执行模块是一套**移动端扫码报工系统**，通过工位二维码确定报工类型，逐步骤引导完成生产/检验/委外等记录的快速录入。

### 1.1 核心概念

| 概念 | 说明 |
|------|------|
| **工位（Workstation）** | 物理工位的二维码编码，绑定 `(工段 + 设备 + 报工类型)`，扫码即确定后续流程 |
| **员工（Employee）** | 操作人/检验员的工号二维码，支持多人同时扫码 |
| **批次（ProductionBatch）** | 扫码解析批次号，获取批次信息和工序组列表 |
| **工序组（ProcessGroup）** | 批次下的工序集合，按工序名+工段匹配确定报工归属 |
| **报工类型（ReportType）** | 工位属性，决定整个流程的模板和数据提交目标 |

### 1.2 交互流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 步骤1     │ →  │ 步骤2     │ →  │ 步骤3     │ →  │ 步骤4     │
│ 扫工位码   │    │ 扫员工码   │    │ 扫批次号   │    │ 填表单     │
│ (确定类型) │    │ (多人可选) │    │ (解析数据) │    │ (提交)     │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                       │
                                                  ┌────┘
                                                  ▼
                                          ┌──────────────┐
                                          │ 提交并继续     │
                                          │ / 提交并完成   │
                                          └──────────────┘
```

### 1.3 8 种报工类型

| ReportType | 中文名 | 步骤3模式 | 提交目标 |
|-----------|--------|----------|---------|
| `ProductionRecord` | 普通报工 | Pattern A：选工序组 | `POST api/production-record/record` |
| `PicklingInRecord` | 酸洗入缸 | Pattern A：选工序组 | `POST api/pickling` |
| `PicklingOutRecord` | 酸洗出缸 | Pattern B：选入缸记录 | `POST api/pickling/out-record` |
| `SectionOutsource` | 工段委外 | Pattern A：选工序组 | `POST api/section-outsource` |
| `OutsourceRecovery` | 委外回收 | Pattern B：选委外记录 | `POST api/section-outsource/recovery` |
| `ProcessInspection` | 过程检验 | Pattern A：选工序组 | `POST api/process-inspection/batch` |
| `MaterialReceiveCheck` | 成检到料 | Pattern C：直接确认 | `POST api/material-receive-check` |
| `FinalInspection` | 成品检验 | Pattern D：选检验项目 | `POST api/final-inspection` |

### 1.4 三种步骤3模式

| 模式 | 有工序组？ | 有选择列表？ | 适用类型 |
|------|-----------|------------|---------|
| **Pattern A** | ✅ 扫批次→过滤工序组→用户选择 | 工序组列表 | ProductionRecord, PicklingInRecord, SectionOutsource, ProcessInspection |
| **Pattern B** | ❌ 扫批次→加载关联待处理记录→用户选择 | 待处理记录列表 | PicklingOutRecord（入缸记录）, OutsourceRecovery（委外记录） |
| **Pattern C** | ❌ 扫批次→直接进入表单 | 无选择 | MaterialReceiveCheck |
| **Pattern D** | ❌ 扫批次→选检验项目→进入表单 | 检验项目列表 | FinalInspection |

### 1.5 基础配置

| 配置 | 说明 |
|------|------|
| **工位管理（Workstations）** | 工位码绑定（工段 + 设备 + 报工类型），扫码后自动确定目标记录表和表单模板 |
| **员工管理（Employees）** | 员工基础信息（工号/姓名/部门/岗位），扫码识别操作人/检验员，支持多人协作 |

## 二、扫码报工与检验（ScanExecute）

### 2.1 路由与权限

| 项目 | 值 |
|------|-----|
| 页面路由 | `@page "/mobile-report"` |
| 授权角色 | `BatchStaff`, `BatchDirector`, `Admin` |
| 返回导航 | 返回批次列表 `/batches` |

### 2.2 条码/二维码格式

```
{批次号}                     → 纯批次号
{批次号}|{工序组ID}          → 带工序组ID（兼容旧标签，直接跳过工序组选择）
```

示例：`BATCH-001` 或 `BATCH-001|5`

### 2.3 扫码技术实现

**文件：** `wwwroot/js/scanner.js`

| 技术 | 说明 |
|------|------|
| 首选解码 | **BarcodeDetector API**（浏览器原生，Chrome/Edge）— 支持 QR码 + Code128/EAN-13/UPC/Code39 等条码 |
| 回退解码 | **jsQR**（CDN加载）— 仅二维码 |
| 摄像头 | `navigator.mediaDevices.getUserMedia`，`facingMode: 'environment'` |
| 扫码方式 | 逐帧扫描 `requestAnimationFrame` → `BarcodeDetector.detect()` 或 `jsQR()` |
| 分辨率 | 640×480 |

### 2.4 解析 API

**端点 1：** `GET /api/scan/resolve?batchNo={batchNo}&processGroupId={processGroupId}`
— 已知工序组ID，直接获取批次详情

**端点 2：** `GET /api/scan/batch-groups?batchNo={batchNo}`
— 仅已知批次号，获取批次信息 + 所有工序组列表

**响应 DTO 字段说明详见代码注释。**

### 2.5 提交 API 汇总

| 报工类型 | HTTP 方法 | 路由 | Service 方法 |
|---------|----------|------|-------------|
| 普通报工 | POST | `api/production-record/record` | `ScanService.CreateProductionRecordAsync` |
| 酸洗入缸 | POST | `api/pickling` | `PicklingService.CreateAsync` |
| 酸洗出缸 | POST | `api/pickling/out-record` | `PicklingService.CreateOutRecordAsync` |
| 工段委外 | POST | `api/section-outsource` | `SectionOutsourceService.CreateAsync` |
| 委外回收 | POST | `api/section-outsource/recovery` | `SectionOutsourceService.CreateRecoveryAsync` |
| 过程检验 | POST | `api/process-inspection/batch` | `ScanService.CreateInspectionAsync` |
| 成检到料 | POST | `api/material-receive-check` | `MaterialReceiveCheckService.CreateAsync` |
| 成品检验 | POST | `api/final-inspection` | `FinalInspectionService.CreateAsync` |

### 2.6 表单字段说明

#### 2.6.1 普通报工 / 酸洗入缸

使用同一套表单模板，按工段不同动态显示专用字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| 班次 | 下拉 | 白班/中班/夜班 |
| 执行日期 | 文本 | yyyy-MM-dd |
| 加工支数 | 数字 | 必填，触发自动算重 |
| 加工重量(kg) | 数字 | 可手动修正自动算重结果 |
| 是否成品 | 复选框 | 系统自动判定，可手动修正 |
| 固溶温度/保温时间 | 数字 | 仅普通报工+固溶工段显示 |
| 断切倍数/成品长度/切后支数 | 数字 | 仅普通报工+断切工段显示 |
| 备注 | 文本 | 可选 |

#### 2.6.2 酸洗出缸

| 字段 | 类型 | 说明 |
|------|------|------|
| 完工日期 | 文本 | yyyy-MM-dd，必填 |
| 备注 | 文本 | 可选 |

#### 2.6.3 工段委外

| 字段 | 类型 | 说明 |
|------|------|------|
| 委外单位 * | 文本 | 必填 |
| 发出日期 | 文本 | yyyy-MM-dd，默认当天 |
| 要求收回日期 | 文本 | yyyy-MM-dd，可选 |
| 发出支数 | 数字 | 可选 |
| 发出重量(kg) | 数字 | 可选 |
| 委外规格 | 文本 | 可选 |
| 是否紧急 | 复选框 | 默认否 |
| 备注 | 文本 | 可选 |

#### 2.6.4 委外回收

| 字段 | 类型 | 说明 |
|------|------|------|
| 回收日期 | 文本 | yyyy-MM-dd，必填 |
| 正常回收支数/重量 | 数字 | 正常加工后回收 |
| 未加工支数/重量 | 数字 | 非正常未加工退回 |
| 备注 | 文本 | 可选 |

#### 2.6.5 过程检验

| 字段 | 类型 | 说明 |
|------|------|------|
| 检验日期 | 文本 | yyyy-MM-dd |
| 班次 | 下拉 | 白班/中班/夜班 |
| 检验支数/重量 | 数字 | 可选 |
| 检验项目 | 文本 | 自由输入 |
| 合格(支数/重量/让步放行/让步说明) | 数字/文本 | 合格相关字段 |
| 不合格(返整/入库/报废支数 + 描述) | 数字/文本 | 不合格相关字段 |

#### 2.6.6 成检到料

| 字段 | 类型 | 说明 |
|------|------|------|
| 到料日期 | 文本 | yyyy-MM-dd |
| 班次 | 下拉 | 白班/中班/夜班 |
| 检验员 | 文本 | 默认为已扫码员工 |
| 备注 | 文本 | 可选 |

#### 2.6.7 成品检验

除基础字段（检验日期/班次/支数/重量/合格/不合格）外，根据检验项目类型有条件显示：

| 检验项目 | 条件字段 |
|---------|---------|
| 尺寸 | 外径范围 / 壁厚范围 / 长度余量范围 |
| 水压 / 水下气压 | 压力(Mpa) / 保压时间(s) |
| 其他（PMI/表检/内窥/涡流/超声波/端口着色） | 无专用字段 |

### 2.8 工位上下文（Workstation）

工位二维码包含以下属性：

| 属性 | 说明 |
|------|------|
| `Code` | 工位编码（唯一，扫码入口） |
| `Name` | 工位名称 |
| `SectionName` | 关联工段名 |
| `EquipmentName` | 设备名称 |
| `ReportType` | 报工类型（决定整个流程） |

报工类型工作在**单工位绑定模式**：一个工位只对应一个 ReportType，扫码即确定。

### 2.9 员工上下文（Employee）

员工二维码解析后存储到 `_operators` 列表中，多人扫码可叠加。提交时自动拼接为 `姓名(工号)、姓名(工号)` 格式填入操作人/检验员字段。

## 三、前端服务

### 3.1 ScanService（扫码核心服务）

**文件：** `MES.Blazor.Services.ScanService`

| 方法 | 说明 |
|------|------|
| `ResolveAsync(batchNo, processGroupId)` | GET `api/scan/resolve` — 解析批次+工序组 |
| `GetBatchProcessGroupsAsync(batchNo)` | GET `api/scan/batch-groups` — 批次信息+工序组列表 |
| `CreateProductionRecordAsync(request)` | POST `api/production-record/record` — 提交普通报工 |
| `CreateInspectionAsync(request)` | 包装 POST `api/process-inspection/batch` — 提交过程检验 |

### 3.2 其他前端 Service

| Service | 提供方法 |
|---------|---------|
| `WorkstationService` | `GetByCodeAsync(code)` — 扫码解析工位 |
| `EmployeeService` | `GetByCodeAsync(code)` — 扫码解析员工 |

## 四、配置清单

### 4.1 依赖项

- `BarcodeDetector` API — 浏览器原生扫码（Chrome/Edge），支持二维码+条码
- `jsQR` CDN — 前端扫码解码回退方案
- 浏览器 `getUserMedia` API — 摄像头访问

### 4.2 工位配置要求

每台报工终端需在 `Workstations` 表中预配置以下字段：

| 字段 | 示例值 | 说明 |
|------|--------|------|
| Code | D001 | 唯一工位编码，二维码内容 |
| Name | 1号固溶炉 | 工位名称 |
| SectionName | 固溶 | 关联工段 |
| EquipmentName | 固溶炉-1# | 设备名称 |
| ReportType | ProductionRecord | 报工类型 |
