## 一、概述

本文档定义质量管理上下文的接口设计，包括DTO、枚举、API端点。

**当前实现**：
- ✅ 炉号登记（FurnaceRegistration）：完整 CRUD + 批量创建 + 牌号自动查询 + 化学成分验证
- ✅ 工厂牌号化学成分（ChemicalComposition）：完整 CRUD ✅（已迁移至生产标准上下文）
- ✅ 工厂牌号化分验证规则（ChemicalValidationRule）：完整 CRUD + 按工厂牌号查询 ✅（已迁移至生产标准上下文）
- ✅ 过程检验（ProcessInspection）：完整 CRUD + 跨批次分页查询
- ✅ 成品检验（FinalInspection）：完整 CRUD + 批量创建 + 批次信息自动调取（批次信息经 ProductionBatch 查询投影，不冗余存储）
- ✅ 质量过程跟踪（QualityProcessTracking）：成检到料→成品检验→成品入库 整合读模型 + 分页查询
- ✅ 不合格品报告（NCR）：不合格品反馈→处置→分析→追责→纠正预防闭环，3 状态状态机（处理中/已关闭）
- ✅ 理化检测：
  - ✅ 化学分析（ChemicalAnalysis）：光谱分析15元素 + CRUD + 批量创建
  - ✅ 硬度检验（HardnessTest）：硬度检测 CRUD + 批量创建
  - ✅ 晶粒度检验（GrainSizeTest）：晶粒度评级 CRUD + 批量创建

**服务契约增量（质量域）**

| 接口 | 方法 | 说明 |

**DTO 契约增量**

- `InspectionPatrolDto` 新增 **`RectificationOperator`**（string?，整改人——第二次扫码补整改时的操作人姓名），与 `VerificationResult` / `IsClosed` 同属 G4 整改闭环块
- `InspectionPatrolRectifyRequest`：`VerificationResult`（≤500）/ `RectificationOperator`（≤200）/ `IsClosed`（bool），三者皆可空/可省（扫码页提交时由服务端覆写 `RectificationOperator`）
- 创建路径的 `Inspector` / `Reporter` / `DataSource` **前端传值一律被服务端覆写**（防伪造操作人）

**扫码页与之对应的调用序列**（`ScanQuality.razor`，详见 `质量管理模块详细设计.md` §2.41）

1. 页面挂载 → `GET current-operator`（只读展示操作人）
2. 扫到批次码 → `GET .../lookup-batch?batchNo=`（取批次 + 工序组）→ `GET .../position-options`（取工段候选）
3. 选完工序+工段 → `GET .../by-key`（闭环定位）→ 命中待整改则 `GET .../{id}`（带出第一次明细与照片）
4. 提交 → `POST ...`（新建）或 `POST .../{id}/rectify`（整改）→ 逐张 `POST .../{id}/attachments`
5. 界面「改选已有单 / 新建」逃生口：`by-key` 列表内切换，或直接转新建模式
