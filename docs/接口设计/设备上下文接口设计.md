# 设备上下文接口设计

**版本：V2.6**
**最后更新：2026-08-15**

---

## 一、概述

本文档定义设备上下文的接口设计，包括DTO、API端点和业务规则。设备上下文涵盖设备台账管理、点检记录管理、保养工单管理和维修工单管理。

**关键设计（V2.1 物化状态）：**
- 扫码报修：移动端扫码解析设备 → 提交生成维修工单，通过 `ScanController` 的 `resolve-equipment` 端点实现
- 设备运行状态（RunningStatus）、点检状况（InspectionStatus）、保养状况（MaintStatus）**为 Equipment 表物化存储字段**，由 `EquipmentStatusCalculator` 在点检/保养/维修写操作后同步更新（V2.0 前为 Service 层动态计算，不存储）
- 维修状态（RepairStatus）根据 RepairStartTime/RepairEndTime 自动推导并持久化存储
- 点检/保养/维修通过 EquipmentId 关联设备台账
- 设备编号（EquipmentCode）为用户手动输入，点检/保养/维修编号为系统自动生成

### 2.4 扫码解析端点

扫码场景通过 `ScanController` 统一提供批次扫码和设备扫码解析能力：

**Controller：** `MES.Api.Controllers.Infrastructure.ScanController`
**路由：** `api/scan`

| 方法 | 路由 | 权限 | 说明 |
|------|------|------|------|
| GET | /api/scan/resolve?batchNo={batchNo}&processGroupId={processGroupId} | 已认证 | 扫码解析（通用）：解析批次二维码，返回批次信息和可用工段列表 |
| GET | /api/scan/batch-groups?batchNo={batchNo} | 已认证 | 批次分组查询：按批次号解析，返回该批次下所有工序组选项 |
| GET | /api/scan/resolve-equipment?code={code} | 已认证 | 扫码解析设备（返回设备摘要信息，含 ID/编码/名称/区域/关联工段/型号） |

#### 响应 DTO

**ScanResolveResultDto**（`GET /api/scan/resolve`）

| 字段 | 类型 | 说明 |
|------|------|------|
| BatchNo | string | 批次号 |
| PlantGrade | string | 工厂牌号（钢种） |
| ProcessGroupId | int | 工序组 ID |
| ProcessName | string | 工序名称 |
| ManufacturingSpec | string? | 制造规格 |
| AvailableSections | List\<SectionOption\> | 可用工段列表 |
| UnitWeight | decimal? | 单支重量(kg) |

**ScanBatchResolveResultDto**（`GET /api/scan/batch-groups`）

| 字段 | 类型 | 说明 |
|------|------|------|
| BatchNo | string | 批次号 |
| Status | BatchStatus | 批次状态 |
| StatusDisplay | string | 批次状态中文显示 |
| PlantGrade | string | 工厂牌号（钢种） |
| Specification | string | 规格 |
| TagNo | string? | 挂牌号 |
| UnitWeight | decimal? | 单支重量（用于扫码自动算重） |
| ProcessGroups | List\<ProcessGroupOption\> | 该批次下的所有工序组选项（含 Id/序号/工序名称/制造规格/工段列表） |

**ScanEquipmentResolveResultDto**（`GET /api/scan/resolve-equipment`）

| 字段 | 类型 | 说明 |
|------|------|------|
| EquipmentId | int | 设备ID |
| EquipmentCode | string | 设备编号 |
| EquipmentName | string | 设备名称 |
| Location | string | 所在区域 |
| RelatedSection | string? | 关联工段 |
| ModelNumber | string? | 型号规格 |

#### 业务逻辑

- **resolve-equipment：** 根据 `EquipmentCode` 精确匹配查询，未找到时返回 `BusinessException`。
- **resolve：** 根据 `batchNo` + `processGroupId` 匹配批次工序组，返回该批次信息和当前工序组下可用工段列表（按工序组执行序号排序）。
- **batch-groups：** 根据 `batchNo` 查询该批次下的所有工序组选项，用于扫码时让用户选择目标工序组。

| PUT | /api/repair-order/{id}/complete | EquipmentEditor/EquipmentFull/Admin | 完成维修（填写维修类别、内容、备件、其它维修人） |

### 5.4 业务规则

- **编号自动生成：** 格式 `WX-YYYYMMDD-XXX`，按日自增
- **状态自动推导并存储：** RepairEndTime 不为空→Completed, RepairStartTime 不为空且 RepairEndTime 为空→InProgress, 均为空→Pending
- **设备参数回写：** 创建/更新维修工单时，自动回写 Equipment 的 `LastRepairDate` 为最近 `RepairEndTime`
- **维修执行：** 扫码维修分两步：①开始维修（设置维修人和开始时间，状态→InProgress）②完成维修（填写维修类别、内容、备件，状态→Completed）
- **多人协作：** 完成维修时可通过 `OtherRepairPersons` 添加其它维修人，存入独立 `OtherRepairPersons` 字段（逗号分隔，自动去重，不合并到 `RepairPerson`）

## 六、枚举定义

> **枚举中英/显示参数化：** 设备上下文全部枚举（LifecycleStatus/UsageType/RunningStatus/EquipmentTaskStatus/RepairPriority/RepairOrderStatus）后端存储一律为**英文枚举名**（Equipment/RepairOrder 实体为 string 属性存储枚举名），前端显示一律为中文。中文显示名经 `EnumHelper.GetDisplayName` 统一出口（DTO 计算属性如 InspectionStatusDisplay/MaintStatusDisplay/LifecycleStatusDisplay/UsageTypeDisplay/RunningStatusDisplay），并受 `EnumDisplayDefinition` 配置表参数化（`ApplyEnumOverrides` 覆盖优先，未配置回退静态字典）；DataExchange 导入导出经 `EnumHelper.Parse/GetDisplayName` 中英互转。

### 6.1 生命周期（LifecycleStatus）

| 存储值 | 中文显示 | 说明 |
|--------|----------|------|
| Active | 在用 | 设备正常使用中 |
| Standby | 备用 | 设备备用状态 |
| Scrapped | 报废 | 设备已报废 |

### 6.2 作用类型（UsageType）

| 存储值 | 中文显示 | 说明 |
|--------|----------|------|
| Primary | 主生产设备 | 直接参与生产的主要设备 |
| Secondary | 辅生产设备 | 辅助生产的设备 |
| Other | 其它 | 其他类型设备 |

### 6.3 维修优先级（RepairPriority）

| 存储值 | 中文显示 | 说明 |
|--------|----------|------|
| Normal | 普通 | 常规维修 |
| Urgent | 紧急 | 紧急维修 |
| Emergency | 特急 | 特急维修 |

### 6.4 维修状态（RepairOrderStatus）

| 存储值 | 中文显示 | 说明 |
|--------|----------|------|
| Pending | 待维修 | 已报修，尚未开始维修 |
| InProgress | 维修中 | 维修进行中 |
| Completed | 已完成 | 维修已完成 |

### 6.5 运行状态（RunningStatus，物化存储）

| 值 | 中文显示 | 说明 |
|----|----------|------|
| Normal | 正常 | 设备无待维修问题 |
| Pending | 待维修 | 有待维修工单 |
| InProgress | 维修中 | 有正在进行的维修 |

### 6.6 物化状态枚举（EquipmentTaskStatus）

适用于 InspectionStatus 和 MaintStatus。

| 值 | 中文显示 | 说明 |
|----|----------|------|
| NotApplicable | 不适用 | 该设备无需点检/保养 |
| Pending | 待执行 | 点检/保养未到周期 |
| Normal | 正常 | 点检/保养正常进行中 |
| Overdue | 逾期 | 点检/保养已逾期 |

## 七、打印设计

### 7.1 打印端点

所有4个实体均支持以下两种打印端点（均直接返回 PDF 文件流）：
- **print-batch-file：** 按 ID 数组批量打印
- **print-all-file：** 按当前筛选条件打印全部

### 7.2 打印请求参数

| 参数 | 类型 | 说明 |
|------|------|------|
| Ids | int[] | 批量打印的ID数组（仅print-batch） |
| Columns | List\<PrintColumnDef\> | 打印列定义（列名、是否显示） |
| Keyword/SortBy/筛选条件 | 各类型 | 同查询参数（仅print-all） |

### 7.3 打印权限

所有打印端点统一使用 EquipmentEditor/EquipmentFull/Admin 权限。
