# 计划排程上下文接口设计

**版本：V5.31**
**最后更新：2026-08-15**

---

## 一、概述

本文档定义计划排程上下文（Scheduling Context）的接口设计，包括 DTO、API 端点和业务规则。

**关键设计：**
- 订单总况（ProductionOverview）是纯查询聚合，不涉及任何数据写入，无独立实体
- 原锁计划使用 LEFT JOIN 实时查询模式（WorkOrderExecutionSummary + RawMaterialLockPreExecution），G13 直接从实体读取，无物化表，支持分页查询和 G15 内联编辑
- 工单排程（WorkOrderSchedule）是 LEFT JOIN 实时查询视图（WorkOrderExecutionSummary + WorkOrderPlan 薄表），支持 G15 内联编辑 + 计划安排批量重置，无物化表
- 所有实体的 `WorkOrderId` 均为唯一索引
- 批次计划（BatchPlan）是实时查询视图（ProductionBatch LEFT JOIN WorkOrderExecutionSummary + WorkOrderPlan + BatchPlanSchedule），支持分页查询、筛选上下文获取和 GetAllAsync 全量加载，无独立实体
- OrderDemandAdjustment（工单需求调整）数据库实体保留在本上下文，其 API/UI 层已迁移至工单上下文（工单需求调整页面），其 G13 字段已直接存入 WorkOrderExecutionSummary 实体
- WorkOrderSchedule 物化表（WorkOrderSchedules）已删除（V4.5），改为实时查询+WorkOrderPlan 薄表模式
- **批次计划薄表（BatchPlanSchedule）为独立实体，存储批次级流转计划决策，通过"计划安排"按三规则自动计算 8 个字段（含外径跨度）：规则1 冷轧排程命中→FlowTarget=实时值（成检/完工冷轧/冷轧）；规则2 重点生产批次→FlowTarget=MapFlowTargetByCRType（荒管检/在制检/成品检验/冷轧）；规则3 降级→null。PlanFlowLevel 五档（1急+/2急/3急-/4一般/5略，1A/1B 拆分已废弃），PlanFlowTarget 六档，支持手工内联编辑（仅抢单/备注）**
- **成检计划（FinalInspectionPlan）是全量加载 Items 模式页面，基于 ProductionBatch + MaterialReceiveCheck + FinalInspection 实时查询，无独立实体，API 端点 GET `/api/final-inspection-plan/kanban` 返回全量数据**
- ~~**批次计划产量目标（BatchPlanTarget）：独立实体，每个工段一条日产目标(吨)，在批次计划页面 Tab 栏下方以内联编辑框展示，全量覆盖保存（V5.3 新增）**~~（⚠️ 已弃用 V5.28，见 §8.8/§十五）

### 3.2 API 端点

#### GET /api/raw-material-lock-plan/list

分页查询原锁计划列表。

> **前端调用方式：** Blazor 页面使用内存全量加载模式，通过 `GetPagedAsync(PageSize=50000)` 一次性获取全部数据，后续排序/筛选/搜索均在客户端内存中执行。`keyword`/`sortBy`/`isDescending`/`filters` 参数传空值。

**请求参数：** 同工单需求调整列表。

**支持排序字段：**

| SortBy 值 | 对应字段 | 说明 |
|-----------|----------|------|
| WorkOrderNo | WorkOrderNo | 工单号 |
| Salesman | Salesman | 业务员 |
| CustomerName | CustomerName | 往来单位 |
| SignDate | SignDate | 订单日期 |
| DeliveryDate | DeliveryDate | 交货日期 |
| SalesOrderNo | SalesOrderNo | 订单号 |
| ProductionMainNo | ProductionMainNo | 主号 |
| PlantGrade | PlantGrade | 工厂牌号 |
| Specification | Specification | 规格 |
| ScheduleStage | ScheduleStage | 主号关注 |

**响应：** `ApiResponse<PagedResult<RawMaterialLockPlanAndExecutionDto>>`

#### POST /api/raw-material-lock-plan/set-pre-execute-flags

设置预执行标记（G15）：批量设置 IsPreInput 和/或 IsMainNoMaterialComplete。

**请求体：**

```json
{
    "workOrderIds": [123, 456, 789],
    "isPreInput": true,
    "isMainNoMaterialComplete": null,
    "budgetInputDate": null,
    "isBudgetComplete": null
}
```

**参数说明：**
- `workOrderIds`：必填，工单ID列表
- `isPreInput`：可选，设置 IsPreInput（true=执行/false=取消执行/null=不修改）
- `isMainNoMaterialComplete`：可选，设置 IsMainNoMaterialComplete（系统自动计算，不接受手工设置）
- `budgetInputDate`：可选，设置 BudgetInputDate（DateTime?，预算投料日）
- `isBudgetComplete`：可选，设置 IsBudgetComplete（true=预算主号齐全/false=取消/null=不修改），切换为 true 时级联设置同组 `IsMainNoMaterialComplete=true`，false 时强制同组 false

**响应：** `ApiResponse<SetPreExecuteFlagsResult>`（返回更新记录数 + 提示消息）

**内部流程：**
1. 按 WorkOrderId 批量查询 `RawMaterialLockPreExecution` 中的匹配记录
2. 不存在的记录先 INSERT（upsert 模式）
3. 根据 nullable 参数选择性设置字段
4. 当 `isPreInput` 有值（无论 true 或 false）时，触发 `IsMainNoMaterialComplete` 系统自动计算，支持设 true 和回退 false：
   - **A质量影响**：`IsMainNoMaterialComplete = IsPreInput`（直接跟随）
   - **B已购未回/C计划未执行/D未完善计划**：按 `(SalesOrderNo, ProductionMainNo, RawMaterialLockRemark)` 分组，组内**全部**工单"就绪" → 组内**全部**工单 IsMainNoMaterialComplete=true；**任一**未就绪 → 全部 false。
     某工单"就绪"条件（三选一）：
     - 用户显式标记`IsPreInput=true`，**或**
     - **B类型**：`G5.PendingRoughTubeQty == 0 && G5.PendingOutsourceFinishQty == 0`（待回物料已回），**或**
     - **C/D类型**：`G7.FlowStatus >= 1`（已开始流转）
   - 组内无 PreExecution 记录的成员自动创建一条
5. 当 `isBudgetComplete` 有值时，触发级联：true → 同 `(SalesOrderNo, ProductionMainNo)` 组内全部工单 `IsMainNoMaterialComplete=true`；false → 同组全部 `IsMainNoMaterialComplete=false`
6. 两个 SaveChangesAsync 调用：先保存 G15 upsert，再执行重算

#### POST /api/raw-material-lock-plan/print-file

打印原锁计划数据，直接返回 PDF 文件流（供 `openPdfFromApi` JS 函数通过 fetch 获取）。

**请求体：** `RawMaterialLockPlanPrintRequest`

```json
{
    "title": "原锁计划",
    "items": [...],
    "columns": [
        { "key": "WorkOrderNo", "label": "工单号" },
        { "key": "Salesman", "label": "业务员" },
        ...
    ]
}
```

**响应：** `File(pdfBytes, "application/pdf", "原锁计划.pdf")`（直接返回 PDF 二进制流）

**说明：**
- 使用 `TablePrintHelper.GeneratePdf()` 生成 PDF
- 与传统 `POST /print` 返回 base64 字符串不同，此端点直接返回 `FileContentResult`，通过 JS fetch 获取二进制流后使用 Blob URL + iframe 展示
- 这是新标准做法（参见 04_开发规范 §6.33）

### 4.2 API 端点

#### GET /api/production-overview/overview

获取订单总况聚合数据（无分页，全量返回 8 行 × 7 桶）。

**请求参数：** 无

**响应：** `ApiResponse<ProductionOverviewDto>`

**内部逻辑：**
1. 从 `WorkOrderExecutionSummary`（ScheduleStage >= 2，五档中排除主号暂停/主号完成）汇总 R0~R2
2. 从 `ProductionBatch`（Status=InProgress/None）+ `ProcessGroup` 汇总 R3~R7
3. R0（成品在购）= SUM(PendingOutsourceFinishWeight)，按工单交期分布到各桶
4. R1（待投料）= ScheduleStage=2（原料锁定）的 SUM(TotalWeight - PendingOutsourceFinishWeight - InputWeight)
5. R2（在购荒管）= SUM(PendingRoughTubeWeight)，按工单交期分布到各桶
6. R3~R7 按 ClassifySection 互斥分类，按匹配批次交期分布到各桶

## 五、生产工段待产量现况（SectionProductionStatus）

### 5.1 DTO 定义

**文件：** `MES.Core/DTOs/Scheduling/SectionProductionStatusDto.cs`

| 字段 | 类型 | 说明 |
|------|------|------|
| ProcessGroupName | string | 工序组名称 |
| SectionName | string | 工段名称 |
| ProductStatus | string | 产类（荒管/在制/成品，ProductStatuses 三态） |
| InProduction | decimal? | 生产中：批次当前工序/工段匹配此维度且工段未完工的现有效原料重量汇总；=0 时返回 null |
| PendingProduction | decimal? | 待产量：批次下一工序/工段匹配此维度且工段已完工的现有效原料重量汇总；=0 时返回 null |
| Total | decimal? | 工段生产与待产汇总量 = 生产中 + 待产量；=0 时返回 null |
| PlanFlowQuantity | decimal? | 计划流转量：批次计划中流转=是的重量汇总（kg） |
| PlanKeyWeight | decimal? | 重点批重量：批次计划中流转=是且等级=急+的重量汇总（kg） |

### 5.2 API 端点

#### GET /api/section-production-status

获取所有(工序组, 工段, 产类)三维的生产/待产现况汇总（无分页，全量返回）。

**请求参数：** 无

**响应：** `ApiResponse<List<SectionProductionStatusDto>>`

**内部逻辑：**
1. 加载所有未完成的批次（Status ≠ Completed）及其 ProcessGroups
2. 提取所有唯一的 (ProcessGroup.ProcessName, SectionName, ProductStatus) 组合作为维度行（产类由 ProductStatusHelper.Calculate 逐批次判定）
3. 按维度逐行聚合：
   - InProduction = Σ CurrentValidWeight WHERE CurrentGroupName/SectionName 匹配 AND CurrentSectionCompleted=false
   - PendingProduction = Σ CurrentValidWeight WHERE NextProcess/NextSectionName 匹配 AND CurrentSectionCompleted=true
   - Total = InProduction + PendingProduction
4. 另从批次计划全量数据（GetAllAsync(null) 口径）汇总 PlanFlowQuantity（计划流转量）与 PlanKeyWeight（重点批重量）

### 6.2 API 端点

#### GET /api/section-flow-analysis

获取生产段流转量分析数据（无分页，全量返回 14 个流转类别行）。

**请求参数：** 无

**响应：** `ApiResponse<List<SectionFlowAnalysisDto>>`

**内部逻辑：**
1. 从 `SectionFlowCategorySetting` 加载 14 个流转类别（A-N）
2. 从 `CombinationGroups`（组合归类表）加载每个类别下的归属行（(工序组, 工段, 产类) 三维唯一归属映射），工序组/工段支持"全部"通配，产类为 ProductStatuses 三态或 AllStatus 哨兵；`SectionFlowCategoryItem` 已删除
3. 调用 `SectionProductionStatusService.GetStatusAsync()` 实时获取各(工序组,工段)待产量
4. 按归属行的 (ProcessGroupName, SectionName, ProductStatus) 与实时待产量匹配，未归属行不参与聚合，按类别 SUM（/1000 转吨）
5. 计算可持续天数 = PendingTotal / DailyProductionTarget
6. 总况判定：< LowerLimitDays → "偏少"；> UpperLimitDays → "过多"；其他 → "正常"
7. 计划流转判定：计划流转量 > 日产设定 → "加速"，否则 "-"
8. 另从批次计划全量数据汇总 PlanFlowQuantity/PlanKeyWeight 与重点批次统计（KeyBatchCount/KeyBatchWeight）

更新段落分类设置（日产能目标、偏少/过多天数阈值），**非管理员**（工单主管/厂长）也可修改。

**请求体：** `SectionFlowSettingUpdateDto`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| Id | int | ✅ | 段落分类 Setting ID |
| DailyProductionTarget | decimal? | ❌ | 日产能目标（吨/天） |
| LowerLimitDays | decimal? | ❌ | 偏少下限天数 |
| UpperLimitDays | decimal? | ❌ | 过多上限天数 |

**响应：** `ApiResponse`

**权限：** WorkOrderDirector / Admin（区别于 §7.2 的 AdminOnly 权限）

### 6.3 生产段落流转量分析（SectionParagraphFlowAnalysis，2026-08-15 新增）

#### GET /api/section-paragraph-flow-analysis

获取生产段落流转量分析数据（按生产段落上卷，无分页，全量返回）。

**请求参数：** 无

**响应：** `ApiResponse<List<SectionParagraphFlowAnalysisDto>>`

**内部逻辑：**
1. 从 `SectionParagraphConfig` 加载生产段落（ParagraphName 唯一，按 DisplayOrder 排序）
2. 从 `CombinationGroups` 组合归类表加载各段落的归属行（按「归属段落」列匹配）
3. 调用 `SectionProductionStatusService.GetStatusAsync()` 获取各(工序组,工段)实时待产量
4. 按归属行 (ProcessGroupName, SectionName, ProductStatus) 匹配聚合（/1000 转吨）
5. 计算可持续天数 = PendingTotal / DailyFlowTarget，总况判定（偏少/正常/过多）
6. 计划流转判定：计划流转量 > 日流转设定 → "加速"，否则 "-"
7. 另从批次计划全量数据汇总 PlanFlowQuantity/PlanKeyWeight 与重点批次统计

#### POST /api/section-paragraph-flow-analysis/print-file

打印生产段落流转量分析（Mode B ⓪：前端已准备数据），请求体 `SectionParagraphFlowAnalysisPrintRequest`（Title/Items/Columns），返回 `File(pdfBytes)`。

   - **规则3 降级（非流转）**：IsFlow=false，FlowLevel=5（略），FlowTarget/FlowCRType/PlanOuterDiameterSpan/FlowExecSpec 全 null，ExecutionSequence=批次现执行序（未产视为 0）
