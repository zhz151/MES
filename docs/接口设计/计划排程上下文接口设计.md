# 计划排程上下文接口设计

**版本：V5.44**
**最后更新：2026-09-04**

---

## 一、概述

本文档定义计划排程上下文（Scheduling Context）的接口设计，包括 DTO、API 端点和业务规则。

**关键设计：**
- 订单总况（ProductionOverview）是纯查询聚合，不涉及任何数据写入，无独立实体
- 原锁计划使用 LEFT JOIN 实时查询模式（WorkOrderExecutionSummary + RawMaterialLockPreExecution），G13 直接从实体读取，无物化表，支持分页查询和 G15 内联编辑
- 工单排程（WorkOrderSchedule）是 LEFT JOIN 实时查询视图（WorkOrderExecutionSummary + WorkOrderPlan 薄表），支持 G15 内联编辑 + 计划安排批量重置，无物化表
- 所有实体的 `WorkOrderId` 均为唯一索引
- 批次计划（BatchPlan）是实时查询视图（ProductionBatch LEFT JOIN WorkOrderExecutionSummary + WorkOrderPlan + BatchPlanSchedule），支持分页查询、筛选上下文获取和 GetAllAsync 全量加载，无独立实体
- OrderDemandAdjustment（工单需求调整）数据库实体保留在本上下文，其 API/UI 层已迁移至工单上下文（工单需求调整页面），其 G13 字段已直接存入 WorkOrderExecutionSummary 实体
- **批次计划薄表（BatchPlanSchedule）为独立实体，存储批次级流转计划决策，通过"计划安排"按三规则自动计算 8 个字段（含外径跨度）：规则1 冷轧排程命中→FlowTarget=实时值（成检/完工冷轧/冷轧）；规则2 重点生产批次→FlowTarget=MapFlowTargetByCRType（荒管检/在制检/成品检验/冷轧）；规则3 降级→null。PlanFlowLevel 五档（1急+/2急/3急-/4一般/5略，1A/1B 拆分已废弃），PlanFlowTarget 六档，支持手工内联编辑（仅抢单/备注）**
- **成检计划（FinalInspectionPlan）是全量加载 Items 模式页面，基于 ProductionBatch + MaterialReceiveCheck + FinalInspection 实时查询，无独立实体，API 端点 GET `/api/final-inspection-plan/kanban` 返回全量数据**
- ~~**批次计划产量目标（BatchPlanTarget）**~~ 已删除：实体/EF 配置/后端 Service+接口/Controller/DTO/前端 Service/DI 注册全删，迁移 `20260823194559_DropBatchPlanTargetTable` DROP TABLE `BatchPlanTargets`；原 §8.8/§十五 已移除

### 3.2 API 端点

#### GET /api/raw-material-lock-plan/list

分页查询原锁计划列表。

> **前端调用方式：** Blazor 页面使用内存全量加载模式，通过 `GetPagedAsync(PageSize=50000)` 一次性获取全部数据，后续排序/筛选/搜索均在客户端内存中执行。`keyword`/`sortBy`/`isDescending`/`filters` 参数传空值。

**请求参数：** 同工单需求调整列表。

**支持排序字段：**

| SortBy 值 | 对应字段 | 说明 |
|-----------|----------|------|
| WorkOrderNo | WorkOrderNo | 工单号 |
| Salesman | Salesman | 业务员 |
| CustomerName | CustomerName | 往来单位 |
| SignDate | SignDate | 订单日期 |
| DeliveryDate | DeliveryDate | 交货日期 |
| SalesOrderNo | SalesOrderNo | 订单号 |
| ProductionMainNo | ProductionMainNo | 主号 |
| PlantGrade | PlantGrade | 工厂牌号 |
| Specification | Specification | 规格 |
| ScheduleStage | ScheduleStage | 主号关注 |

**响应：** `ApiResponse<PagedResult<RawMaterialLockPlanAndExecutionDto>>`

#### POST /api/raw-material-lock-plan/set-pre-execute-flags

设置预执行标记（G15）：批量设置 IsPreInput 和/或 BudgetInputDate。

**请求体：**

```json
{
    "workOrderIds": [123, 456, 789],
    "isPreInput": true,
    "budgetInputDate": null
}
```

**参数说明：**
- `workOrderIds`：必填，工单ID列表
- `isPreInput`：可选，设置 IsPreInput（true=执行/false=取消执行/null=不修改）
- `budgetInputDate`：可选，设置 BudgetInputDate（DateTime?，预算投料日）

> **说明：** `IsMainNoMaterialComplete`/`IsBudgetComplete` 及其 A/B/C/D 就绪判定规则已随迁移 `20260811000000_DropRawMaterialLockPreExecutionCompleteFields` 删除，该端点不再承载主号齐全级联逻辑。

**响应：** `ApiResponse<SetPreExecuteFlagsResult>`（返回更新记录数 + 提示消息）

**内部流程：**
1. 按 WorkOrderId 批量查询 `RawMaterialLockPreExecution` 中的匹配记录
2. 不存在的记录先 INSERT（upsert 模式，一个工单一条）
3. 根据 nullable 参数选择性设置字段：`isPreInput` 有值则覆盖 IsPreInput；`budgetInputDate` 有值则覆盖 BudgetInputDate，`isPreInput == false` 时清空 BudgetInputDate
4. 单个 SaveChangesAsync 保存

#### POST /api/raw-material-lock-plan/print-file

打印原锁计划数据，直接返回 PDF 文件流（供 `openPdfFromApi` JS 函数通过 fetch 获取）。

**请求体：** `RawMaterialLockPlanPrintRequest`

```json
{
    "title": "原锁计划",
    "items": [...],
    "columns": [
        { "key": "WorkOrderNo", "label": "工单号" },
        { "key": "Salesman", "label": "业务员" },
        ...
    ]
}
```

**响应：** `File(pdfBytes, "application/pdf", "原锁计划.pdf")`（直接返回 PDF 二进制流）

**说明：**
- 使用 `TablePrintHelper.GeneratePdf()` 生成 PDF
- 此端点直接返回 `FileContentResult`（PDF 二进制流），通过 JS fetch 获取后使用 Blob URL + iframe 展示（标准做法，参见 04_开发规范 §6.33）

### 4.2 API 端点

#### GET /api/production-overview/overview

获取订单总况聚合数据（无分页，行数随机台组配置动态，7 桶）。

**请求参数：** 无

**响应：** `ApiResponse<ProductionOverviewDto>`

**内部逻辑：**
1. 数据源：`WorkOrderExecutionSummary`（ScheduleStage >= 2）+ `ProductionBatch`（Status=InProgress/None）+ `ProcessGroup`
2. **延期判定统一为 主号-预计完成日(EstimatedProcessCompletionDate) > 交货日期(DeliveryDate)**（与「订单延期量[预计完结]」行同源、总量一致；原「> 桶截止日」口径已弃用）
3. 日期桶分布：延期分类行按交货日期分桶，订单延期量[预计完结]按预计完成日分桶
4. 原料行：待计划量=完善计划+执行计划（CalcPending 待投料口径），在购量=成购缺口（成品计划量−已到货量）
5. 生产工段行：批次按工段待执行节点匹配（IsNotReached 工序组级，荒管抛光走 IsNotReachedBySection 工段级）；**冷轧/冷拔越界判定**：当前工序组==目标冷轧/冷拔组且当前工段序号已越过该组冷轧拔序号→机台已轧完、不计入待产；机台组行按产类拆分在制/成品（ClassifyPendingProductStatus：待执行工序组制造规格==批次规格且成品类物品→成品，否则在制）；**冷轧/冷拔行完全遍历机台组**（ClassifySection 用组 ProcessKeys 包含工序 Key 匹配，无硬编码工序/组 Key）
6. 整体完工预计 = Max(生产工段天数) + 原料待投料量/2030机台组日产 + 2（成品检验；2030 机台组日产取产能档案 DailyProductionCapacities.ProcessName='2030'，配置表驱动）
7. 成检行：复用成检计划看板，汇总「待检验+检验中」两档批次重量

### 5.2 API 端点

#### GET /api/section-production-status

获取所有(工序组, 工段, 产类)三维的生产/待产现况汇总（无分页，全量返回）。

**请求参数：** 无

**响应：** `ApiResponse<List<SectionProductionStatusDto>>`

**内部逻辑：**
1. 加载所有未完成的批次（Status ≠ Completed）及其 ProcessGroups
2. 提取所有唯一的 (ProcessGroup.ProcessName, SectionName, ProductStatus) 组合作为维度行（产类由 ProductStatusHelper.Calculate 逐批次判定）
3. 按维度逐行聚合：
   - InProduction = Σ CurrentValidWeight WHERE CurrentGroupName/SectionName 匹配 AND CurrentSectionCompleted=false
   - PendingProduction = Σ CurrentValidWeight WHERE NextProcess/NextSectionName 匹配 AND CurrentSectionCompleted=true
   - Total = InProduction + PendingProduction
4. 另从批次计划全量数据（GetAllAsync(null) 口径）汇总 PlanFlowQuantity（计划流转量）与 PlanKeyWeight（重点批重量）

## 六、段落流转分析（SectionParagraphFlowAnalysis）

> 段落日产配置已重构为「3 类配置驱动自动生成」，段落只填参数。旧「生产段流转量分析（SectionFlowAnalysis）」及其依赖的组合段落归类 `CombinationGroups`、流转类别日产配置 `SectionFlowCategorySetting` 已全套删除，不再从上述两张表加载类别/归属行。

### 6.1 段落自动生成（3 类）

段落由 `SectionParagraphConfig` 按 CategoryType 自动生成，字段：ParagraphKey、CategoryType、ParagraphName（显示名）、DisplayOrder、DailyFlowTarget（日流转设定）、LowerLimitDays（偏少天数）、UpperLimitDays（过多天数）、Remark；唯一索引 `UK_SPC_CategoryType_ParagraphKey`（过滤非空）。段落随机台组/工段配置增减，仅参数可编辑：

- **Cold（冷轧拔）**：按冷轧机台组配置表 `ColdRollMachineGroupConfig` 的组显示名自动生成，ParagraphKey=机台组 GroupKey
- **Section（普通工段）**：按 StandardWorkDays 启用工段自动生成（扣除冷轧拔/检验/入库三个工段），ParagraphKey=工段 SectionKey
- **Fixed（检验）**：固定「荒管检」（RoughTubeInspection）/「在制检」（InProcessInspection）

### 6.2 聚合规则（3 类）

- **Cold**：工序组命中该机台组内任一工序
- **Section**：工段命中该段落工段 且 工序组不属于任何冷轧拔机台组（防重叠）
- **Fixed**：检验工段，荒管检→ProductStatus=RoughTube、在制检→ProductStatus=InProgress

### 6.3 API 端点

#### GET /api/section-paragraph-flow-analysis

获取段落流转量分析数据（按生产段落上卷，无分页，全量返回）。

**请求参数：** 无

**响应：** `ApiResponse<List<SectionParagraphFlowAnalysisDto>>`

**内部逻辑：**
1. 从 `SectionParagraphConfig` 加载生产段落（按 CategoryType 自动生成，ParagraphKey 唯一，按 DisplayOrder 排序）
2. 按上述 3 类聚合规则将实时 (工序组, 工段) 归入对应段落
3. 调用 `SectionProductionStatusService.GetStatusAsync()` 获取各(工序组,工段)实时待产量（Fixed 类按 ProductStatus 匹配）
4. 按归属段落聚合（/1000 转吨）
5. 计算可持续天数 = PendingTotal / DailyFlowTarget，总况判定（偏少/正常/过多）
6. 计划流转判定：计划流转量 > 日流转设定 → "加速"，否则 "-"
7. 另从批次计划全量数据汇总 PlanFlowQuantity/PlanKeyWeight 与重点批次统计

#### POST /api/section-paragraph-flow-analysis/print-file

打印段落流转量分析（Mode B ⓪：前端已准备数据），请求体 `SectionParagraphFlowAnalysisPrintRequest`（Title/Items/Columns），返回 `File(pdfBytes)`。

1. 按轧机类型组（配置表 ColdRollMachineGroupConfig 定义，配置表驱动，替代原固定 4 组；配置了 SupplyTargetGroupKey 的供给方组拆档取整）聚合
2. 流转总量 = 该类型排程批次近6天量（在轧+待轧，PositionDiff≤6，不含远日），口径与排程汇总一致
3. 在制品/成品按排程产出形态拆分（IsFinished=最后工序组为成品），成品+在制=流转总量
4. 机台需求数 = Σ(规格流转量 ÷ 单机单日量) ÷ 6天，四舍五入得每日台数；供给方组在制/成品各自取整再相加
5. 结果缓存 60 秒，冷轧排程保存（SaveAllAsync）/机台组配置保存·删除会主动失效

#### GET /api/cold-roll-plan/suggestion

获取冷轧排程建议（半自动）。仅产出建议不自动写入；「一键采用」由前端将建议行级 Items 合并未被覆盖的现有行后走既有 `POST /api/cold-roll-spec-schedule/save-all` 全量同步。

**请求参数：** 无

**响应：** `ApiResponse<List<ColdRollScheduleSuggestionDto>>`

**内部逻辑（三步决策）：**
1. **特急锁定**：档1（急+ = IsUrgent ∧ 正常流转 ∧ 关注工序==当前冷轧）批次锁定，档位 ≥ CrOnly
2. **流转保底**：5060 在制/待轧（PositionDiff≤6）经 ProcessGroups 延伸下一 20/30 冷轧组折算流入机台（flowDemand2030），2030 组 minTarget = max(组MinMachines, flowDemand2030)；两阶段对倒——先放宽 5060 在制档位（TierStepWide）喂饱 2030 总负荷，超出 5060 最大机台数再逐档压缩成品档（TierStepNarrow）
3. **产能平衡（统一语义）**：minTarget = isDemander ? max(组MinMachines, demandInflow.Total) : 组MinMachines；沿档位阶梯双向调整——超上限向窄收（Urgent→CrOnly）、不足向宽放（Partial3→All）至 count∈[minTarget,max]；**凡配了 MaxMachines 的组（无论有无供需链）都走产能平衡**——无供需组（三辊/冷拔独立池、或取消供给目标组后的 5060）不再无条件固定 Partial2 纯人工档，超上限标注矛盾 A'、不足标注矛盾 A；未配机台数上限组 no-op（suggestedTier 保持默认原始档，仅行级特急锁定生效）
- 档位阶梯 `TierLadder=[CrOnly,Urgent,Partial2,Partial3,All]`，宽度 0/1/2/3/4；`NormalizeTier`：Partial1→Urgent、Subsequent→All；`MatchesScheduleType`：All/Subsequent→true、CrOnly=档1、Urgent/Partial1=isUrgent∧正常、Partial2=isUrgent、Partial3=isUrgent∨B顺
- 机台数公式 `ComputeMachineCount`：Σ(Weight/(dailyOutput×6m)) 四舍五入；dailyOutput 优先产能档案(方式B)>排程行 DailyOutput>机台数配置 EstimatedDailyOutput(方式A)；PositionDiff≤6 才计
- 结果缓存 60 秒（ScheduleSuggestionCacheKey），排程保存/产能档案保存/机台数配置保存·删除时主动失效
- 矛盾标注交人：A=全量仍不足 / A'=急+锁定已超最大机台数 / B=需求组承接流转 < 最小机台数（可叠加）

### 13.6 冷轧排程在冷轧计划中的使用流程

1. 排程员点击"编辑排程"按钮 → 前端 `EnterSchedulingModeAsync()`
2. 加载已有排程数据：`ColdRollSpecScheduleService.GetAllAsync()`
3. 排程数据映射到 `_scheduleEdits` 字典，按 (ProcessType, BilletSpec, RollingSpec, IsFinished) 为 key
4. UI 上 4 个排程设置列（在轧要求/待轧要求/待轧序/待轧设备号）进入可编辑状态
5. 排程员在各行编辑 MudSelect（CompletionType/RollType）和 MudNumericField（RollOrder）/ MudTextField（SchedMachineNo）
6. 点击"保存排程" → `SaveScheduleAsync()`：
   - 构建 `List<ColdRollSpecScheduleDto>`，一次调用 `ColdRollSpecScheduleService.SaveAllAsync(list)`
   - 简化视图保存时展开到明细级别（`_rawAllItems` 匹配明细行）
   - 保存验证：RollType≠"None" 时 RollOrder 必须 > 0
7. 退出编辑模式后排程数据持久化，下次打开计划自动加载
