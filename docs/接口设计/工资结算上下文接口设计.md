# 工资结算上下文接口设计

**版本：V1.24**
**最后更新：2026-09-04**

> **现行模型**：生产计件为「计件类别 × 维度档」两表模型（PieceRateProductionCategory / PieceRateProductionCategoryTier，单价 = 类别 BasePrice × 命中档 Ratio 连乘，无例外价/绝对价）；旧单表 PieceRateStandard 及其路由 `api/piece-rate-standard`（原 §3.1~§3.12 端点）已删除，「三、计件类别」章按两表模型重写。成检计件独立为「四、成检计件类别」章（`api/piece-rate-final-inspection-category`，定位键 = 成检项目 InspectionItem 单键，无四键约束）。
> **共享采集口径**：个人/集体/靠工月结与模拟测算共用共享采集器 `PieceRateCollector` 计价（生产 4 源 / 成检记录源），杜绝双通道漂移；未定价提醒仅对「已记录到量（Weight/Quantity 任一>0）但命中不到启用类别」的行发出，无产出量（数量空）与命中类别但数量缺失折算 0 → 静默不发工资也不提醒。
> **试算口径**：试算 UI 按真实记录点选计价（生产 = §3.12/§3.13 产量 4 源、成检 = §4.12/§4.13 成检记录）；§3.7/§4.7 手工 match-price 端点保留兼容既有测试（手动填维度试算表单已废弃）。生产 Length 维取数：Cut 行 = 本行 FinishedCutLength；非切行且批 Fixed → 批次最长定尺长；Range/NonFixed/缺 → 6000mm 兜底。

## 二、考勤表（Attendance）

按月获取启用员工 + 当月出勤（月视图网格数据）。

- 参数：`year`(int)、`month`(int)、`keyword`(string?, 员工工号/姓名模糊搜索)

- 返回：`ApiResponse<int>`（保存条数）

## 三、计件类别（PieceRateProductionCategory）

**路由前缀：`api/piece-rate-category`**（构造参数 `IPieceRateProductionCategoryService` + `IPieceRateCategoryImportService`，后者供 §3.8~§3.11 批量导出/模板/预览/导入）

**核心口径（两表模型）**：类别 = 工段(必选单选) × 工序/产类/作业阶段(可空多选，空=全选) + 基准价 + 结算单位，主表 PieceRateProductionCategory；维度系数在子表 PieceRateProductionCategoryTier 档行（**只存系数、不冗余基准，无例外价/绝对价**），类别下实际配了启用档行的维才参与结算（未配置 = 系数 1）。结算单价 = 类别.BasePrice × 各命中档 Ratio 连乘。自动组合名（DisplayName，不落库）= `工段中文｜产类中文集(空=全部产类)｜工序中文集(空=全部工序)｜阶段中文集(空=全部阶段)`，多值以「·」连接。保存校验：同工段启用类别**禁止交集**（覆盖 = 工段×工序域×产类域×阶段域，任一维全选即霸占该维全域）+ 档内同维区间重叠/等值取值去重（仅校验启用行，边界相切 = 合法邻接，定尺维整数共享即重叠）。**匹配唯一性**由禁交集保证：任意一条报工命中启用类别 ≤1；命中 >1 = 禁交集被破坏，防御性报错；命中不到返回 null（= 未定价）。

**导入/导出语义（数据维护闭环）**：定位 = 工段 × 三约束归一组（空=全选）；冲突 = **覆盖更新**。类别定义模板（kind=category）只动主属性（基准价/单位/启停/备注/四键）**绝不清档**；维档系数模板（kind=tier）按定位整组替换该类别 Tiers。任一行非法（定位重复/禁交集/档区间重叠/取值重复/字段不合法）→ 整体拒绝不进事务（有事务回滚标记）。解析同口径中文域值中英容忍，校验复用类别 Service 禁交集/档重叠规约，模板含 1 示例行。

### 3.1 GET api/piece-rate-category

分页查询。

- 权限：`SalaryView`
- 参数：`PieceRateProductionCategoryQueryParams`（PageIndex/PageSize/Keyword/SortBy/IsDescending + `SectionKey`/`Unit` 英文 Key 精确筛选 + `IsActive` 启停筛选）+ 独立 `filters`(string?, 列级筛选 FilterDescriptor 列表 JSON，手动反序列化)
  - `SectionKey`：工段英文 Key（SectionKeys）精确筛选；`Unit`：结算单位英文 Key（PieceRateUnitKeys）精确筛选；`IsActive`：启停（null=全部）
  - `filters`：列级筛选（ExcelFilter 标准模式，`in`/`isnull` 操作符 + `__EXCEL_FILTER_NULL__` 空值哨兵）；布尔/数值/日期列可下推，显示派生列（DisplayName/TierCount 等）忽略
  - `Keyword`：自动组合名 DisplayName（含中文约束名）/工段英文 Key/Remark 子串 Contains（OrdinalIgnoreCase）
  - 排序：全字段（SectionKey/DisplayName/BasePrice/Unit/IsActive/TierCount/Remark/UpdatedTime 等），默认 CreatedTime 降序
- 返回：`ApiResponse<PagedResult<PieceRateProductionCategoryListItemDto>>`（Id/SectionKey/SectionKeyChinese/ProcessKeys/ProductStatusKeys/StageKeys/DisplayName 自动组合名/BasePrice/Unit/UnitChinese/IsActive/TierCount 启用档行数/Remark/CreatedTime/UpdatedTime）

### 3.2 GET api/piece-rate-category/{id}

按 Id 获取详情（含维度档全量，供编辑页）。权限：`SalaryView`。返回 `ApiResponse<PieceRateProductionCategoryDetailDto>`（继承列表行全部字段 + `Tiers` 全部维度档行——含停用行，编辑页需展示；档行按维度声明序 + Id 排序，等值维优先展示取值文本）。

### 3.3 POST api/piece-rate-category

创建类别（定义 + 维档整组，自动组合名不落库）。权限：`SalaryEdit`。请求体 `PieceRateProductionCategorySaveRequest`（SectionKey 必填、中文/Key 归一为英文 Key；ProcessKeys/ProductStatusKeys/StageKeys 可空多选、空=全选、中文归一 Key；BasePrice 必填>0；Unit 必填合法 Key；IsActive 启停；Remark 备注；`Tiers` 全量意图整组替换——Id>0=更新占位、Id=0=新增，实际保存整组替换不依赖 Id）。服务端校验：工段/单位/维度键合法性、基准价>0、档系数>0、区间可解析（定尺维须整数）、同工段启用类别**禁止交集**、档内同维区间重叠/等值取值去重，非法抛 `BusinessException`。返回 `ApiResponse<PieceRateProductionCategoryDetailDto>`。

### 3.4 PUT api/piece-rate-category/{id}

更新类别（改定义 + 停用旧/整组替换维档，Id 由路由传入，请求体 `Id` 恒 0/忽略）。权限：`SalaryEdit`。请求体同 `PieceRateProductionCategorySaveRequest`，校验规则同创建，返回 `ApiResponse<PieceRateProductionCategoryDetailDto>`。

### 3.5 DELETE api/piece-rate-category/{id}

删除类别（级联删子表维档行）。权限：`SalaryDelete`。返回 `ApiResponse<bool>`。

### 3.6 GET api/piece-rate-category/options

类别编辑页下拉选项源（工段/工序/产类/作业阶段/结算单位/特殊制造状态/特殊牌号）。权限：`SalaryView`。

- 返回：`ApiResponse<PieceRateProductionCategoryOptionsDto>`
  - `Sections`：启用工段（StandardWorkDay IsEnabled=true；同一 SectionKey 多行取通用行，Key + 中文名）
  - `Processes`：启用工序（ProcessDefinition IsEnabled=true；Key + 中文名）
  - `ProductStatuses`：产类固定三值（ProductStatuses：荒管/在制/成品）
  - `Stages`：作业阶段（PieceRateStageKeys：InTank=入缸/OutTank=出缸）
  - `Units`：结算单位（PieceRateUnitKeys）
  - `States`：特殊制造状态（PieceRateStateKeys，如 Bright=光亮）
  - `Grades`：特殊牌号候选（StandardGradeMapping.PlantGrade DISTINCT 去重，数据驱动，按牌号对照表新增自动扩展）

### 3.7 POST api/piece-rate-category/match-price

试算匹配（与将来结算同算法）：按一条报工（工段+工序+产类+作业阶段+维度值）在启用类别里命中 ≤1 个类别并返回单价明细；命中不到返回 null（= 未定价）。

- 权限：`SalaryView`
- 请求体：`PieceRateProductionMatchRequest`
  - `SectionName` 工段（英文 Key，必填，来自记录 SectionName）/ `ProcessName` 工序（Key，来自记录 ProcessName）/ `ProductStatus` 产类（Key）/ `Stage` 作业阶段（`InTank`=入缸、`OutTank`=出缸，空=普通报工无阶段）/ `SpecialState` 特殊制造状态（Key，空=普通状态）
  - 维度值：`OuterDiameter`/`WallThickness`/`Length`/`CutRate`（decimal?）、`FixedLengthCount` 定尺种数（int?）、`PlantGrade` 特殊牌号（工厂牌号原文，等值匹配）、`EquipmentName` 设备号（报工文本，等值匹配）
  - `Remark` 报工备注自由文本（可选；仅冷拔类型 ColdDrawType 维按关键词包含命中使用，空=该维系数 1）
- 匹配逻辑：SQL 仅下推 `SectionKey==` + `IsActive` → 键约束（工序/产类/阶段，空=全选放行）内存 OrdinalIgnoreCase 比较 → 命中 >1 = 禁交集被破坏，数据违例防御性报错 → 命中不到 = 未定价返回 null → 档扫描（只扫该类别实际配置了启用档行的维；区间维数值落入多档重叠取区间最窄、值维等值命中、冷拔类型 = Remark 含 MatchValue 关键词命中且最长词优先；未配置/未命中维度 = 系数 1）→ 总系数 TotalRatio = 命中档 Ratio 连乘
- 返回：`ApiResponse<PieceRateProductionMatchResultDto?>`（CategoryId/SectionKey/SectionKeyChinese/DisplayName 自动组合名/BasePrice 类别基准价/TotalRatio 总系数/UnitPrice = BasePrice × TotalRatio/Unit 结算单位/UnitChinese/**SimulatedAmount 整行模拟金额（decimal?；手工填维度无计量字段恒 null，按记录点选计价才有值见 §3.13）**/Hits 命中档明细（DimensionKey/维度中文/RangeText 区间原文或取值/Ratio）/Remark 取命中类别备注；未定价返回 null）

### 3.8 GET api/piece-rate-category/export-all

全量标准导出（备份 / 离线改后再导）。权限：`SalaryView`。

- 返回：xlsx 文件流（`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`），双 sheet——「类别」主定义 +「维档」档行（同导入模板列，中文表头/中文域值，定位与导入解析完全同口径，可直接回导）
- 无参数；空库导出仅表头

### 3.9 GET api/piece-rate-category/import/template?kind=category|tier

下载导入模板。权限：`SalaryView`。

- 参数：`kind` 必填——`category`=类别定义模板（工段/工序/产类/阶段/基准价/结算单位/启用/备注）、`tier`=维档系数模板（定位四键 + 维度/档值/系数/启用），含 1 示例行（中文域值）
- 返回：xlsx 文件流

### 3.10 POST api/piece-rate-category/import/preview

上传文件做预检（不落库），返回行级统计与错误/覆盖明细。权限：`SalaryView`。

- 请求体：multipart/form-data，字段 `kind`（category|tier）+ 文件 `file`（.xlsx，表头按名称匹配、列序无关、少列允许）
- 返回：`ApiResponse<ImportPreviewResult>`（TotalRows/ValidCount/ErrorCount/AddCount/OverwriteCount + RowResults 逐行——RowNumber/Key/IsValid/IsDuplicate/RowAction 新增|覆盖|忽略/Errors 错误明细）
  - 类别模板：定位命中既有启用/停用类别 → 覆盖（不动档行）；未命中 → 新增（无档行）
  - 维档模板：定位类别不存在 → 整行报错「请先导入类别定义」；存在 → 覆盖（整组替换意图）
  - 任一行非法 → ErrorCount>0，明细标注该行所有错误

### 3.11 POST api/piece-rate-category/import

正式导入（事务内覆盖更新，与预览同口径校验）。权限：`SalaryEdit`。

- 请求体：同 §3.10（multipart/form-data，`kind` + `file`）
- 返回：`ApiResponse<ImportResult>`（SuccessCount/FailedCount/HasRolledBack 整体回滚标记/RollbackReason 回滚原因/Errors）
  - 校验含文件内同定位重复、「禁止交集」等完整规约（与页面创建/编辑完全同口径，防漂移）；任一行非法或回滚理由成立 → `HasRolledBack=true` 整批不落库
  - 类别定义导入：只改主属性 + 四键（不动档行）；维档导入：按定位整组替换 Tiers
  - 成功行落库后 CreatedBy/UpdatedBy = 当前登录用户

### 3.12 GET api/piece-rate-category/trial-records

模拟测算候选产量记录浏览（**全局任意跨期记录**）。权限：`SalaryView`。

- 参数：`PieceRateProductionTrialRecordQuery`（PageIndex/PageSize + `Source` 产量源英文名必填（`ProductionRecord` 生产记录 / `PicklingIn` 去油酸洗入缸 / `PicklingOut` 去油酸洗完工 / `ProcessInspection` 过程检验，大小写不敏感，缺/非法 → `BusinessException`「请选择产量源/无效的产量源」）+ `Keyword` 关键字）

## 四、成检计件类别（PieceRateFinalInspectionCategory）

**路由前缀：`api/piece-rate-final-inspection-category`**（构造参数 `IPieceRateFinalInspectionCategoryService` + `IPieceRateFinalInspectionCategoryImportService`，后者供 §4.8~§4.11 批量导出/模板/预览/导入）

**核心口径（独立模块）**：成检（成品检验）岗位计件类别。与生产计件彻底分表：主表 `PieceRateFinalInspectionCategory` 以**成检项目（InspectionItem 9 项，单选）单键定位**（无「工段/工序/产类/作业阶段」四键约束、无跨项目覆盖禁交集——不同项目天然互斥）；子表 `PieceRateFinalInspectionCategoryTier` 为 8 维档（只存系数连乘，不冗余基准）。结算单价 = 类别.BasePrice × 各命中档 Ratio 连乘。类别更新 = 档行**整组替换**；停用旧类别可新建同项目新启用类别。**同项目启用唯一**：同一成检项目同时仅一条启用类别（服务端预检 + DB 过滤唯一索引 `UK_FinalInspectionCategory_Item_Active` 兜底）；命中 >1 = 数据违例防御性报错，命中不到返回 null（= 未定价）。三个与生产计件共用规则沿用：①计价=基准 × 系数连乘，无例外价/绝对价；②调价=停用+新建（工资流水快照）；③结算数量折算沿用 `PieceRateUnitKeys.QuantityDimension`。

**8 维档（`PieceRateInspectionDimensionKeys`）**：区间 4 维——外径/壁厚/长度（`MinValue/MaxValue` decimal）、检验支数（`MinInt/MaxInt` int）；等值 4 维——长度状态（LengthStatus：Fixed=定尺/Range=范围尺/NonFixed=非定尺）/特殊牌号（PlantGrade）/特殊制造状态（PieceRateStateKeys）/特殊设备号（EquipmentName 文本等值）。⚠️ 检验支数**整数闭区间**分段：共享边界整数即判重叠（`1-10` 与 `10-100` 冲突），邻接高档须从低档末值+1 起（`1-10` 后接 `11-100`/`11-9999`）；**勿用开区间 `>N`**（`PieceRateRangeParser` 对开区间按闭端点解析，与相邻闭带共享整数会判重叠），表达「N 以上」写 `{N+1}-9999`。十进制区间边界点相切 = 合法邻接（`41-54` 与 `>54`）。

**导入/导出语义（数据维护闭环）**：定位 = 成检项目（OrdinalIgnoreCase，启用优先）；冲突 = **覆盖更新**。类别定义模板（kind=category）只动主属性（基准价/单位/启停/备注）**绝不清档**；维档系数模板（kind=tier）按定位整组替换该类别 Tiers。任一行非法（文件内重复定位/同项目启用唯一违例/区间重叠/等值重复/字段不合法）→ 整体拒绝不进事务。解析同口径中文域值中英容忍（`EnumHelper.TryParse` 归一），模板含 1 示例行（示例用「当前无类别」项目 + 启用=否，原样导入不误覆盖/不误计价）。

## 五、每日工资（PayrollDailyWage）

**路由前缀：`api/payroll-daily-wage`**（构造参数 `IPayrollDailyWageService`）

**核心口径**：仿考勤表月视图的每日工资两表——**非计件工资**（组 NonPiece = Hourly 计小时 + Daily 计日）与**个人计价工资**（组 IndividualPiece = PieceIndividual 个人计件），由路由 `/payroll/wages/non-piece`、`/payroll/wages/piece` 分别携带组。单元格 = 每日工资额；**引擎自动带出当日值** + 人工可改 +「保存本月」落库为归口快照。存储单张共享表 `PayrollDailyWageRecords`（`SalaryMode` = 保存时计薪模式快照，员工日后换归口历史仍按快照显示可回溯）。固定月薪 Fixed 不按日出、靠工计件（PieceAttendance）另行规划，均不进本表；**集体计件（PieceCollective）不按日出，走 §六 月度集体结算**。员工集合 =（档案归口 ∈ 组 的启用员工）∪（当月已有记录且记录 SalaryMode ∈ 组 的员工）。

> **个人计件引擎口径（GET month 的 DayEngineAmount 语义）**：取数源 **5 类** = 生产记录 `ProductionRecords`（生产类别·Stage 无）+ 去油/酸洗入缸 `PicklingInRecords`（Stage=InTank）+ 去油/酸洗完工 `PicklingOutRecords`（Stage=OutTank）+ 过程检验 `ProcessInspections`（生产类别·Inspection 工段·操作人=Inspector）+ 成检 `FinalInspections`（成检类别，Range/NonFixed 单支长 6000mm 兜底）。归属 = **写名总人头为分母**（`OperatorNameHelper` 逐段解析人头，不分身份）——每份 = 行额/总人头，只给命中「个人计件」员工累加；时间基准方（靠工/计时/日薪/月薪）记 0 不发放；集体计件不按日出、走 §六 月度集体结算，不进本引擎。金额 = 命中现行启用类别单价（生产四键 / 成检项目单键）× 命中维档系数连乘，PerTon=kg/1000×价、PerPiece=支数×价、PerKm=支×mm/1e6×价；命中不到/缺数量 → 0 元进 Warnings；命中 >1 → 数据违例。

- 返回：`ApiResponse<int>`（保存条数）

## 六、集体计件月结（PayrollCollective）

**路由前缀：`api/payroll-collective`**（构造参数 `IPayrollCollectiveService`）

**核心口径**：**集体=岗位 × 月度评分 × 月结快照**，适用于 `SalaryMode=PieceCollective` 员工，**最终工资按月确定**（非按日）。

- **集体边界 = 岗位 Position**：一个集体 = 员工管理同一 Position 下、当前在册且 `PieceCollective` 的员工集合（换岗/停用当月自动退出，历史月按快照仍显示可回溯）。**同岗位非集体计件者不计入**。
- **岗位池总额（GET month 的 PoolAmount）**：复用 §五 同一条 **5 类取数源**计价扫描（个人日结/集体月结共用共享采集器 `PieceRateCollector`，防双通道口径漂移）——凡当月行有 ≥1 名在册集体成员写名 → 按现行启用类别折算行额 ÷ 写名总人头（分母不分身份），**仅把集体成员的份额归到其岗位池**；非集体者份记 0（其按本人通道结算）；纯非集体行整行跳过。历史月按结算时现行单价估算。
- **分配**：成员权重 `w = 当月考勤实出勤小时(AttendanceRecord 求和) × 月度分值(1–10，1 位小数如 8.5)`；`个人月得 = 池 × w ÷ Σ同岗位成员 w`。无出勤/未评分 → w=0 → 得 0，页面行内标注补齐后「引擎重算」。
- **评分/出勤快照**：月结保存时把 `Position/Score/AttendanceHours` 冻结进月结记录（员工日后换岗/改评分不影响已存，需显式「引擎重算」再覆盖）。

### 6.1 GET api/payroll-collective/month

按月获取各岗位集体结算卡片（含引擎草稿 + 已保存快照双值）。

- 权限：`SalaryView`
- 参数：`year`(int)、`month`(int)
- 返回：`ApiResponse<CollectiveMonthDto>`（Year/Month + `HasSaved` 当月是否有已保存月结快照 + `Groups` 岗位结算卡片 + `Warnings` 引擎提示）
  - `CollectiveGroupDto`：`Position`（岗位 Key）/ `PoolAmount`（岗位池）/ `SumWeight`（Σ 出勤×分值）/ `Members`
  - `CollectiveMemberDto`：EmployeeId/Code/Name/Position + `EngineCovered`（是否当前在册集体成员，引擎重算只覆盖这些）+ `Score decimal?`（分值 1–10、1 位小数如 8.5，未评分=null）/ `AttendanceHours`（出勤，历史快照员工=冻结值）/ `Weight`（w=出勤×分值，无出勤或未评分=0）/ `EngineAmount`（引擎分配月得草稿，历史快照员工=null）/ `SavedAmount`（当月已存月结，无记录=null）
  - 员工集合 =（当前在册且 Position 非空且 PieceCollective）∪（当月已有月结记录的员工，历史回溯）；打开默认显示 = `HasSaved ? SavedAmount : EngineAmount`（**页面显示/录入整元** RoundYuan 四舍五入、0 清空；API/引擎返回完整精度防丢尾差）
- Warnings 含未定价行提示：`{年}年{月}月有 N 行产量/检验记录到数量但未匹配到计件单价（按0元计）`

### 6.2 POST api/payroll-collective/month/save

整月保存（Amount>0 存/更新、空或 ≤0 删除）。

- 权限：`SalaryEdit`
- 请求体：`SaveCollectiveMonthDto`（Year/Month + `Entries` 逐成员 `CollectiveMonthEntryDto{EmployeeId, Amount decimal?}`）
- 服务端：当月成员集合 upsert；新插行按保存时当前档案记 `Position`（无岗位 = 空串）+ 当月 `Score/AttendanceHours` 快照冻结；既有记录更新仅 Amount（快照不漂移）
- 返回：`ApiResponse<int>`（保存条数）

### 6.3 GET api/payroll-collective/scores

按月获取月度评分员工行（= 当前在册集体成员 ∪ 当月已有评分历史员工补集，各含岗位 + 已评分值）。

- 权限：`SalaryView`
- 参数：`year`(int)、`month`(int)
- 返回：`ApiResponse<CollectiveScoresDto>`（Year/Month + `Rows` 员工行 `CollectiveScoreRowDto{EmployeeId, Code, Name, Position, Score decimal?}`（1 位小数如 8.5））

### 6.4 POST api/payroll-collective/scores/save

整月保存评分（有值 upsert、null 删除）。

- 权限：`SalaryEdit`
- 请求体：`SaveCollectiveScoresDto`（Year/Month + `Entries` 逐员工 `CollectiveScoreEntryDto{EmployeeId, Score decimal?}`（1 位小数如 8.5））
- 服务端：`Score` 越界或超位（<1 或 >10 或 >1 位小数）抛 BusinessException `月度分值须在 1–10 且最多 1 位小数: {score}`；null 删除当月记录（无记录则不动）；评定机制业务自理，系统仅录入
- 返回：`ApiResponse<int>`（保存条数）

## 七、靠工计件月结（PayrollAttendance）

**路由前缀：`api/payroll-attendance`**（构造参数 `IPayrollAttendanceService`）

**核心口径**：**靠工 = 靠工岗位 × 本人出勤 × 靠工系数**，适用于 `SalaryMode=PieceAttendance` 员工，**最终工资按月确定**（非按日）。靠工不与集体/个人分配冲突——靠工按「小时参照」另计、不抽岗位池份子（个人/集体份额仍归计件员工本人），业务定稿公式。

- **靠工工资（月） = 靠工岗位当月平均小时工资 × 本人当月实出勤小时 × 本人靠工系数**；平均小时工资 = 选中靠工岗位（**只计算件：个人计件 + 集体计件并集**）当月计件总工资 ÷ 同批岗位计件人员总出勤小时（**分子分母各自合并**成单一时薪，多岗位不逐岗重复计酬）。
- **员工管理配置**：员工「靠工系数」前新增**「靠工岗位」多选列**（`AttendancePositions nvarchar(200)`，岗位英文 Key 逗号串），候选 = **计件活岗动态**（当前在册存在 个人计件/集体计件 员工的岗位）。
- **引擎取值**：`positionPay[p]`（当月计件总工资，对在册计件员工 5 源扫描 `share=行额/写名总人头` 后按档案岗位累加）+ `positionHours[p]`（计件员工当月出勤和，非计件者出勤**不进分母**）；`avg(S)=Σ positionPay ÷ Σ positionHours`（选中岗位集合 S），`引擎月额 = avg × 本人出勤 × 系数`。
- **边界告警（Warnings）**：靠工岗位为空（未配岗）/ 选中岗位当月无计件出勤或产值（分母 0）→ avg null、引擎额 null、提示补岗；本人无出勤 → 引擎额 0。
- **快照**：月结保存把 `AttendancePositions/AttendanceHours/AttendanceCoefficient` 冻结进月结记录（员工日后换岗/换模式不影响已存，需显式「引擎重算」再覆盖）；保存金额 `Amount>0` 存/更新、空或 ≤0 删除。

### 7.0 关联端点 GET api/employee/piece-positions（员工上下文）

- 权限：`ScanView`
- 返回：`ApiResponse<List<string>>`（岗位英文 Position Key 列表 = 当前在册 `IsActive && Position 非空 && SalaryMode ∈ {PieceIndividual, PieceCollective}` 员工的 Position Distinct，OrdinalIgnoreCase 去重）

### 7.1 GET api/payroll-attendance/month

按月获取靠工计件员工月结网格（含引擎草稿 + 已保存快照双值）。

- 权限：`SalaryView`
- 参数：`year`(int)、`month`(int)
- 返回：`ApiResponse<AttendanceWageMonthDto>`（Year/Month + `HasSaved` 当月是否有已保存月结快照 + `Rows` 员工行 + `Warnings` 引擎提示）
  - `AttendanceWageRowDto`：EmployeeId/EmployeeCode/EmployeeName + `AttendancePositions`（靠工岗位 Key 逗号串）/ `EngineCovered`（是否当前在册靠工员工，引擎重算只覆盖这些）+ `AttendanceHours`（本人当月出勤，历史快照员工=冻结值）/ `AttendanceCoefficient`（靠工系数）/ `AvgHourlyWage`（合并平均时薪，分母 0=null）/ `EngineAmount`（引擎草稿，历史快照员工=null）/ `SavedAmount`（当月已存月结，无记录=null）

- Warnings 含未定价行提示：`{年}年{月}月有 N 行产量/检验记录到数量但未匹配到计件单价（按0元计，可能影响靠工参照时薪）`

### 7.2 POST api/payroll-attendance/month/save

- 权限：`SalaryEdit`
- 请求体：`SaveAttendanceWageDto`（Year/Month + `Entries` 逐员工 `AttendanceWageEntryDto{EmployeeId, Amount decimal?}`）

## 八、杂辅工记录（PayrollMiscWork）

杂项辅助工作手工登记台账控制器 `api/payroll-misc-work`（类级 `[Authorize]`，无业务逻辑纯转发）。**口径**：金额 = 手工录入源头、保留小数不取整（Hours decimal(18,1) 支持 1.5/7.5、Amount decimal(18,2)）；**每人每天可多条**（无唯一索引，一条 = 一段任务）。已并入月工资汇总：月汇总对当月杂辅求和计入员工应发（见「月工资汇总」章），本章保持逐条登记台账口径。

### 8.2 POST api/payroll-misc-work/record

## 九、津贴与处罚（PayrollAllowance）

津贴与处罚月度录入控制器 `api/payroll-allowance`（类级 `[Authorize]`，无业务逻辑纯转发）。**口径**：月度金额网格——行=员工、列=固定 9 个金额项目（满勤奖/工龄奖/夜班津贴/岗位补贴/高温费/工伤补贴/带班费/处罚/代缴社保，列元数据集中 `PayrollAllowanceItems.All`），存储为宽表固定 9 列 `PayrollAllowanceRecord`（每人每月一行，EmployeeId+Year+Month **唯一**，与 Excel 同构）；金额**强制整元**（RoundYuan AwayFromZero、空/0=null 等价未填、**禁负数**，服务端 NormalizeAmount 权威规约单点执行）；月历 = IsActive 在册员工 ∪ 当月已有记录员工（停用员工当月历史行仍显示可改）。已并入月工资汇总：月汇总读取本表 9 字段——应发含 7 项正津贴、实发含处罚/代缴取负（见「月工资汇总」章），本章保持月度登记口径。

### 9.1 GET api/payroll-allowance/month

按月读取津贴网格（员工行 + 9 金额项目，无行值即 null）。

- 权限：`SalaryView`
- 参数：`year`/`month`（FromQuery）
- 服务端：校验月份（<2000 或非 1–12 抛）；在册员工 Id ∪ 当月行员工 Id（含停用）`Distinct` 拉员工映射（`Chunk(1000)`，查不到 Code/Name 兜底 `-`）；当月行 `Where(Year&&Month)` 并入（停用员工历史行回显、IsActive=false）；铺行按 工号(OrdinalIgnoreCase)+Id 稳定升序
- 返回：`ApiResponse<AllowanceMonthDto>`（`Rows` 员工行 = EmployeeCode/EmployeeName/PositionCategory/Position/PositionRemark/SalaryMode/IsActive + FullAttendanceBonus…SocialSecurity 9 值；合计由前端 tfoot 现算，不冗余入库）

### 9.2 POST api/payroll-allowance/month/save

- 请求体：`SaveAllowanceMonthDto`（Year/Month + `Rows: AllowanceRowInputDto[]`，行=EmployeeId + 9 值）

- 返回：`ApiResponse<int>`（已保存员工行数）
