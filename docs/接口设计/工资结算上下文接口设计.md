# 工资结算上下文接口设计

**版本：V1.8**
**最后更新：2026-09-02**

> ⚠️ 2026-09-02：生产计件旧「PieceRateStandard 单表 + DimensionKey 因子/例外价（OnePrice）行」模型已重构为「计件类别 × 维度档」两表模型（PieceRateProductionCategory / PieceRateProductionCategoryTier，无例外价/绝对价）。旧控制器与其路由 `api/piece-rate-standard`（原 §3.1~§3.12 全部端点）已随单表模型删除，「三、计件类别」章按新接口重写；V1.0~V1.7 为该旧接口演化史，随重构作废。

## 一、概述

本文档定义工资结算上下文（Payroll Context）的接口设计，独立主菜单 + 独立 RBAC 三档角色（`SalaryViewer/SalaryEditor/SalaryFull`，策略 `SalaryView/SalaryEdit/SalaryDelete`，Admin 全权）。包含两个控制器：

| # | 控制器 | 路由前缀 | 端点个数 | 说明 |
|---|--------|---------|---------|------|
| 1 | Attendance | `api/attendance` | 2 | 考勤表月视图读取/整月保存 |
| 2 | PieceRateProductionCategory | `api/piece-rate-category` | 7 | 计件类别（工段×工序/产类/作业阶段 + 基准价 + 维档系数）CRUD + 编辑页选项 + 试算匹配 |

### DTO 清单

|-----|------|------|
| AttendanceMonthDto / SaveAttendanceDto / AttendanceCellDto | `MES.Core/DTOs/Payroll/AttendanceDtos.cs` | 考勤表月视图 |

## 二、考勤表（Attendance）

**路由前缀：`api/attendance`**（构造参数 `IAttendanceService`）

### 2.1 GET api/attendance/month

按月获取启用员工 + 当月出勤（月视图网格数据）。

- 权限：`SalaryView`
- 参数：`year`(int)、`month`(int)、`keyword`(string?, 员工工号/姓名模糊搜索)
- 返回：`ApiResponse<AttendanceMonthDto>`（员工行 + 天数列 + 出勤小时，稀疏存储，有值才落库）

### 2.2 POST api/attendance/save

整月保存（有值 upsert、清空删除）。

- 权限：`SalaryEdit`
- 请求体：`SaveAttendanceDto`
- 返回：`ApiResponse<int>`（保存条数）

## 三、计件类别（PieceRateProductionCategory）

**路由前缀：`api/piece-rate-category`**（构造参数 `IPieceRateProductionCategoryService`）

**核心口径（2026-09-02 两表模型，替代旧单表 PieceRateStandard）**：类别 = 工段(必选单选) × 工序/产类/作业阶段(可空多选，空=全选) + 基准价 + 结算单位，主表 PieceRateProductionCategory；维度系数在子表 PieceRateProductionCategoryTier 档行（**只存系数、不冗余基准，无例外价/绝对价**），类别下实际配了启用档行的维才参与结算（未配置 = 系数 1）。结算单价 = 类别.BasePrice × 各命中档 Ratio 连乘。自动组合名（DisplayName，不落库）= `工段中文｜产类中文集(空=全部产类)｜工序中文集(空=全部工序)｜阶段中文集(空=全部阶段)`，多值以「·」连接。保存校验：同工段启用类别**禁止交集**（覆盖 = 工段×工序域×产类域×阶段域，任一维全选即霸占该维全域）+ 档内同维区间重叠/等值取值去重（仅校验启用行，边界相切 = 合法邻接，定尺维整数共享即重叠）。**匹配唯一性**由禁交集保证：任意一条报工命中启用类别 ≤1；命中 >1 = 禁交集被破坏，防御性报错；命中不到返回 null（= 未定价）。

### 3.1 GET api/piece-rate-category

分页查询。

- 权限：`SalaryView`
- 参数：`PieceRateProductionCategoryQueryParams`（PageIndex/PageSize/Keyword/SortBy/IsDescending + `SectionKey`/`Unit` 英文 Key 精确筛选 + `IsActive` 启停筛选）+ 独立 `filters`(string?, 列级筛选 FilterDescriptor 列表 JSON，手动反序列化)
  - `SectionKey`：工段英文 Key（SectionKeys）精确筛选；`Unit`：结算单位英文 Key（PieceRateUnitKeys）精确筛选；`IsActive`：启停（null=全部）
  - `filters`：列级筛选（ExcelFilter 标准模式，`in`/`isnull` 操作符 + `__EXCEL_FILTER_NULL__` 空值哨兵）；布尔/数值/日期列可下推，显示派生列（DisplayName/TierCount 等）忽略
  - `Keyword`：自动组合名 DisplayName（含中文约束名）/工段英文 Key/Remark 子串 Contains（OrdinalIgnoreCase）
  - 排序：全字段（SectionKey/DisplayName/BasePrice/Unit/IsActive/TierCount/Remark/UpdatedTime 等），默认 CreatedTime 降序
- 返回：`ApiResponse<PagedResult<PieceRateProductionCategoryListItemDto>>`（Id/SectionKey/SectionKeyChinese/ProcessKeys/ProductStatusKeys/StageKeys/DisplayName 自动组合名/BasePrice/Unit/UnitChinese/IsActive/TierCount 启用档行数/Remark/CreatedTime/UpdatedTime）

### 3.2 GET api/piece-rate-category/{id}

按 Id 获取详情（含维度档全量，供编辑页）。权限：`SalaryView`。返回 `ApiResponse<PieceRateProductionCategoryDetailDto>`（继承列表行全部字段 + `Tiers` 全部维度档行——含停用行，编辑页需展示；档行按维度声明序 + Id 排序，等值维优先展示取值文本）。

### 3.3 POST api/piece-rate-category

创建类别（定义 + 维档整组，自动组合名不落库）。权限：`SalaryEdit`。请求体 `PieceRateProductionCategorySaveRequest`（SectionKey 必填、中文/Key 归一为英文 Key；ProcessKeys/ProductStatusKeys/StageKeys 可空多选、空=全选、中文归一 Key；BasePrice 必填>0；Unit 必填合法 Key；IsActive 启停；Remark 备注；`Tiers` 全量意图整组替换——Id>0=更新占位、Id=0=新增，实际保存整组替换不依赖 Id）。服务端校验：工段/单位/维度键合法性、基准价>0、档系数>0、区间可解析（定尺维须整数）、同工段启用类别**禁止交集**、档内同维区间重叠/等值取值去重，非法抛 `BusinessException`。返回 `ApiResponse<PieceRateProductionCategoryDetailDto>`。

### 3.4 PUT api/piece-rate-category/{id}

更新类别（改定义 + 停用旧/整组替换维档，Id 由路由传入，请求体 `Id` 恒 0/忽略）。权限：`SalaryEdit`。请求体同 `PieceRateProductionCategorySaveRequest`，校验规则同创建，返回 `ApiResponse<PieceRateProductionCategoryDetailDto>`。

### 3.5 DELETE api/piece-rate-category/{id}

删除类别（级联删子表维档行）。权限：`SalaryDelete`。返回 `ApiResponse<bool>`。

### 3.6 GET api/piece-rate-category/options

类别编辑页下拉选项源（工段/工序/产类/作业阶段/结算单位/特殊制造状态/特殊牌号）。权限：`SalaryView`。

- 返回：`ApiResponse<PieceRateProductionCategoryOptionsDto>`
  - `Sections`：启用工段（StandardWorkDay IsEnabled=true；同一 SectionKey 多行取通用行，Key + 中文名）
  - `Processes`：启用工序（ProcessDefinition IsEnabled=true；Key + 中文名）
  - `ProductStatuses`：产类固定三值（ProductStatuses：荒管/在制/成品）
  - `Stages`：作业阶段（PieceRateStageKeys：InTank=入缸/OutTank=出缸）
  - `Units`：结算单位（PieceRateUnitKeys）
  - `States`：特殊制造状态（PieceRateStateKeys，如 Bright=光亮）
  - `Grades`：特殊牌号候选（StandardGradeMapping.PlantGrade DISTINCT 去重，数据驱动，按牌号对照表新增自动扩展）

### 3.7 POST api/piece-rate-category/match-price

试算匹配（与将来结算同算法）：按一条报工（工段+工序+产类+作业阶段+维度值）在启用类别里命中 ≤1 个类别并返回单价明细；命中不到返回 null（= 未定价）。

- 权限：`SalaryView`
- 请求体：`PieceRateProductionMatchRequest`
  - `SectionName` 工段（英文 Key，必填，来自记录 SectionName）/ `ProcessName` 工序（Key，来自记录 ProcessName）/ `ProductStatus` 产类（Key）/ `Stage` 作业阶段（`InTank`=入缸、`OutTank`=出缸，空=普通报工无阶段）/ `SpecialState` 特殊制造状态（Key，空=普通状态）
  - 维度值：`OuterDiameter`/`WallThickness`/`Length`/`CutRate`（decimal?）、`FixedLengthCount` 定尺种数（int?）、`PlantGrade` 特殊牌号（工厂牌号原文，等值匹配）、`EquipmentName` 设备号（报工文本，等值匹配）
- 匹配逻辑：SQL 仅下推 `SectionKey==` + `IsActive` → 键约束（工序/产类/阶段，空=全选放行）内存 OrdinalIgnoreCase 比较 → 命中 >1 = 禁交集被破坏，数据违例防御性报错 → 命中不到 = 未定价返回 null → 档扫描（只扫该类别实际配置了启用档行的维；区间维数值落入多档重叠取区间最窄、等值维等值命中；未配置/未命中维度 = 系数 1）→ 总系数 TotalRatio = 命中档 Ratio 连乘
- 返回：`ApiResponse<PieceRateProductionMatchResultDto?>`（CategoryId/SectionKey/SectionKeyChinese/DisplayName 自动组合名/BasePrice 类别基准价/TotalRatio 总系数/UnitPrice = BasePrice × TotalRatio/Unit 结算单位/UnitChinese/Hits 命中档明细（DimensionKey/维度中文/RangeText 区间原文或取值/Ratio）/Remark 取命中类别备注；未定价返回 null）
