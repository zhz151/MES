## 1. 概述

看板上下文是纯查询聚合层，**不创建新表**，从多个现有上下文读取数据并在首页聚合展示。

### 核心原则

| 原则 | 说明 |
|------|------|
| **不建新表** | 看板没有自己的 Entity/DbSet |
| **纯只读** | 看板页面没有任何新增/编辑/删除操作 |
| **首页即看板** | 登录首页（Index.razor）是唯一的看板页面，桌面端 = 常用入口磁贴卡 + 「订单进度查询」「生产批次进度查询」两张查询卡**上下堆叠、各约半屏宽居中**；手机端 = 同样三卡纵向堆叠（全宽，`mh-*` 体系）。**V3.16 起「订单负荷实时状况」卡已从首页删除** |
| **跳转只在入口区** | V3.11 起**卡片内不再挂链接**（阶段名/数值为纯展示），跳转一律走顶部「常用入口」磁贴或侧栏菜单，避免正文里散落写死的详情页路径；两张查询卡更进一步——**结果就地渲染、不跳转** |
| **不重复报表** | 首页只放"查询入口 + 就地结果"，**不出现常驻的可排序多列明细表**（明细/筛选/打印归「报表总览」） |
| **不重复菜单** | 常用入口是**菜单子集的高频投影**（11 条，非全量 90 叶复刻），Href/Label/有效策略与 `AppMenu` 严格一致，可见性与侧栏菜单相同 |
| **无中间层** | **V3.16 起 Index.razor.cs 零业务调用**（仅 `IsMobile` 级联参数），取数下沉到各子卡自身；无 DashboardService 中间层 |

### 定位

> **首页回答管理层核心问题："今天工厂怎么样？"**
>
> 点击卡片 → 进入对应功能页查看明细，无需在 Dashboard 上下文中重建。

## 5. 目录结构

```
MES.Blazor
  ├─ Pages
  │    ├─ Index.razor                   ← 首页（常用入口磁贴卡 + 订单进度查询卡 + 生产批次进度查询卡）
  │    └─ Index.razor.cs                ← V3.16 起仅 IsMobile 级联参数，零 Service 注入
  ├─ Shared
  │    ├─ AppShortcuts.cs               ← 常用入口静态清单（V3.9，菜单子集投影；V3.11 换成 AppShortcut 记录并加 Icon/Accent）
  │    ├─ OrderProgressQueryCard.razor(.cs)    ← 首页「订单进度查询」卡（2026-09-14）
  │    ├─ BatchProgressQueryCard.razor(.cs)    ← 首页「生产批次进度查询」卡（2026-09-14）
  │    ├─ OrderProgressTree.razor(.cs/.css)    ← 订单进度树（首页 Compact 态与 /orders/progress 页共用，2026-09-14 由 OrderProgress.razor 整文件迁出）
  │    └─ BatchProgressCard.razor(.cs)         ← 批次执行进度卡（2026-09-10 由批次详情/两计划页共用，首页查询卡复用）
  └─ Services                           ← 各子卡自行注入业务 Service（Index 不再直接使用）
       ├─ Order/OrderProgressService.cs
       └─ Batch/BatchService.cs
```

## 6. 依赖的实体

所有数据均来自现有上下文，Dashboard 不需要新增 Entity。

| Service | 所属上下文 | 用途 |
|---------|-----------|------|
