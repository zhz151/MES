## 0. 目标与背景

取代旧「计件标准单表 + 维度因子行」模型（`PieceRateStandards` + `DimensionKey` 因子/例外价平铺）。彻底解决：
- 产类被塞成行内乘性维，无法表达「荒管/非荒管各成体系、基准相差数倍」的水平差；
- 例外价（OnePrice）绝对价不随基准、且为多维重叠区写死绝对价，阻碍加维演进；
- 维度因子行随组合数膨胀（笛卡尔积）。

**三个不可动摇的规则（业务定稿）**：
1. 计件标准分两大类、两张独立表族：**生产计件** / **成检计件**（本文档仅覆盖生产计件；成检计件已于 2026-09-03 独立重建，见《成检计件详细设计.md》）。
2. 计价 = 类别基准价 × 各命中档系数连乘 × 补充档命中比值。**不存在「例外价 / 绝对价」选项**——一切价格必须能表达为「基准 × 系数」。
3. 类别匹配**禁止交集**：任意两条启用类别覆盖空间不得重叠。

## 1. 领域模型总览

```
计件类别（生产） = 工段(必选·单选) + 工序(可选·多选·空=全选)
                 + 产类(可选·多选·空=全选) + 作业阶段(可选·多选·空=全选)
                 + 基准价(必填) + 结算单位(必填)
     │  1
     ├─ 维度档（0..n） 基础档：外径/壁厚/长度/断切率/定尺 → 区间 + 比值
     │                             补充档：特殊牌号/特殊制造状态/设备号 → 等值 + 比值
     └─ 无启用维度集合（类别下实际配了档行的维才参与结算）
```

**键来源（全部落现成配置/枚举）**：
- 工段：`StandardWorkDay`（SectionKey，仅 IsEnabled=true 者可选）；
- 工序：`ProcessDefinition`（ProcessKey，仅 IsEnabled=true 者可选）；
- 产类：`ProductStatuses` 固定三值（荒管/在制/成品）；
- 作业阶段：本阶段先两枚——`InTank`=入缸、`OutTank`=出缸（酸洗/去油专用；其它工段类别此键留空）。
- 牌号补充档：`StandardGradeMapping.PlantGrade`（工厂牌号，与报工 PlantGrade 同源等值匹配）；
- 状态补充档：`PieceRateStateKeys`（先一枚 `Bright`=光亮）；
- 设备补充档：报工 `EquipmentName` 设备号文本（暂未规范到设备表，见 §9-7）。

## 2. 数据模型

### 2.1 PieceRateProductionCategory —— 生产计件类别（主表）

| 列 | 类型 | 说明 |
|---|---|---|
| Id | int PK | |
| SectionKey | nvarchar(50) | 工段，必填，单选（StandardWorkDay.SectionKey） |
| BasePrice | decimal(18,4) | 基准价，必填，>0 |
| Unit | nvarchar(20) | 结算单位，必填（PieceRateUnitKeys） |
| IsActive | bit | 启用/停用 |
| Remark | nvarchar(200)? | 备注 |

继承 BaseEntity。索引：`IX_Category_Section`（SectionKey + IsActive）。**工序/产类/阶段三约束不在主表**（2026-09-02 V1.2 实体化）：由关系成员子表 `PieceRateProductionCategoryKey`（见 §2.3）承载，0 成员行 = 该维全选。原主表三 JSON 数组列 `ProcessKeys/ProductStatusKeys/StageKeys` 已删除（迁移 20260902120723 回填 18 成员行后 DropColumn）。

### 2.2 PieceRateProductionCategoryTier —— 类别维度档（子表）

| 列 | 类型 | 说明 |
|---|---|---|
| Id | int PK | |
| CategoryId | int FK | 所属类别 |
| DimensionKey | nvarchar(30) | OuterDiameter / WallThickness / Length / CutRate / FixedLengthCount / SpecialGrade / SpecialState / SpecialDevice / ColdDrawType |
| RangeText | nvarchar(100)? | 区间原文（如 `D>54`、`54≥D>41`）或取值文本 |
| MinValue / MaxValue | decimal? | 区间维（数值边界） |
| MinInt / MaxInt | int? | 定尺维（整数边界） |
| MatchValue | nvarchar(100)? | 等值补充档（牌号/状态/设备号）取值；冷拔类型 = 备注关键词 |
| Ratio | decimal(18,6) | 加价系数（命中即乘；默认 1） |
| IsActive | bit | 启用/停用 |

继承 BaseEntity。索引：`IX_Tier_Category`（CategoryId）。

**关键**：基准价只存在类别上；维档行**只存系数、不冗余基准**。结算单价 = 类别.BasePrice × 命中行 Ratio 连乘。

### 2.3 PieceRateProductionCategoryKey —— 类别约束集合成员（子表）

| 列 | 类型 | 说明 |
|---|---|---|
| Id | int PK | |
| CategoryId | int FK | 所属类别（级联删） |
| ConstraintType | nvarchar(30) | Process / ProductStatus / Stage（`PieceRateConstraintTypes`，杜绝魔法字符串） |
| Key | nvarchar(50) | 成员英文 Key（工序/产类/阶段各自域值） |

继承 BaseEntity。**复合唯一索引 `(CategoryId, ConstraintType, Key)`** 防同键重复；约束 `ConstraintType + Key` 取自 `PieceRateConstraintTypes`（含 `IsKey` 判等）。**0 成员行 = 该维全选**（等价域语义：显式全列表保存端收敛为空集、不插行——见 §3.1，避免「空」与「显式全列」两种等价形态并存）。匹配/禁交集/覆盖计算一律把成员行取为内存 `HashSet(OrdinalIgnoreCase)` 空集自动转全域（`CategoryCoverageRule` 零改动复用）。

## 3. 类别定义规则

### 3.1 四键约束
- **工段**：必选单选。
- **工序 / 产类 / 作业阶段**：三者同构——可选、可多选；空 = 全选（成员子表 `PieceRateProductionCategoryKey` 0 行即全选；保存端归一：输入为空或显式全列表 → 收敛为空集不插行，禁止「显式全列表」与「空」两种等价形态并存）。

### 3.2 自动组合名（不落库）
展示名 = `工段中文｜产类中文集(空=全部产类)｜工序中文集(空=全部工序)｜阶段中文集(空=全部阶段)`。
例：`酸洗｜荒管｜全部工序｜出缸`、`矫直｜在制·成品｜全部工序｜全部阶段`。

### 3.3 禁止交集（保存时校验）
两条类别 C1、C2（同工段 SectionKey 相等）若下列覆盖**全部相交**即冲突，`BusinessException` 拒存：

```
覆盖(C) = SectionKey × Procs(C) × Prods(C) × Stages(C)
Procs(C)   = ProcessKeys 为空 ? 全域(∞) : ProcessKeys
Prods(C)   = ProductStatusKeys 为空 ? {荒管,在制,成品} : 该集
Stages(C)  = StageKeys 为空 ? {普通报工, 入缸, 出缸} : 该集   ← 普通报工=无阶段，是阶段域的合法取值
```

- 不同工段永不冲突；
- 「空=全选」类别会霸占同工段整块空间：与任何同工段、且产类/阶段覆盖与之相交的具体类别冲突。业务按**产类互斥 / 阶段互斥**建类别天然安全（`酸洗·{荒管}·出缸` 与 `酸洗·{在制,成品}·出缸` 产类不相交，永不冲突）。

### 3.4 匹配唯一性
禁止交集保证：任意一条报工（工段+工序+产类+阶段确定）在启用的类别里命中**至多一个**类别。命中不到的属「未定价」（见 §6.3）。

## 4. 维度档规则

| 维度 | 形态 | 匹配 |
|---|---|---|
| 外径 OuterDiameter / 壁厚 WallThickness / 长度 Length / 断切率 CutRate | 区间型 | 数值落在某档 Min/Max → 取该档 Ratio |
| 定尺 FixedLengthCount | 整数区间 | 个数落入 → Ratio |
| 特殊牌号 SpecialGrade | 等值型 | PlantGrade 等值命中 → Ratio |
| 特殊制造状态 SpecialState | 等值型 | 状态 Key 等值命中 → Ratio |
| 设备号 SpecialDevice | 等值型 | 报工 EquipmentName 等值命中 → Ratio |
| 冷拔类型 ColdDrawType | 备注关键词 | 报工备注 Remark **包含** MatchValue 关键词 → Ratio（2026-09-04 引入） |

- 类别下未配置的维度 = 系数 1，不参与（用户确认：不存「启用维度集合」，按实际档行自适应）；
- 补充档未设 = 默认 1（用户确认）；
- **无例外价**：任何行不允许存绝对价；Ratio 必须能由价格反解。

**冷拔类型维（ColdDrawType，2026-09-04 拍板）**：值维家族中唯一「等值相等 → 备注包含」语义的维——档行 `MatchValue` 存**自由文本关键词**（非固定枚举），报工备注 `Remark` 含该词即命中该档乘系数；未命中 = 系数 1（不返回）。同一备注命中多个关键词取【最长关键词】（更具体）定则；同长取先配行（Id 小者）。匹配助手 `PieceRateRemarkMatcher.MatchKeyword`（MES.Services/Payroll）为引擎与服务双份 SelectHitTier 的**单一命中源**，防双通道漂移。仅给冷拔类别（ColdRollDraw · 工序=ColdDraw）配档；关键词仅取生产记录 `Remark`（唯一冷拔产量源）。**无 schema 变化**：沿用 `PieceRateProductionCategoryTiers`，DimensionKey 为自由 string。

## 5. 匹配算法（试算 / 将来结算共用）

```
输入：报工记录 r { SectionName, ProcessName, ProductStatus, 阶段Stage,
                   OD,WT,LEN,CutRate,定尺数, PlantGrade, EquipmentName, Remark }
      Stage 来源：PicklingInRecord→InTank / PicklingOutRecord→OutTank / 普通报工 ProductionRecord→无阶段
      Remark：仅 ProductionRecord 源回填（冷拔类别唯一产量源）

1. 候选类别 = Category
   WHERE SectionKey == r.SectionName
     AND IsActive
     AND (ProcessKeys 为空 OR r.ProcessName ∈ ProcessKeys)
     AND (ProductStatusKeys 为空 OR r.ProductStatus ∈ ProductStatusKeys)
     AND (StageKeys 为空 OR r.Stage ∈ StageKeys)
   → 禁交集保护下命中数 ≤ 1；>1 为数据违例，防御性报错。

2. 单价 = 类别.BasePrice
        × Π(命中基础档.Ratio)      // 只扫该类别实际配置了档行的维
        × 补充档命中(牌号/状态/设备).Ratio   // 未配置或未命中 = 1
        × 冷拔类型命中(Remark 含关键词, 最长词优先).Ratio   // 未配置或未命中 = 1

3. 金额 = 单价 × 数量   // 数量按 类别.Unit 取数维度折算（复用 PieceRateUnitKeys.QuantityDimension）
```

**Cut 生产采集两维接线（2026-09-04，V1.4）**：生产采集源（`ProductionRecord`，工段=Cut）结算请求此前 LEN / 定尺数两维**均不填** → 引擎缺值跳过（系数 1），切料类别（如真库类别 37：Length×FixedLengthCount 两维档）单价系统性漏乘。现由共享采集器 `PieceRateCollector`（MES.Services/Payroll）接线，**口径 = 计划口径最小实现**：
- **Length（LEN）** = 该切割行 `FinishedCutLength`（mm）。正式切割行落实际值=计划长度；非正式切割行该字段可空 → 引擎缺值天然跳过该维（系数 1）。
- **定尺数（FixedLengthCount）** = 批次 `ItemDetails` **去重定尺长度种数**（批次级计划属性，不随切割行变；不读实际切割去重、不读关联工单/主号整单并集）。仅当批次 `LengthStatus=Fixed` 才取值；`ItemDetails` 缺/解析失败/非定尺批 → 空 → 引擎跳过该维（系数 1）。文本快照格式两形态容忍解析（`"5,14154mm,30支;…"` / `"5项,14154mm,30支;…"`），解析器 `BatchItemDetailsParser.CountDistinctLengthsMm`（MES.Core/Helpers）。同批多行经批级缓存免重复解析。
- 其余 4 源（成检/酸洗入/酸洗出/工序检验）非 Cut 不填两维，行为不变；**试算 match-price 与结算同源**（均只对 Cut 生产记录填两维）。

**结算数量口径（用户确认）**：酸洗/去油一缸的量，入缸算入缸的钱（发给装缸操作人）、出缸算出缸的钱（发给卸缸操作人）——两端各计一次是两段劳动、两位操作人，合法，非重复计费。入缸、出缸同价时建一个「阶段=全选」类别即可；异价建两个「阶段={入缸}/{出缸}」类别。

### 5.1 模拟测算（按产量记录点选计价）+ 共享记录→请求映射（2026-09-04 V1.5）

生产计件类别**列表页**新增「模拟测算」面板：从 4 类**真实产量记录**（表+字段口径见下表）里点选一条 → 服务按**现行启用类别**给出结算单价与整行计件额（与当月结算同口径、未按写名人头均分）。比手敲维度直观（成检页同款能力）。

| 源（枚举） | 表 | 阶段 Stage | 操作人列 | 批次号 | 特有口径 |
|---|---|---|---|---|---|
| ProductionRecord | 生产记录 | 无 | Operator | Include 批导航 | spec/牌号**空回退批**；**Cut 行**补 Length=FinishedCutLength、FixedLengthCount=批 ItemDetails 去重定尺种数、光亮接线 |
| PicklingIn | 去油酸洗入缸 | InTank | Operator | Include 批导航 | 只用记录 ManufacturingSpec（不回退批） |
| PicklingOut | 去油酸洗完工 | OutTank | Operator | 自冗余 BatchNo | 冗余字段自入缸冻结 |
| ProcessInspection | 过程检验 | 无 | **Inspector** | 自冗余 BatchNo + Include 批 | spec/牌号**空回退批** |

**共享映射单源 `ProductionMatchRequestMapper`**（MES.Services/Payroll，静态类 4 方法）：结算采集（`PieceRateCollector` 4 源）与模拟测算都只经它构建计价请求 `PieceRateProductionMatchRequest`，防双通道漂移——同一条真实记录在任何一处出价必一致。归一规则：工段中英 `SectionKeys.ToKey ?? 原样`、规格→OD/WT `SpecificationParser`、牌号/规格空回退批（仅 ProductionRecord/ProcessInspection）、Remark/Equipment 原样回填。

**光亮特殊制造状态接线（仅 Cut 行）**：此前 `SpecialState=Bright` 在真库仅类别 37（Cut 成品断切，PerTon 40）配了档，但结算永不喂值（配置存在不生效）。V1.5 起**结算与模拟测算同接**——`ProductionRecord` 工段=Cut 且批次 `ProductionBatch.DeliveryState ∈ {Bright, BrightUTube, BrightCoiled}`（`IsBrightDelivery` 白名单，OrdinalIgnoreCase）→ 请求 `SpecialState=PieceRateStateKeys.Bright` 乘 ×1.35。非 Cut 不喂（现仅 Cut 类别有 Bright 档，避免误伤）；「结算真库口径核验」= 光亮 = 批次交货状态（非 ManufacturingStatus 状态机）。⚠️ **口径变化影响**：真库 Cut 切行中光亮批 24 行（全 Bright）由 ×1.0 变 ×1.35，相关月度结算金额上升（此前漏发 35%）；不改结算则模拟测算与月结不同价，违背同价设计，故两端同接。

**候选浏览 + 计价端点**（权限 SalaryView，挂 `api/piece-rate-category`）：
- `GET trial-records`：源必选（非法/缺 → BusinessException「请选择产量源/无效的产量源」）+ 关键字 + 分页；默认各源日期列 desc + Id desc；**关键字只下推记录本地列**（Operator/Inspector/EquipmentName/Remark/ManufacturingSpec，PicklingOut/ProcessInspection 另含自冗余 BatchNo）——批次号/规格仅 Include+投影展示，导航列不下推（浏览纪律）。
- `GET trial-records/{source}/{id}/price`：按源查实体 → Mapper 映射 → 现行类别计价 → `MatchResult + SimulatedAmount`（整行计件额 = `PieceRateAmountHelper.AmountForUnit(单位, 单价, Weight, Quantity, length:null)`；**null = 未定价**：无启用类别或值未命中任何档）。

**模拟金额折算口径**：PerTon=Weight kg÷1000×单价；PerPiece=支×单价；PerKm 生产记录无长度维（仅切行有 mm 定尺，非千米）→ 恒 null，前端灰字提示。记录缺重量/支数 → null 同灰字。前端展示：命中类别（Id+自动组合名）、基准价 G29 × 总系数 G29 = 结算单价、命中档 chips（维度中文：RangeText × Ratio G29）。

## 6. 结算与流水（后续阶段，设计预留）

- 工资流水在结算生成时**快照**命中类别、基准、系数、单价、日期（历史不受后续调价影响）；
- 调价即改类别基准/档行，旧流水不动；调价支持 IsActive 停用旧类别 + 新建新类别（版本追溯按需再议，当前不做日期版本）。

### 6.1 未定价校验清单（防漏单）
结算前强制输出：在结算窗口内有报工、但按(工段,工序,产类,阶段)命中不到任何启用类别的行清单，显式标注「未定价」，人工处理后才允许出工资。酸洗/去油若某阶段记录属「故意不结算」（本阶段未建类别）需在此清单中有明确说明/过滤，不得静默。

### 6.3 未匹配提醒口径（2026-09-04，提醒拆分）
§3.4 命中不到启用类别的行在共享采集器 `PieceRateCollector`（工资结算链路 5 源统一）的 `CollectResult.UnpricedCount` 中统计，供三结算服务月结页做「有量未定价」缺口提醒。**口径拆分（用户拍板）**：仅**「已记录到量（任一计量>0：Weight/Quantity）却命中不到启用类别」**计为未定价缺口进提醒（按 0 元计）；**数量问题一律静默**不发工资、不进提醒——
- 无产出量（漏记 / 虚拟补录数量空，Weight 与 Quantity 均 ≤0 或空）；
- 命中类别但数量缺失/折算不出金额（`AmountForUnit` 返回 null/≤0）→ 同属数量问题静默。

三种结算服务当月警告文案随此收敛（原「未定价或缺少数量」合并计数 → 现仅「有量没价」计 1），具体见《工资结算上下文详细设计.md》§9.4。

### 7.2 例外价（OnePrice）废除的代价

## 附：数据维护闭环——批量导出 / 模板 / 预览 / 导入（2026-09-02 V1.2）

**背景**：类别 + 维档是父子整组结构，DataTool 通用机制（扁平单表 + 自然唯一键）无法承载，故在计件类别页提供专用导入/导出，实现「工资结算数据维护闭环」。冲突策略 = **覆盖更新**。模板/导出列值全用中文域值（中英容忍），工序/工段显示名反向映射自配置表（`ISectionNameDisplayService`/`IProcessDefinitionService` 显示名→Key），保证「导出→改→再导」闭环。任一数据行无效 → 整组/整体拒绝入库（组级原子性，预览与导入同口径解析）。

- **导出全量**（`ExportAsync`）：当前全量标准 → xlsx 双 sheet「类别」+「维档」（备份 / 改后再导）。
- **模板**（`GenerateTemplateAsync(kind)`）：kind=category|tier，单 sheet + 1 示例行。示例工段 = 「当前无类别」的启用工段 + 示例行启用=否——原样导入模板也不会误覆盖真实类别/误计价。
- **预览**（`PreviewImportAsync`）：解析 + 校验 + 统计，复用 `ImportPreviewResult`/`ImportRowResult`（MES.Core/Models/ImportModels.cs）：新增 AddCount / 覆盖 OverwriteCount / 错误 ErrorCount + 明细。
- **导入**（`ImportAsync`）：事务内覆盖更新；解析出现任意错误 → 整体拒绝。

**模板语义（职责分离、避免误删档）**：
- **类别定义模板**（category）：列 `工段/工序(可"、"分隔;空=全)/产类(同上)/阶段(同上)/基准价/结算单位/启用/备注`。定位 = 工段 + 三约束归一组（空=该维全选）。命中类别 → **整组替换三约束成员行 + 更新主属性（基准/单位/启停/备注），绝不清既有档行**；未命中 → 新建（无档行）。同定位类别文件内重复 → 报错。
- **维档系数模板**（tier）：列 `工段/工序/产类/阶段/维度/档值/系数/启用`。定位未命中 → 整行报错「请先导入类别定义」；命中 → **该类别 Tiers 整组替换为文件行**。组内经档内重叠/等值去重同口径校验（`ValidateTierGroup`），违例整组拒存不动原档。

**解析口径**：三约束 / 工段 / 单位 / 维度均经常量 `ToKey` + 配置显示名反向映射 + 域白名单校验（同编辑页 SaveAsync 规约）；区间维经 `PieceRateRangeParser`（定尺维整数带 `ToIntBound`）、特殊制造状态等值维归一英文 Key（`PieceRateStateKeys`）；基准 >0、系数 >0。**解析期错误即置行无效**（`AddParseError` 记错并 `IsValid=false`），空行跳过、空表/不可读 Fatal。

**实现**：接口 `IPieceRateCategoryImportService` + `MES.Services/Payroll/PieceRateCategoryImportService.cs`；4 端点挂 `api/piece-rate-category`（权限 template/export/preview = SalaryView、import = SalaryEdit）；Controller 构造新增注入第二服务；前端类别列表页工具栏「导出全量 / 导入类别 / 导入维档」+ `PieceRateCategoryImportDialog` 弹窗（下载模板 → 上传 .xlsx → 解析预览 chips+错误表 → 执行导入）；`MES.Blazor/Services/Payroll/PieceRateCategoryImportService.cs` 前端服务，DI 双向注册。测试 `PieceRateCategoryImportServiceTests`（11 例：新建/覆盖不动档/重复定位/禁交集冲突/维档整组替换/定位缺失/区间重叠整组拒存/等值重复/字段非法/导出双 sheet/模板单 sheet）。
