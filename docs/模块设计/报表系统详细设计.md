# 报表系统（Report）详细设计

> 版本：v1.8
> 最后更新：2026-08-23

## 1. 概述

报表系统是**纯读取聚合层**，**不创建独立表**，从多个现有上下文查询数据并聚合为透视报表，提供在线查看和 PDF 打印功能。

### 核心原则

| 原则 | 说明 |
|------|------|
| **不建新表** | 报表系统没有自己的 Entity/DbSet |
| **纯只读** | 无新增/编辑/删除操作，仅查询聚合 |
| **后端聚合** | Service 层直接跨表查询并计算透视表，前端仅负责展示 |
| **列显隐持久化** | 通过 ColumnPrefsService 保存用户列偏好 |
| **打印为 PDF** | 后端 QuestPDF 生成 PDF，由 JS 触发下载 |

### 适用范围

适用于**跨上下文的汇总统计场景**。如果一个报表只需要读一个实体的数据，应直接在对应上下文的列表页实现，不需要进报表系统。

## 3. 产量报表详细设计

### 3.1 数据源

产量报表聚合 **5 个上下文**的数据，按日期+工段维度透视：

| 数据项 | 来源表 | 上下文 | 分组字段 | 重量字段 |
|-------|-------|-------|---------|---------|
| 投料荒管 | ProductionBatch (SourceMaterialType="RoughTube"，「荒管」为显示名) | Batch | CreatedTime | InputWeight |
| 各工段产量 | ProductionRecord | Batch | ExecDate + SectionName | Weight |
| 委外回收 | OutsourceRecovery → SectionOutsource JOIN | Batch | RecoveryDate + SectionOutsource.SectionName | RecoveryWeight |
| 过程检验 | ProcessInspection | Quality | InspectionDate | Weight |
| 成品入库 | InventoryBatch (MaterialType="OrderFinished"，「订单成品」为显示名) | Warehouse | InboundDate | InitialWeight |

### 3.2 聚合逻辑

```
输入: fromDate, toDate（最大跨度 366 天）
输出: 日期 × 工段的二维透视表

列顺序:
  [0] 日期（固定）
  [1] 投料荒管（固定特殊列）
  [2..n] 标准工段列（按 SectionDefs.All 顺序）
  [n+1] 过程检验（固定特殊列）
  [n+2] 成品入库（固定特殊列）
  [n+3..] 额外工段（数据库中出现的非标准工段，按字母序）

数据行:
  每个有数据的日期一行
  "合计"行通过 FooterContent 渲染

重量单位: kg（展示时取整为 int）
```

### 3.3 架构

```
前端 (ProductionOutput.razor)                   后端 (ReportController)
       │                                              │
       ├─ GET /api/report/daily-output                │
       │    ?fromDate=...&toDate=...                  │
       │ ← DailyProductionReportResponse              │
       │    { SectionColumns, Rows[] }                │
       │                                              │
       └─ POST /api/report/daily-output/print-file    │
            { fromDate, toDate, columns[] }           │
          → PDF byte[] (QuestPDF)                     │
```

### 3.4 文件清单

| 层 | 文件 | 说明 |
|----|------|------|
| API Controller | `MES.Api/Controllers/Report/ReportController.cs` | 2 个端点（daily-output, daily-output/print-file） |
| Service | `MES.Services/Report/ReportService.cs` | 跨表聚合查询逻辑 |
| DTO | `MES.Core/DTOs/Report/DailyProductionReportDto.cs` | DailyProductionReportResponse / DailyProductionReportRow / DailyProductionReportPrintRequest |
| 打印 | `MES.Services/Printing/ReportPrintHelper.cs` | QuestPDF Mode B 打印（前端传列定义） |
| Blazor Page | `MES.Blazor/Pages/Reports/ProductionOutput.razor` | 产量报表页面 |
| Code-behind | `MES.Blazor/Pages/Reports/ProductionOutput.razor.cs` | 查询、列显隐、打印逻辑 |
| Blazor Service | `MES.Blazor/Services/Report/ReportService.cs` | 前端 HTTP 调用封装 |

### 3.5 关键实现细节

- **前端列模式**：产量报表使用全量加载模式（非 ServerData 分页），一次性获取全量数据后由前端负责列显隐（ColumnDisplaySelect）+ 列顺序持久化（ColumnPrefsService）
- **固定列宽模式**：`table-layout: fixed` + 每列显式 width/min-width，避免动态列数导致表头/表体错位
- **CSS sticky 表头**：手动实现粘性表头（替代 MudTable FixedHeader，后者会拆分表格导致表脚错位）
- **打印模式**：Mode B⓪（前端准备数据），前端将当前可见列定义传给后端，后端按列顺序生成 PDF
- **权限**：`BatchStaff/BatchDirector/Admin`（与批次上下文复用，后续可细化独立报表角色）

### 3.6 特殊设计说明

- **无分页**：报表按日期范围聚合最多 366 行数据，全量一次性加载
- **无 ServerData**：数据量小（行数=天数 ≤ 366，列数=工段数 ≤ 30），完全由前端管理展示
- **无 ExcelFilter**：报表的筛选灵活度不如列表页，暂不实现列头筛选；日期范围使用搜索栏控制
- **"本月"/"上月"快捷按钮**：提供便捷的日期范围快速输入

## 4. 物料进出存报表详细设计

### 4.1 数据源

物料进出存报表聚合 **仓库上下文** 的 2 张表（无独立报表表，符合报表系统「纯读取聚合层」原则）：

| 数据项 | 来源表 | 上下文 | 关键字段 |
|-------|-------|-------|---------|
| 入库流 | InventoryBatch | Warehouse | WarehouseId / InboundDate / MaterialType / **InboundSource** / InitialWeight |
| 出库流 | OutboundRecord → JOIN InventoryBatch | Warehouse | OutboundDate / OutboundWeight / **OutboundType** / 批次库房·物料键 |

> 无 Material 主数据：材料 = 批次上的 `MaterialType`。无期初/期末快照：期初/结存由「入−出」累计递推派生。

### 4.2 聚合逻辑

```
输入: 无（固定本年 1月1日 ~ 12月31日 + 期初截至上年末）
输出: Rows（全口径）=库房×物料类型；InboundSourceRows=库房×物料类型×入库来源；OutboundTypeRows=库房×物料类型×出库类型
      列=期初 + 12月×入/出/结 + 实时数据/实时结存；同一数据集支撑 4 报表切换（入库/出库/库存/物料进出存，仅展示列不同）

全口径行粒度: 库房 × 物料类型（库房合并单元格）
期初: Σ(上年末前入) − Σ(上年末前出)
每月: 入/出为全口径流量单值（不按来源/类型拆分）
结存: 逐月递推 Closing[m] = Closing[m-1] + In[m] − Out[m]（真实全口径）
来源粒度行(InboundSourceRows): 仅累计本年入，行=库房×物料类型×来源，全 0 来源行隐藏，不展示期初/结存
类型粒度行(OutboundTypeRows): 仅累计本年出，行=库房×物料类型×类型，全 0 类型行隐藏，不展示期初/结存
隐藏: 全口径 整行 期初/入/出 全 0 → 隐藏
排序: 库房固定顺序（原料库→成品库→在制品库→次品库）
      + 组内物料类型固定顺序（圆棒→荒管→临界成品→订单成品→订成-非交付态→备料成品→余库料→半成品→在制品→次品圆棒→次品荒管→次品成品→次品半成品→次品在制→报废品）
      + 来源粒度 来源固定顺序（外购→委外→生产入库→检验入库→其它）/ 类型粒度 类型固定顺序（生产领用→销售出库→退货出库→委外出库→其它出库）
合计: 无（用户决策，去合计行）
```

### 4.3 架构

```
前端 (MonthlyStock.razor)                         后端 (InventoryService.GetMonthlyStockSummaryAsync)
       │                                               │
       └─ GET /api/inventory/monthly-stock-summary ──► 加载全部 InventoryBatch(含来源) + OutboundRecord JOIN 批次(含类型)
         ← MonthlyStockSummaryResultDto               字典按 (库房Id|物料类型) 聚合 → 期初/递推/固定顺序排序
           （Rows / InboundSourceRows / OutboundTypeRows）      + 按 (库房|物料|来源)/(库房|物料|类型) 聚合粒度行
```

- **4 报表切换前端就地切换**（无网络请求）：入库报表=`InboundSourceRows`（每月「入」+「来源汇总(t)」+「物料汇总(t)」）；出库报表=`OutboundTypeRows`（每月「出」+「出库类型汇总(t)」+「物料汇总(t)」）；库存报表=`Rows`（「结」+期初+实时结存）；物料进出存报表=`Rows`（「入/出,[结]」+期初+实时数据）；**期初列仅「库存/物料进出存」显示**
- **双层合并单元格**（入库/出库报表）：库房合并（rowspan=库房组行数）+ 物料类型合并（rowspan=同库房内该物料行数）+「物料汇总(t)」合并列（=该物料类型截至当前月合计，入报表 ΣTotalIn / 出报表 ΣTotalOut）；后端排序保证同组相邻，前端 `ComputeRowspans()` 计算行对齐 rowspan
- **未来月留空**（2026-08-23）：当前月份之后（`m > _currentMonthIndex`）月份单元格留空不显示数据
- **实时列**（2026-08-23）：「实时结存」（库存）=截至当前月的真实库存余额；「实时数据」（物料进出存）=截至当前月的 入/出/结 合计；「来源汇总(t)/出库类型汇总(t)」同改为截至当前月合计
- **表格线**（2026-08-23）：浅色 1px `#d0d0d0` 独立边框模型（border-collapse:separate，sticky 表头/列边框不丢失）；月份表头/单元格 min-width:90px 列宽一致
- **打印**：前端 getTableHtml(`#monthly-stock-table-wrap`) + printRawHtml（原生 `<table>`，标题按当前报表）——**传容器选择器**（getTableHtml 契约=容器内第一张 table，传表自身 id 会取不到返回空）；**打印前追加 print-fit `<style>`（table-layout:fixed;width:100%;font-size:12px;white-space:normal）+ 传 `"landscape"` 横向 A4**，表格总宽度恒等于页宽、不超过单页界限
- **单位**：kg/1000 → t，F1，0 值留空；物料进出存报表每格「入/出,[结]」（如 80/15,[65]=当月入 80t、出 15t、月末结存 65t，0 的部分省略）

| Service | `MES.Services/Warehouse/InventoryService.cs` | `GetMonthlyStockSummaryAsync` 聚合 |

### 4.5 关键实现细节

- **权限**：`WarehouseStaff/WarehouseDirector/Admin`（与仓库上下文一致）
- **粒度行无期初/结存**：来源/类型粒度行仅统计本年入/出流量，不展示期初/结存（结存为全口径概念，只有 库存/物料进出存 报表展示）
- **数据完整性注意**：入库流 = InventoryBatch 行本身；物理删除无出库记录的批次会使对应入库流从报表消失（接受为设计决策）
- **行排序静态字典**：后端 `WarehouseDisplayOrder`（库房名→序）+ `MaterialTypeDisplayOrder`（MaterialType 枚举名→序，未知经 `EnumHelper.TryParse<MaterialType>` 兜底，仍未知 → int.MaxValue 尾部），再按名 OrdinalIgnoreCase 次级排序保证稳定
