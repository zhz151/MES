# 报表系统（Report）详细设计

> 版本：v1.2
> 最后更新：2026-08-15

## 1. 概述

报表系统是**纯读取聚合层**，**不创建独立表**，从多个现有上下文查询数据并聚合为透视报表，提供在线查看和 PDF 打印功能。

### 核心原则

| 原则 | 说明 |
|------|------|
| **不建新表** | 报表系统没有自己的 Entity/DbSet |
| **纯只读** | 无新增/编辑/删除操作，仅查询聚合 |
| **后端聚合** | Service 层直接跨表查询并计算透视表，前端仅负责展示 |
| **列显隐持久化** | 通过 ColumnPrefsService 保存用户列偏好 |
| **打印为 PDF** | 后端 QuestPDF 生成 PDF，由 JS 触发下载 |

### 适用范围

适用于**跨上下文的汇总统计场景**。如果一个报表只需要读一个实体的数据，应直接在对应上下文的列表页实现，不需要进报表系统。

## 3. 产量报表详细设计

### 3.1 数据源

产量报表聚合 **5 个上下文**的数据，按日期+工段维度透视：

| 数据项 | 来源表 | 上下文 | 分组字段 | 重量字段 |
|-------|-------|-------|---------|---------|
| 投料荒管 | ProductionBatch (SourceMaterialType="RoughTube"，「荒管」为显示名) | Batch | CreatedTime | InputWeight |
| 各工段产量 | ProductionRecord | Batch | ExecDate + SectionName | Weight |
| 委外回收 | OutsourceRecovery → SectionOutsource JOIN | Batch | RecoveryDate + SectionOutsource.SectionName | RecoveryWeight |
| 过程检验 | ProcessInspection | Quality | InspectionDate | Weight |
| 成品入库 | InventoryBatch (MaterialType="OrderFinished"，「订单成品」为显示名) | Warehouse | InboundDate | InitialWeight |

### 3.2 聚合逻辑

```
输入: fromDate, toDate（最大跨度 366 天）
输出: 日期 × 工段的二维透视表

列顺序:
  [0] 日期（固定）
  [1] 投料荒管（固定特殊列）
  [2..n] 标准工段列（按 SectionDefs.All 顺序）
  [n+1] 过程检验（固定特殊列）
  [n+2] 成品入库（固定特殊列）
  [n+3..] 额外工段（数据库中出现的非标准工段，按字母序）

数据行:
  每个有数据的日期一行
  "合计"行通过 FooterContent 渲染

重量单位: kg（展示时取整为 int）
```

### 3.3 架构

```
前端 (ProductionOutput.razor)                   后端 (ReportController)
       │                                              │
       ├─ GET /api/report/daily-output                │
       │    ?fromDate=...&toDate=...                  │
       │ ← DailyProductionReportResponse              │
       │    { SectionColumns, Rows[] }                │
       │                                              │
       └─ POST /api/report/daily-output/print-file    │
            { fromDate, toDate, columns[] }           │
          → PDF byte[] (QuestPDF)                     │
```

### 3.4 文件清单

| 层 | 文件 | 说明 |
|----|------|------|
| API Controller | `MES.Api/Controllers/Report/ReportController.cs` | 2 个端点（daily-output, daily-output/print-file） |
| Service | `MES.Services/Report/ReportService.cs` | 跨表聚合查询逻辑 |
| DTO | `MES.Core/DTOs/Report/DailyProductionReportDto.cs` | DailyProductionReportResponse / DailyProductionReportRow / DailyProductionReportPrintRequest |
| 打印 | `MES.Services/Printing/ReportPrintHelper.cs` | QuestPDF Mode B 打印（前端传列定义） |
| Blazor Page | `MES.Blazor/Pages/Reports/ProductionOutput.razor` | 产量报表页面 |
| Code-behind | `MES.Blazor/Pages/Reports/ProductionOutput.razor.cs` | 查询、列显隐、打印逻辑 |
| Blazor Service | `MES.Blazor/Services/Report/ReportService.cs` | 前端 HTTP 调用封装 |

### 3.5 关键实现细节

- **前端列模式**：产量报表使用全量加载模式（非 ServerData 分页），一次性获取全量数据后由前端负责列显隐（ColumnDisplaySelect）+ 列顺序持久化（ColumnPrefsService）
- **固定列宽模式**：`table-layout: fixed` + 每列显式 width/min-width，避免动态列数导致表头/表体错位
- **CSS sticky 表头**：手动实现粘性表头（替代 MudTable FixedHeader，后者会拆分表格导致表脚错位）
- **打印模式**：Mode B⓪（前端准备数据），前端将当前可见列定义传给后端，后端按列顺序生成 PDF
- **权限**：`BatchStaff/BatchDirector/Admin`（与批次上下文复用，后续可细化独立报表角色）

### 3.6 特殊设计说明

- **无分页**：报表按日期范围聚合最多 366 行数据，全量一次性加载
- **无 ServerData**：数据量小（行数=天数 ≤ 366，列数=工段数 ≤ 30），完全由前端管理展示
- **无 ExcelFilter**：报表的筛选灵活度不如列表页，暂不实现列头筛选；日期范围使用搜索栏控制
- **"本月"/"上月"快捷按钮**：提供便捷的日期范围快速输入

## 4. 扩展规划

### 第一期（已实现）

- [x] 产量报表 — 日产量按工段透视表 + PDF 打印

### 第二期（建议）

| 报表 | 数据来源 | 说明 |
|------|---------|------|
| 质量合格率报表 | ProcessInspection / FinalInspection / Ncr | 各工段检验合格率、不良品分类统计 |
| 设备维修统计报表 | RepairOrder / MaintenanceOrder | 设备故障率、维修响应时间、保养完成率 |

### 架构扩展点

- **新增报表流程**：① Service 层实现聚合查询 DTO → ② Controller 添加端点 → ③ Blazor Service 添加调用 → ④ Blazor Page 实现展示 → ⑤ 导航菜单追加入口
- **现有报表新增数据列**：只需在 Service 聚合查询中追加数据源，DTO 和前端自动适配（`SectionColumns` + `Values` 字典结构）
- **如需引入图表**：可在前端集成 Chart.js / ECharts（目前 Blazor WASM 无成熟图表库原生绑定）
