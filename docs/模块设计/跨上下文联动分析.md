# 全系统跨上下文联动分析

> 分析日期：2026-07-29
> 覆盖范围：8 个上下文，共发现并修复 12 处遗漏

## 联动模式

系统中有 3 种跨上下文数据联动模式：

| 模式 | 说明 | 适用场景 | 示例 |
|------|------|---------|------|
| **全量聚合重算** | SaveChanges 后重新 SUM/MAX 源表，Upsert 目标表 | **必须一致** — 不重算就是错的数值聚合 | WES、QPT、SourceOrder 同步、BatchTracking |
| **增量计算** | SaveChanges 后直接 +-= 目标字段 | **必须一致** — 简单的数值加减 | 仓库出库 RemainingQuantity -= OutboundQuantity |
| **通知模式** | SaveChanges 后创建或消除 Notification 记录 | **应该知道** — 可能有影响，需要人判断 | OrderDeleted、OrderChanged（工单页 MudAlert 展示） |
| **精准消除** | SaveChanges 后按 WorkOrderNo 消除指定通知记录 | **必须精准** — 按条件消除，避免误伤其他关联单据的通知 | G8/G9 Type A：批次创建时只消除当前分工单的在产计划通知，保留其他分工单的通知 |
| **主动查询** | 前端页面加载时主动调用校验接口 | **可以核查** — 结果是二元的，实时扫描一步到位 | Batches.razor 的 VerifyWorkOrderNosAsync |

### 三层分工原则

跨上下文数据联动按照"影响的确定性"分为三层：

```
必须一致  →  全量聚合重算 / 增量计算（自动执行，无需人工）
应该知道  →  通知模式（记录事件，用户查看后消除，消除 ≠ 已修复）
可以核查  →  主动查询（页面加载时实时扫描，兜底发现异常）
```

以工单号为核心的具体映射：

| 场景 | 模式 | 原因 | 状态 |
|------|------|------|------|
| 工单**被删除**，批次/入库引用已不存在的工单号 | **主动查询** | 存在/不存在是二元的，无需事件记录，实时扫描即可 | ✅ 已实现（Batches + InboundHistory） |
| 工单**内容变更**（ManufacturingItem/PlantGrade 等变，工单号不变） | **通知模式** | 需要人判断是否要同步到批次，不是所有变更都需要修正 | ✅ 已实现（WorkOrderService → Batches 页 MudAlert） |
| WES/QPT/BatchTrk 聚合值过期 | **全量聚合重算** | 数值计算必须实时准确，不重算就是错的 | ✅ 已实现（触发矩阵覆盖 14 类入口） |

## 自包含上下文（无需跨上下文联动）

| 上下文 | 原因 |
|--------|------|
| **排程** | 计划数据，仅做只读消费，不参与其他上下文的聚合计算 |
| **设备** | 设备状态是内部聚合（EquipmentStatusCalculator），不通知外部 |
| **配置** | 纯查询，无增删改入口（前端手动维护） |
| **NCR/理化检验/质保书** | 纯数据录入，数据不被其他上下文的聚合引用 |

## 后续维护原则

1. 新增写入方法时，遵循"提交-通知"模式：先 `SaveChangesAsync`，再调用外部刷新
2. 异常用 try-catch 包裹，仅记 Warning 日志，不阻断主流程
3. 批量操作注意去重（`Distinct()`）避免重复刷新
4. 外部写入 Batch.Status 时必须同步刷新 WES
5. 仓库入库/出库涉及 RemainingQuantity 变化的，需同步 SourceOrder + QPT + WES
6. 仓库入库操作同时触发 WES + QPT + BatchTrk 三路刷新（入库完成推进和状态回退均需 BatchTrk 重算）
7. 成检到料 CRUD 需触发 WES + QPT + BatchTrk 三路刷新（不仅 QPT 和 WES）
8. 批次库存关联（ProductionBatchInventory）CRUD 需触发 WES + BatchTrk 两路刷新（合并投料场景）
9. 在产计划通知消除按场景区分：Type A（新建 SplitFromNumber 批次）使用 **精准消除**（按 WorkOrderNo + ProductionBatchId），Type B（工单号变更）使用 **批量消除**（仅按 ProductionBatchId）
10. 新增写入方法时，若消除通知，需确认是否有多个关联方共享同一源记录，防止误消除
